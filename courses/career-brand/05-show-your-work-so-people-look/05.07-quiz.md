```quiz
type: mcq
question: "In this made-up case, Rawda is a backend developer who built an email digest tool. She is rewriting its README so that a stranger can try the tool in about a minute. Which opening should she use?"
options:
  - "One sentence on what the tool does, a screenshot with a demo link, then a one-line command to start it"
  - "A list of prerequisites and every environment variable, then the install steps, then what the tool does"
  - "Why she built it and how the idea changed over three months, then the list of features it has so far"
  - "A table of contents, the licence and the rules for contributors, then a short description of the tool"
correct: 0
explanations:
  - "Right. A stranger learns what it is, sees it, and can start it in one line, which is the order a reader needs."
  - "Prerequisites and variables first is the tutorial habit. The reader pays for several setup steps before learning what the tool is."
  - "The story of the project matters to her, but a stranger needs the result first. History can sit lower down, if at all."
  - "A table of contents and a licence are fine lower in the file. Put first, they tell the reader nothing about what the tool does."
```

```quiz
type: mcq
question: "In this made-up case, Shereen is a freelance developer who built an invoicing demo. It has seeded fake data, a nightly reset and a visible 'this is a demo' line. The demo account can send bulk text messages through a live paid key, and nothing caps the spending. Which missing control matters most?"
options:
  - "A static page with screenshots of the demo that opens when the demo is asleep for a reader"
  - "A 'last updated' date at the top of the README so that readers know how recent the demo is"
  - "A spending and rate limit on the paid text message service that the demo account is able to reach"
  - "A Sign in with Google button added as a second way into the demo for people who prefer it"
correct: 2
explanations:
  - "A fallback page helps a reader whose demo is asleep. That is access, and it does nothing to stop a stranger from spending her money."
  - "A date is a courtesy to the reader. It does not change what a stranger can do with the paid key."
  - "Right. Any stranger can press send, so a cap on spending and on how often the service can be called stops the harm that is left."
  - "A second way in is an access feature. It adds nothing to the safety of the paid service behind the account."
```

```quiz
type: mcq
question: "In this made-up case, Rida is a frontend developer who adds Google sign-in to a demo. She wants to avoid test-user lists and Google's verification. As this module taught (checked 2026-10), which request should she make?"
options:
  - "Also read the user's Drive files, so that visitors can import their own documents to the demo"
  - "List the first 100 reviewers as test users, and add new reviewers again each week as it runs"
  - "Ask for calendar access as well, and leave the app unverified so no review is needed first"
  - "Ask Google only for the name, email address and profile picture of each person, and no more"
correct: 3
explanations:
  - "Reading Drive files is more than name, email and profile. It needs Google's verification, and an unverified app that needs it is capped at 100 new users."
  - "A test list holds up to 100 users, and their permission expires after 7 days. She would have to keep adding reviewers."
  - "Calendar access is more than the basic three items. An unverified app that needs it is capped at 100 new users."
  - "Right. An app that asks only for name, email and profile needs no test list and shows no warning, and it has no 7-day expiry."
```

```quiz
type: mcq
question: "In this made-up case, Talal is a full-stack developer choosing the project link for his resume. His demo runs on free plans. As this module taught (checked 2026-10), which link is most likely to still work in six months?"
options:
  - "The live demo, hosted on a free plan that puts the app to sleep when nobody has visited for a while"
  - "A static case study page with screenshots and a short recording, with the live demo added as a bonus link"
  - "The live demo, running on a free database that the host deletes 30 days after it was created"
  - "The live demo, behind a sign-up that sends a confirmation message to the reader's email address"
correct: 1
explanations:
  - "A free plan that sleeps makes the reader wait before anything appears, and the plan may change by the time anyone clicks."
  - "Right. A static page has no database to expire and no app to sleep. The live demo is a bonus if it still runs."
  - "A free database can expire after 30 days on some hosts. The demo would be empty or gone long before six months."
  - "A sign-up is a door to leave by. A reader who cannot confirm an email never reaches the work, even on the day it is online."
```

```quiz
type: mcq
question: "In this made-up case, Bana is a student who asks an AI tool how reviewers can run her project. The tool says she should commit her .env file, which holds the keys, so reviewers can run it. What is wrong with this advice?"
options:
  - "A real key in a repository can be stolen, so replace a pushed key and share an example env file"
  - "Nothing is wrong, because reviewers need the same real keys that she uses before they can run the project"
  - "Nothing serious is wrong, because she can delete the file in her next commit and the history is hidden"
  - "Only that the file adds clutter to the repository, so she should move it into a folder with a clearer name"
correct: 0
explanations:
  - "Right. A real key in a repository can be stolen. A pushed key must be revoked and replaced, and an example env file plus a safe demo account lets reviewers try the project."
  - "Reviewers do not need her real keys. A demo account and an example file with placeholder values let them try it, and the real keys stay private."
  - "Deleting the file later does not remove it from the history. Anyone can still read the old commit, so the key must be revoked and replaced."
  - "Clutter is not the problem. The problem is a secret that anyone who sees the repository could copy and use."
```
