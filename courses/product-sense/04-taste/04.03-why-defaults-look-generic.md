Rand and Omar each built a booking page this week, Rand for library group rooms and Omar for lab printers, with the same CSS framework and no changes. Side by side, the two pages look like one product.

## Same framework, same start, same look

<InteractiveCanvas slug="product-m4-same-framework" />

Switch between the two pages. Only the nouns change. A framework gives you a type scale, a spacing step and a set of colours, so that you can start fast. Each <GlossaryTerm term="default" definition="What a tool or framework uses when you choose nothing." /> is made to work for everyone. Rand and Omar kept all of them. The framework did nothing wrong. Unchanged defaults look like everyone else's.

<GoDeeper title="Go deeper: what the defaults are">

At the time of writing (checked 2026-10-25), Tailwind CSS describes its default theme as a starting point. The theme includes a colour palette of 26 colour families plus black and white, a type scale, shadows and fonts. The default spacing unit is 0.25rem, which is 4 pixels at a 16 pixel root size. The default body size, called `text-base`, is 1rem with a line height of 1.5. Its documents show how to extend, override or remove the theme.

Bootstrap's Reboot sets a system font stack, a body size of 1rem, a white background and box sizing that includes borders. Bootstrap documents how to customise with Sass variables, CSS variables and colour modes. <GlossaryTerm term="shadcn/ui" definition="A set of ready-made interface parts that you copy into your own project." /> works the same way: you own the code, and its default base colour is a neutral one. Both frameworks and the kit expect you to change things.

So the sources show what the defaults are, and that the makers expect you to change them. The claim that unchanged defaults look alike is this course's own observation, not a measured finding. There is older evidence for the same trend. A 2021 study, as a later paper describes it, found that web page layouts grew more alike after 2007, and it linked this to shared frameworks such as Bootstrap. That is research, described second-hand. It shows that sameness is older than AI tools.

Do not blame the framework. A tool that works for everyone cannot also be shaped to your product. That part is your job.

</GoDeeper>

## Three choices move a page off its defaults

<InteractiveCanvas slug="product-m4-default-or-choice" />

Switch through the four versions. Each one keeps the changes before it. In Type, the title is larger and the only serif line, and the sizes differ clearly. In Colour, the accent marks the one action, and green plus a word marks a free room. In Content, real hours replace "Room 1" and "Welcome". Each change has a job, and a reason you can say.

<GoDeeper title="Go deeper: why these three">

Type, colour and content are the three places where a page tells people what it is for. Type decides what is read first and how easily. Colour can mark the one action and the state of a room. Content decides whether a page says anything about this product at all.

Look at what each change gave up. In Type, Rand now uses two faces on one page, so she must check that the serif title reads well on a phone. In Colour, the category pills lost their accent and are less noticeable. In Content, the generic "Quiet, Group, Online" pills left the page, so she must find another way to filter if students need one.

A choice always costs something. Naming what was given up is part of the reason. The critique log in chapter 4.6 and the capstone both ask for it.

For Arabic text, no source in this course's research gives sizes, line lengths or line heights, and the numbers you may have seen are for Latin text. Check your type with a native reader on a real phone. That is a course rule, not a finding.

</GoDeeper>

## A default you can explain is a choice

<MermaidDiagram title="Default or choice" chart={`flowchart TD
  W{"A default on my page. Can I say why it fits this job?"} -->|"Yes"| K["Keep it. It is now a choice"]
  W -->|"No"| T{"Does it pass the Good checks?"}
  T -->|"Yes"| K
  T -->|"No"| C["Change it"]
`} />

A default is a choice you did not make. If you can say why it fits the job, you did make it, so keep it. If you cannot, check it against the Good list, then keep it or change it. A default can break a Good check: a reset that removes the focus outline and adds none leaves keyboard users unable to see where they are.

<GoDeeper title="Go deeper: defaults to keep and defaults to check">

Some defaults are good starts. A body size of 16 pixels with a line height of about 1.5 is what Tailwind uses by default. Material 3 recommends the same line height for body text (design-system guidance). Readers can still scale text to 200 percent (a standard, WCAG 1.4.4). Keep it, and say why.

Some defaults need work. Bootstrap's Reboot gives links no special focus style. If a project removes the browser's outline and adds none, a keyboard user cannot see where they are, which fails a Good check (WCAG 2.4.7). The GOV.UK Design System says default placeholder styles often fail the contrast rule (checked 2026-10-25), and that is one reason it tells makers not to use placeholders as labels.

Some defaults hide your product. These are the palette, the font and the generic words such as "Welcome to". These are the places where a choice shows most.

Do not change everything. A page where every default is replaced has many changes that nobody can explain, and each one can break a check. Anthropic, which makes Claude, publishes a design skill that calls the looks its tools produce by default "defaults rather than choices" and says the brief always wins. The same idea applies to people. Module 5 shows what it looks like when nobody chose.

</GoDeeper>

## A choice still has to pass the checks

<MermaidDiagram title="Change one thing on purpose" chart={`flowchart TD
  P["Pick one part and write the reason"] --> C["Change it"]
  C --> K{"Does it pass the Good checks?"}
  K -->|"No"| F["Fix the shade or size, not the idea"]
  F --> K
  K -->|"Yes"| L["Look again at the job"]
`} />

A new colour can fail contrast. A new font can be harder to read on a phone. So change one part, write the reason first, and run the Good checks afterwards. If a check fails, fix the shade or size and check again. Then ask: does the page help the person? Write the choice in one line: I changed this, for this job, and I checked it.

<GoDeeper title="Go deeper: one change, and one line for the log">

Rand picks colour. Her reason: booking is the one action on the page, and she wants people to notice it first. She makes the Book button for the free room the only accent, and she marks rooms with the words Free and Taken, with green only as an extra. She does not rely on colour alone to say a room is free (a standard, WCAG 1.4.1, taught in 2.5).

Then she runs the checks. The button text on the accent still needs a contrast ratio of at least 4.5 to 1. The edge of the button, if she keeps one, needs 3 to 1 against the page. The focus ring still shows when she presses Tab. If one fails, she changes the shade, not the idea.

Last, she looks at the job. Can a student find a free room tonight? In the first version, "Room 1" and "Room 2" said nothing about hours. In the last, "Free 4 to 6 pm" does. The colour helped, and the content helped more. That is worth writing down.

Her line reads: "I made the Book button the only accent colour because booking is the one action, and I checked its text at more than 4.5 to 1." The line has three parts. "I changed this" answers what is different. "For this job" answers why. "I checked it" answers how you know. If a part is missing, the reader has to guess.

Add a fourth part when it matters: what you gave up. The capstone's critique log has columns for what was wrong, the rule or evidence, the change and what was given up. The one line is the middle of that row.

A line can also be wrong. Suppose Rand writes "I made the title serif because it looks classic". A reader cannot check "classic". A better line names the job: "the title is the only serif line, so it is the one thing that stands out. I checked that it reads at a phone size". Chapter 4.4 teaches how to check someone else's lines the same way.

</GoDeeper>

```quiz
question: "Walid's sports club page has the framework's default title, 'Welcome'. He changes the title, and only the title. Which change is a choice that a reader can name?"
options:
  - "'Pitch 2 is free 5 to 7 pm', since players come to book a pitch"
  - "A script font for the title, since the old font looks plain to him"
  - "A purple gradient behind the title, since gradients look modern"
  - "'Welcome to our club!', since a friendly title feels warm"
correct: 0
explanations:
  - "Right. It names the job (players come to book a pitch) and a change (the title shows what is free). A reader can check it: do players find a free pitch fast?"
  - "'Looks plain' names no problem the person has. A script font may also be harder to read on a phone, so the reason is a taste, not a check."
  - "'Looks modern' is a feeling a reader cannot check, and a gradient needs its own contrast check. It names no job."
  - "'Feels warm' names no job. The words could sit on any club page, so they are still a default that nobody chose."
```
