## Pick by job, money and device

<InteractiveCanvas slug="pick-a-visual-tool" />

Change one fact at a time. A diagram and a recording stay the same whatever you can pay. A screen design changes with money and with your device. Every pick has a free path, and if a tool does not open for you, use its second tool or the paper fallback.

<GoDeeper title="Go deeper: the tools behind each pick, at the time of writing (checked 2026-10-25)">

Chat assistants such as Claude and Gemini can build a small page or mock-up next to the chat. Claude calls this an artifact. Since 16 September 2026, new artifacts start from templates such as Docs, Slides and Design, and the older style can no longer be created. They start private, and saving data or connecting apps needs a paid plan. Gemini calls its workspace Canvas. Google's plan table appears to list Canvas among the features that need no paid plan, with limits that refresh every five hours. If you share a Gemini page, anyone with the link can open it. For an app, Google warns that anyone with the public link can view and edit its data. So never put private data in a page you share. Claude is for people aged 18 or over. Gemini is for ages 13 and over. Check which one opens for you.

Claude Design is a research preview that Anthropic launched on 17 April 2026. Its launch page lists paid plans, while a separate help page says Free users can start from a Design template. The two pages disagree, so do not count on it with a free account. Google Stitch is an experiment from Google Labs that turns a prompt or an image into a screen design. Google's pages do not say who can use it, and Google's own staff say that blocks come from regional limits or from the age set on a Google account. If neither opens, use a paper sketch. Draw each screen, label every button, photograph it, and write in the caption that it is a sketch.

A coding helper such as OpenAI's Codex can read your project, run commands and suggest a change for you to review. A free ChatGPT account includes some use. The limit changes, so check the usage page. ChatGPT is for ages 13 and over, with a parent's permission under 18. Use a coding helper to build a demo page only if you read every change before you accept it, as the explain-back rule in chapter 7.4 asks.

A <GlossaryTerm term="skill" definition="A saved set of instructions that an AI tool can load for one kind of job, such as designing a clean page." /> can make a tool follow good habits for a page. Read a skill before you use it, the same way you read a package before you install it in chapter 4.3. Some skills carry their own licence, so read the licence file in the skill's folder.

</GoDeeper>

## Draw it as text, then check every arrow

<MermaidDiagram title="The diagram check" chart={`flowchart TD
  A["Ask for the diagram as text"] --> B["A viewer draws it"]
  B --> C["Check every arrow against your code"]
  C -->|"an arrow has no code behind it"| D["Fix the text"]
  D --> B
  C -->|"every arrow is true"| E["Save it in your repository"]
`} legend="An assistant draws what sounds likely. You keep only the arrows that your project really has." />

An assistant can write your diagram in <GlossaryTerm term="Mermaid" definition="A way to write a diagram as a few lines of text, which a viewer then draws as a picture." />. It draws what sounds likely, not what your code does. Check every arrow against your project, as you did for diagrams in chapter 3.3. Delete any box that has no code behind it.

<GoDeeper title="Go deeper: the text behind a diagram">

Each line of Mermaid text is an arrow. Here is Rota's diagram as Shatha saves it.

```text
flowchart TD
  V["Volunteer"] --> P["Rota page"]
  C["Coordinator"] --> P
  P --> S[("Shift list")]
```

The round brackets with a straight line inside draw the shape of a database. Rota keeps its shifts in a plain list, so the shape is a simple store. At the time of writing, GitHub draws a diagram inside a README when the text sits in a code block labelled mermaid. Check that yours draws. If it does not, paste the text into any Mermaid viewer and save the picture.

The common failure is an extra box. Shatha's first answer from the assistant added a "Text message server" between the page and the volunteers. Rota sends no messages, so no code stood behind that box. She deleted it. A diagram with one wrong box teaches a reader something false, and a reader cannot tell which box is the false one. If you cannot point to the file or the function behind an arrow, remove the arrow.

</GoDeeper>

## Keep every page light

<MermaidDiagram title="One example of a light first view" chart={`flowchart TD
  T["First view: about 170 KB"] --> J["JavaScript 100 KB"]
  T --> I["Images 30 KB"]
  T --> F["Fonts 20 KB"]
  T --> C["Style rules 10 KB"]
  T --> H["Page text 10 KB"]
`} legend="Google's web.dev example split for a slow connection. The five parts add up to 170 KB." />

A light page opens on a weak connection. A starting limit from Google's web.dev is about 170 KB for what the first view needs. Their example split is shown. The article is from 2018, so treat the numbers as a start. Open your browser's network tab to see your own page's size before you share it.

<GoDeeper title="Go deeper: how heavy pages are today">

The web.dev article on performance budgets suggests keeping the first view under about 170 KB, compressed, so a site stays fast even on inexpensive devices and slow 3G connections. Its example split is 100 KB of JavaScript, 30 KB of images, 20 KB of fonts, 10 KB of style rules and 10 KB of page text. The sum of 100, 30, 20, 10 and 10 is 170. The page was last updated in 2018, which is why it is a starting point and not a rule.

For scale, the 2025 Web Almanac reports a median home page of 2.56 MB on mobile. Taking 1 MB as 1,000 KB, that is about 15 times the 170 KB budget. Your demo does not have to be a normal website. A single HTML file with a little style can stay far below the budget. When a tool builds a page for you, it may add libraries you did not ask for. Ask for plain HTML and style rules, then check the size.

</GoDeeper>

## Show it working in under a minute

<MermaidDiagram title="A recording in three parts" chart={`flowchart LR
  A["The problem, 10 s"] --> B["One path, 20 s"] --> C["Result and link, 10 s"]
`} legend="About 40 seconds in total. The part lengths are a plan to adjust, not a rule." />

A short recording shows the real app. Say what it is for, show one path through it, and end on the result and the link. Keep it under a minute, and check the file size before you send it. If a screen is a mock-up, say so on screen.

<GoDeeper title="Go deeper: recording and motion tools">

For a recording on a laptop, OBS Studio is free and open source, and it runs on Windows 10 and 11, macOS 13 or newer, and Linux. It needs no account. On a phone, use the phone's own screen recorder if it has one. If it does not, take screenshots in order and add a short caption to each. Both routes are free.

Motion graphics tools are options only, and this course has no install lab for them. Remotion makes videos from React code. It is free for individuals, non-profits and for-profit organisations with up to three employees, and larger companies need a licence. It is source-available under its own licence, not a standard open-source one. Motion Canvas makes vector animations in TypeScript and is MIT licensed. Manim Community Edition makes precise maths animations in Python and is MIT licensed. All three need a local install on a laptop. Claude's Motion template makes animated explainers, but it is a beta for team plans only.

An assistant can help with the script and the list of shots. It cannot fake the app. Show the real thing, and label anything that is a mock-up or a made-up number.

</GoDeeper>
