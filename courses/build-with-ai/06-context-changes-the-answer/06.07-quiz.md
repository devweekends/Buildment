```quiz
type: mcq
question: "Rahaf works at a company that sells hosted caching to customers. The Redis licence page says: Redis 7.2 and earlier, BSD 3-clause; 7.4 to 7.8, RSALv2 or SSPLv1; 8 and later, RSALv2, SSPLv1 or AGPLv3. She asks an assistant which cache to run, and it answers: 'Use Redis. It is open source under the BSD licence, so you can offer it to customers as a service with no limits.' What is wrong with the answer?"
options:
  - "Nothing is wrong: the BSD licence covers every Redis version, so she can go ahead"
  - "BSD covers only Redis 7.2 and earlier, so she must read the page for her version"
  - "Redis is closed source now, so she should drop it and choose something else"
  - "BSD forbids offering software as a service, so she should buy a licence before she starts"
correct: 1
explanations:
  - "The page she quoted lists three licences by version. BSD is only the first row, so the answer ignores the later rows."
  - "Right. The answer treats one row of the table as all of it. Her next check is the licence page for the exact version she will run, with the date she read it."
  - "The table shows that Redis 8 and later include AGPLv3, which is open source. Redis is not simply closed, and dropping it is not what the page supports."
  - "BSD does not forbid hosting. The limits on offering the software as a service belong to RSALv2, which applies to newer versions."
```

```quiz
type: mcq
question: "Nabeel runs a phone-repair shop. Facts: 1) The shop's app saves about 30 repair tickets a day. 2) Only the app writes, and it runs on the shop's one computer. 3) The owner wants a weekly count of repairs per phone model. 4) The shop has nobody to run a server. An assistant says: 'ClickHouse is the fastest database, so use it.' Which conclusion do the facts support?"
options:
  - "A database inside the app, such as SQLite, because one program writes and no server can run"
  - "ClickHouse, because the weekly count is a total, and ClickHouse is built for totals over many rows"
  - "PostgreSQL, because it is the common choice and it handles many writers on a server"
  - "An LSM store, because tickets arrive all day and cheap writes are the main need"
correct: 0
explanations:
  - "Right. Fact 2 gives one writer on one computer and fact 4 rules out a server, so a database inside the app fits. The weekly count is a small job at 30 tickets a day."
  - "Fact 4 says nobody can run a server, and ClickHouse needs one. At 30 tickets a day, the weekly total is also a small job, not a scan of very many rows."
  - "Fact 2 says only the app writes, so there are no many writers to serve. Fact 4 rules out the server that PostgreSQL would need."
  - "Fact 1 gives 30 tickets a day, which is not a heavy stream of writes. An LSM store is worth it for nonstop writes where slower reads are fine."
```

```quiz
type: mcq
question: "A fictional vendor's page says: 'Our metrics store uses up to 7 times less memory than Prometheus.' Dima's team has these facts. 1) One Prometheus server holds all 40 services. 2) It uses 20% of the server's memory. 3) Data is kept for 30 days. 4) Nobody on the team has run the vendor's store. What should the team do about the claim?"
options:
  - "Switch now, because a saving of 7 times is certain whenever a vendor publishes it"
  - "Ignore it, because every number that a vendor publishes about its own product is false"
  - "Keep Prometheus: memory is no pain, and the saving is an untested claim"
  - "Move to Thanos, because one server that holds 40 services needs a global view"
correct: 2
explanations:
  - "'Up to 7 times' is the vendor's own claim, tested by the vendor. Fact 4 says the team has never measured it on their data."
  - "A vendor's number is a claim to test, not a lie. It may help a team whose memory is the problem. Here fact 2 shows it is not."
  - "Right. Fact 2 shows no memory pain, fact 3 a short keep time, and fact 4 that the claim is untested. They can revisit if memory or disk cost becomes their problem."
  - "Fact 1 says one server holds everything, so there is no second server to join. Thanos and Mimir add a global view over several servers."
```

```quiz
type: mcq
question: "Munir's booking service must save a booking and tell the invoicing service. Facts: 1) If the event is lost, a customer is never billed. 2) The database has transactions. 3) Only invoicing needs this event. 4) The team can run one extra process. Which way fits?"
options:
  - "Publish directly after the save, because an event is cheap to send again later if it is lost"
  - "Write to Kafka first and let the database follow what Kafka holds about each booking"
  - "Read the change of every table through CDC and send all of those changes on to invoicing"
  - "An outbox row saved with the booking and a relay to publish it, so invoicing must cope with repeats"
correct: 3
explanations:
  - "Fact 1 says a lost event means a customer is never billed. A direct publish can lose the event if a crash falls between the save and the publish."
  - "Fact 2 says the database has transactions, so there is no need to let it lag behind Kafka. That way costs a stale read for no gain."
  - "Fact 3 says one service needs one event. Sending every table's changes is more than invoicing needs, and it is more to run than the single process in fact 4."
  - "Right. Facts 1 and 2 say the booking and the event must both happen, and a transaction can hold both. Fact 4 covers the relay. Delivery is at least once, so invoicing must be idempotent."
```
