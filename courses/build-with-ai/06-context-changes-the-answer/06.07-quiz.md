type: mcq
question: "Munir works at a company that sells hosted caching. The Redis licence page says: Redis 7.2 and earlier, BSD 3-clause; 7.4 to 7.8, RSALv2 or SSPLv1; 8 and later, RSALv2, SSPLv1 or AGPLv3. He asks an assistant which cache to run, and it answers: 'Use Redis. It is open source under the BSD licence, so you can offer it to customers as a service with no limits.' What is wrong with the answer?"
options:
  - "The answer is correct and he can go ahead with any version"
  - "BSD covers Redis 7.2 and earlier, and later versions differ"
  - "Redis is closed source now and the company should drop it"
  - "BSD forbids offering software as a service and a paid licence is needed"
correct: 1
explanations:
  - "The page he quoted lists three licences by version. BSD is the first row only, so the answer ignores the later rows."
  - "Right. The answer treats one row of the table as the whole table. His next step is the licence page for the exact version he will run, with the date he read it."
  - "The table shows that Redis 8 and later include AGPLv3, which is open source. Redis is not simply closed, and dropping it is not what the page supports."
  - "BSD does not forbid hosting. The limits on offering the software as a service belong to RSALv2, which applies to newer versions."

type: mcq
question: "A phone-repair shop's app (fictional) has these facts. 1) It saves about 30 repair tickets a day. 2) Only the app writes, and it runs on the shop's one computer. 3) The owner wants a weekly count of repairs per phone model. 4) The shop has nobody to run a server. An assistant says: 'ClickHouse is the fastest database, so use it.' Which conclusion do the facts support?"
options:
  - "A database inside the app, for example SQLite, with no server to run"
  - "ClickHouse, a column store for the weekly count of repairs per phone model"
  - "PostgreSQL, the common choice for many writers on a server"
  - "An LSM store, cheap writes for tickets that arrive throughout the day"
correct: 0
explanations:
  - "Right. Fact 2 gives one writer on one computer and fact 4 excludes a server, so a database inside the app fits. The weekly count is a small job at 30 tickets a day."
  - "Fact 4 says nobody can run a server, and ClickHouse needs one. At 30 tickets a day, the weekly total is also a small job, not a scan of very many rows."
  - "Fact 2 says only the app writes, so there are no many writers to serve. Fact 4 excludes the server that PostgreSQL would need."
  - "Fact 1 gives 30 tickets a day, which is not a heavy stream of writes. An LSM store is worth it for nonstop writes where slower reads are fine."

```quiz
type: mcq
question: "A booking service (fictional) must save a booking and tell the invoicing service. Facts: 1) If the event is lost, a customer is never billed. 2) The database has transactions. 3) Only invoicing needs this event. 4) The team can run one extra process. Which way fits?"
options:
  - "Publish directly after the save and resend the event if it is lost"
  - "Write to Kafka first and let the database follow what Kafka holds"
  - "Read the changes of every table through CDC and send them on to invoicing"
  - "Save the booking and an outbox row together, with a relay to publish the event"
correct: 3
explanations:
  - "Fact 1 says a lost event means a customer is never billed. A direct publish can lose the event if a crash falls between the save and the publish."
  - "Fact 2 says the database has transactions, so there is no need to make it lag behind Kafka. That way costs a stale read for no gain."
  - "Fact 3 says one service needs one event. Sending every table's changes is more than invoicing needs, and it is more to run than the single process in fact 4."
  - "Right. Facts 1 and 2 say the booking and the event must both happen, and a transaction can hold both. Fact 4 covers the relay. Delivery is at least once, so invoicing must be idempotent."
```
