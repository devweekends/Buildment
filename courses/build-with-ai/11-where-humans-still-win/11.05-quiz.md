```quiz
type: mcq
question: "Bayan reads this on a vendor's blog: 'Teams that use our coding assistant finish 40% more tasks.' She opens the post and finds three facts. 1) The vendor wrote the post. 2) The 40% comes from 12 customers that the vendor chose. 3) A task counts as finished when the assistant suggested code, whether or not anyone kept it. What do the facts support?"
options:
  - "An independent measurement of finished work, which is safe to use as it stands"
  - "A result that holds for every team, since the sample is large enough"
  - "A vendor's own claim from a chosen sample: a reason to test, not proof"
  - "A count of kept code, so the code the assistant wrote must be good"
correct: 2
explanations:
  - "Fact 1 says the vendor wrote the post, and fact 2 says the vendor chose the 12 customers. That is a company's own claim, not an independent measurement."
  - "Fact 2 says the 40% comes from 12 customers that the vendor chose. A small chosen sample cannot show what would happen for every team."
  - "Right. The vendor wrote it, chose the 12 customers, and counted suggestions as finished work. It is a good reason to try the tool on your own work, and it is not proof that the tool helps."
  - "Fact 3 says a task counts when the assistant suggested code, whether or not anyone kept it. That counts suggestions, not code that was good enough to keep."
```

```quiz
type: mcq
question: "Ehab asks two chat assistants whether a mentoring program for open-source contributors (a fictional program) accepts people who are not students. Both answer: 'Only university students can apply.' Ehab then opens the program's own rules page, updated this year. It says: 'Anyone aged 18 or over can apply, whether or not they are students.' What should he do?"
options:
  - "Go by the rules page, since the program wrote it and it is current"
  - "Trust the two answers, since two assistants agreeing makes an error unlikely"
  - "Ask a third assistant and go with the answer that two of three give"
  - "Paste the page into an assistant and use only its summary of the page"
correct: 0
explanations:
  - "Right. The rules page is the primary source, written by the program and dated this year. Two assistants can share the same old answer, so their agreement does not outweigh it."
  - "Models often make the same mistake, so agreement between them does not prove an answer is right. The page that he can read himself says otherwise."
  - "A vote between assistants is still not a source. All of them can repeat the same out-of-date answer, and the rules page is one click away."
  - "He can read two lines himself. A summary adds a chance of a new mistake, and the page already answers the question."
```

```quiz
type: mcq
question: "Rami is a freelance web developer. A client's site crashed. The client's office manager pasted the server log into a chat assistant and sent Rami its summary. 1) The log holds the site's payment API key on line 12. 2) The summary says: 'The crash began at 14:05 when the payment service timed out.' 3) The log itself shows the first error at 13:52, in the database connection. What should Rami do first?"
options:
  - "Fix the payment service, since the summary says it failed at 14:05"
  - "Get the key replaced and check the summary against the log, as both failed"
  - "Delete the chat with the log, since that takes the key out of the tool"
  - "Paste the log into a second AI tool, since two summaries are safer"
correct: 1
explanations:
  - "The log puts the first error at 13:52, in the database connection, before any payment timeout. The summary is wrong, and the key is still exposed."
  - "Right. Two habits at once. A key that went into a chat tool is treated as stolen: cancel it and make a new one. And an AI summary is checked against its source, which here points to the database at 13:52."
  - "Deleting the chat feels like a fix, but the key has already left the client's hands. Treat it as stolen and replace it. The summary also still needs checking."
  - "A second tool would spread the key further, and a second summary is still not the source. The log itself already answers the question."
```

```quiz
type: mcq
question: "Sami's chat assistant answers 'Which database should my clinic booking tool use?' with: 'Use ClickHouse. It is the fastest database.' Sami finds three facts. 1) The tool saves one booking at a time, about 300 a day, and each booking must be saved whole or not at all. 2) The 'fastest' claim comes from a benchmark of one flat table of web-analytics rows. 3) One person runs the server. What do the facts support?"
options:
  - "Use ClickHouse, since a benchmark win means it is fastest for any job"
  - "Use a write-optimised store, since saving bookings is mostly writing"
  - "Run two databases at the start, since one person can manage both"
  - "Ask which job 'fastest' measured; it was not saving single bookings"
correct: 3
explanations:
  - "Fact 2 says the claim comes from one flat table of web-analytics rows. A win on that job says little about saving one booking at a time."
  - "Fact 1 says about 300 bookings a day, a small write load, and each booking must be saved whole or not at all. A write-optimised store trades cheaper writes for costlier reads, and he does not need that trade."
  - "Fact 3 says one person runs the server. Two databases means two things to look after, and nothing in the facts asks for it."
  - "Right. 'Fastest' needs a job. The benchmark measured a different job from saving single bookings safely, so the claim does not settle the choice. The next step is to compare it with Sami's workload."
```

```quiz
type: mcq
question: "Manar wants an AI assistant to summarise the open issues in her study group's public repository. 1) Anyone can write an issue there. 2) The assistant only needs to read issues. 3) Her account also holds private client work. 4) She will use the setup for two weeks. Which token fits?"
options:
  - "A classic token with full rights, so the assistant never hits a limit"
  - "A read-only token for all her repositories, so one setup covers later tasks"
  - "A fine-grained token for that one repository, read-only, with an expiry date"
  - "A read-only token for that one repository that never expires, to avoid renewing it"
correct: 2
explanations:
  - "Fact 2 says the assistant only needs to read. Full rights add the power to change or delete, and anyone can write an issue that may carry hidden instructions."
  - "Fact 3 says her account holds private client work. A token for all her repositories lets text in a public issue steer an assistant that can reach private code, a risk that a security company showed in 2025."
  - "Right. One repository, read-only, with an expiry date is the least access the job needs. It also fits the two weeks she will use it."
  - "Fact 4 says two weeks. GitHub advises always adding an expiry date, so the token stops working when the job is done."
```
