# Shop the collection gate

This gate is walked on a phone, or on a desktop browser narrowed to 360 pixels with the network throttled to something honest. A gallery that is elegant at 1440 pixels and unusable at 360 has failed the learner this variant is written for, and no screenshot at desktop width can show that.

Bring the running API, the seed with two sold pieces, and one browser window you can resize. Keep a second window open on the network panel with "disable cache" ticked, so a stale response cannot pass for a fast one.

## Walk the collection

Open the collection and read the first card without tapping it. It should show a photo, a title, a maker line, a price with the correct decimals, and a ready range in words. There should be no quantity control anywhere on the page, and no phrase about availability alerts. The sold label should appear as a word inside the card for the two sold pieces when the "show sold work" toggle is on.

Apply a craft filter, then a ready-time filter, then combine them. Watch the URL change as you do. Reload the page and confirm the filters return. Press back and confirm the previous result set returns. Change the country selector and check that a workshop which does not serve that country loses its cards while the other workshops keep theirs. Then set a filter that matches nothing and read the empty state: it should say that no piece matches and offer a way to clear the filters.

Page through the collection. The bar should read "20 of 34" or whatever your seed total is, and the previous button should be disabled on the first page. Change a filter while on page 2 and confirm the page resets to 1 rather than showing an empty grid.

## Read one piece like a buyer

Open an available piece from ceramics. The gallery should show the first photo large and the rest as thumbnails, each with its own description in the alt attribute. The page should list materials, technique, dimensions in centimetres and inches, and care notes, in that order, followed by the ready range and one sentence about shipping to your selected country.

Repeat with a buyer country the workshop excludes. The sentence must say the workshop does not ship there, and there must be no cart button pretending otherwise. Repeat with a workshop whose shipping is paused, and confirm the page explains the pause without naming a date. Then set the country back and confirm the rate and transit range return.

Scroll to the maker credit. It should read "Made by" a name, or "Made at" the workshop, matching the artisan's display choice in the seed. Change the seed artisan to the workshop-only display, reload, and confirm the credit changes without the name leaking into the page source.

## Try the sold piece

Open one of the two sold pieces. There must be no add-to-cart control, no quantity field and no notification signup. The only action should be "Request something similar". Follow it and read the URL: it should carry the workshop ID and `inspiredBy` equal to the sold piece ID. Reload that URL and check both values survive.

Now search the client and server source for the words "notify", "back in" and "alert". The result should be empty apart from code that handles error banners. Any match that offers to tell a buyer when a piece returns is a defect against this variant's product policy, however small the button looks.

Finally, request a draft piece by URL. You should get the not-found page with a link back to the collection and no title, price or workshop name in the response or the page. Do the same for an archived piece.

## Check the page with a keyboard

Put the mouse aside. Tab from the top of the collection: the first focus should be a visible skip link, then the filter panel button, then each card in order. Open a card with Enter, then tab through the gallery thumbnails and the action area. Every control needs a visible focus ring, and the thumbnails need accessible names rather than the word "image".

Run the browser accessibility panel on the piece page. Images should have descriptions or be marked decorative, headings should run in order without skipping a level, and the contrast of body text against its background should pass at the sizes you used. Tap the filter button and the action button with a thumb: both targets should be comfortable at 44 pixels, not the thin text link that looks tidy on a laptop.

## Gate checklist

- [ ] The collection renders on a 360 pixel wide screen with no horizontal scrolling and one card per row.
- [ ] A card shows photo, title, maker line, price with correct decimals, ready range and a sold label where it applies.
- [ ] No quantity control, availability alert or "notify me" control exists on the collection or the piece page.
- [ ] Filters write to the URL, survive a reload and a back press, and reset the page number when changed.
- [ ] An empty filter result explains itself and offers a reset rather than a blank grid.
- [ ] Pagination shows the count, disables the impossible direction and keeps the filter bar in view.
- [ ] The piece page lists photos in the maker's order, materials, technique, dimensions in two units and care notes.
- [ ] The maker credit follows the artisan's display choice and never invents a name.
- [ ] Shipping renders a rate with a transit range, a not-shipped sentence or a paused sentence, per workshop and country.
- [ ] A sold piece shows the request link and carries the workshop ID and `inspiredBy` piece ID in its URL.
- [ ] A draft or archived piece returns the not-found page with no title, price or workshop name.
- [ ] Keyboard order, focus rings, alt text and tap targets pass the pass described above.

## Learning log

1. Which three filters did you keep in the visible bar, and which did you put behind the panel? Name the buying decision each one serves.
2. Show the exact URL for a sold piece's request link and explain why it carries no price and no buyer identifier.
3. What did the page render for a held piece, and which component decision made that different from the sold case?
4. Which value proved your price formatter, and what did the unformatted version look like? Give the minor units and the rendered string.
5. Which photo sizes did the card and the piece page request, and what happened to the page layout before the explicit width and height were added?
6. Which accessibility check failed first, and what did you change? If nothing failed, name the two checks you ran and the tool you used.

Write the answers with values, URLs and screen widths. A reviewer should be able to reproduce the sold-piece link and the shipping sentences from the log alone, then repeat the keyboard pass on the same page.

## What this gate does not prove

The cart does not exist yet, so nothing here proves that an available piece can be added, held or paid for. The request form arrives in module 22, and this gate only proves the handoff contract, not the brief, the photos or the workshop inbox. There is no saved search, no recommendation and no translation, so the page is English only and does not yet handle a right-to-left layout.

The gate also says nothing about performance under load or behind a cache. Image transformations and a small JSON payload make the first visit lighter, but a real measurement on a slow mobile network is the next module's business once the cart adds requests to the same pages.

The next module gives the buyer a cart made of exact pieces, which is the first place where a chosen object can become unavailable between two page views.
