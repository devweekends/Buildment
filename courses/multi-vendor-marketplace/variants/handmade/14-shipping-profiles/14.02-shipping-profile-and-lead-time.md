# Shipping profiles, lead times and packaging

The previous lesson separated three clocks. This lesson stores them. A shipping profile is one document per workshop: where parcels leave from, which destinations the workshop serves, what it charges, how long packing takes, how long transit takes for each group of destinations, how the piece is packed, and whether shipping is paused right now.

Keep one rule in mind while writing the schema. A range belongs in the document as two integers, and a sentence is built from them at read time. Storing "about two weeks" as text means no later code can compare a promise with a date, and the checkout module will have to parse English.

## The profile document

```js
// server/src/modules/shipping/shipping.model.js
const zoneSchema = new Schema({
  code: { type: String, required: true },              // "gulf", "europe", "uk"
  countries: { type: [String], required: true },       // ["AE", "SA", "QA"]
  rateCents: { type: Number, min: 0, default: null },  // null when quoteRequired
  currency: { type: String, required: true },
  quoteRequired: { type: Boolean, default: false },
  transitMinDays: { type: Number, min: 0, max: 120, required: true },
  transitMaxDays: { type: Number, min: 0, max: 120, required: true },
}, { _id: false });

const shippingProfileSchema = new Schema({
  workshopId: { type: Schema.Types.ObjectId, ref: "Workshop", required: true, unique: true },
  shipsFromCountry: { type: String, required: true },   // ISO 3166-1 alpha-2
  handlingMinDays: { type: Number, min: 0, max: 60, required: true },
  handlingMaxDays: { type: Number, min: 0, max: 60, required: true },
  zones: { type: [zoneSchema], default: [] },
  packagingNote: { type: String, maxlength: 300, default: "" },
  customsDescription: { type: String, maxlength: 120, default: "" },
  customsMaterial: { type: String, maxlength: 120, default: "" },
  paused: {
    isPaused: { type: Boolean, default: false },
    note: { type: String, maxlength: 140, default: "" },
  },
  version: { type: Number, default: 1 },
}, { timestamps: true });
```

The unique index on `workshopId` is the rule that a workshop has one profile rather than five. Without it, a double tap on the save button creates a second profile and the resolver reads whichever one the database returns first, which gives a rate that changes between two page loads. Read the unique index documentation if you have only used `unique: true` on a field without checking whether the index exists in the database after a deploy.

The version number is small and useful. A checkout will snapshot the shipping amount and the ranges the buyer accepted, and recording which version supplied them turns a later question about a receipt into one lookup. Increment it on every save that changes zones, rates or handling.

## Validate the ranges, not just the fields

A schema that accepts a minimum of nine days and a maximum of four passes every type check and gives a nonsense sentence. Validate the pair, the country list and the quote flag together, in one function the routes call, so the same rules apply to the maker form and to any later import.

```js
// server/src/modules/shipping/shipping.rules.js
export function profileProblems(input) {
  const problems = [];
  if (input.handlingMinDays > input.handlingMaxDays) problems.push({ field: "handling", code: "RANGE_ORDER" });
  if (!/^[A-Z]{2}$/.test(input.shipsFromCountry ?? "")) problems.push({ field: "shipsFromCountry", code: "COUNTRY_CODE" });
  const seen = new Set();
  for (const zone of input.zones ?? []) {
    if (zone.transitMinDays > zone.transitMaxDays) problems.push({ field: `zones.${zone.code}`, code: "RANGE_ORDER" });
    if (zone.quoteRequired && zone.rateCents != null) problems.push({ field: `zones.${zone.code}`, code: "RATE_OR_QUOTE" });
    if (!zone.quoteRequired && !(zone.rateCents > 0)) problems.push({ field: `zones.${zone.code}`, code: "RATE_REQUIRED" });
    for (const country of zone.countries ?? []) {
      if (!/^[A-Z]{2}$/.test(country)) problems.push({ field: `zones.${zone.code}`, code: "COUNTRY_CODE" });
      if (seen.has(country)) problems.push({ field: `zones.${zone.code}`, code: "COUNTRY_TWICE" });
      seen.add(country);
    }
  }
  if (input.paused?.isPaused && !input.paused.note?.trim()) problems.push({ field: "paused.note", code: "PAUSE_NOTE_REQUIRED" });
  return problems;
}
```

The route turns a non-empty problem list into a 400 with `code: "PROFILE_INVALID"` and a `fields` object keyed by the field name, so the form can place each sentence beside its input. Every one of those problems is a plain sentence in the form, not a stack trace. A country in two zones is the one that surprises people: it means two different transit ranges claim to describe the same destination, and the resolver's answer depends on array order. Refuse the profile and let the maker decide which zone owns it.

## Resolve one country to one answer

The resolver is a pure function with no database call, which is why it can be tested with fixtures and reused by the piece page, the cart and the checkout. It returns one of four answers, and the four are exhaustive by design.

```js
// server/src/modules/shipping/shipping.resolve.js
export function resolveShipping(profile, rawCountry) {
  if (!profile) return { status: "not_shipped" };
  if (profile.paused?.isPaused) return { status: "paused", note: profile.paused.note };
  const country = String(rawCountry ?? "").toUpperCase();
  const zone = profile.zones.find((z) => z.countries.includes(country));
  if (!zone) return { status: "not_shipped", country };
  if (zone.quoteRequired) return { status: "quote_required", zone: zone.code };
  return {
    status: "rate",
    zone: zone.code,
    rateCents: zone.rateCents,
    currency: zone.currency,
    handlingDays: [profile.handlingMinDays, profile.handlingMaxDays],
    transitDays: [zone.transitMinDays, zone.transitMaxDays],
  };
}
```

The pause check comes first on purpose. A maker who cannot post anything should not be quoted a rate for a destination, even if the zone is configured and priced, because the buyer would read the rate as availability. Returning paused first also means a paused profile does not have to be rewritten to remove its zones, and the maker can unpause a week later with the rules intact.

## Lead time for a made-to-order piece

A finished piece page shows handling plus transit, because the object exists and only has to be packed. A made-to-order piece has one more clock, and that clock belongs to the quote. The quote module stores the production range for one commission, and the commission shows the ready window computed from the deposit date and that range.

This lesson therefore stops at handling and transit and prepares the fields the quote will read. Do not put a production range on the shipping profile, because two commissions from the same workshop can have different production ranges depending on the brief. Do not put a delivery date on the piece either. The piece page can say packing takes two to three days and transit to your country has taken seven to fourteen days, and that sentence is complete without a date on it.

The interface rule is short. Format a range from its two integers as "two to three days" or "7 to 14 days", always both ends, never a single number and never an average. An average hides the bad week, which is the week the buyer plans around.

## One profile, or one per piece

A workshop could carry shipping on each piece instead of on the workshop, and the argument for it is real. A ceramic bowl and a flat cover do not weigh the same, and a maker might want a separate rate for each. The cost is where the numbers hide. Twelve pieces with their own rates means twelve places to update when a courier raises a price, twelve chances to forget one, and no single document a buyer or a reviewer can read to understand the workshop's policy.

Choose one profile per workshop for now, because most of the variation sits in the destination rather than in the object. A heavier object usually travels to the same countries as a lighter one, so a zone with a higher rate covers it, and the packaging note explains the difference to the buyer. Keep the profile's version number honest so a later change is visible.

Switch when a workshop genuinely ships two kinds of parcel on different routes, for example small flat textiles by post and large ceramics by courier. Then add an optional per piece override that copies the profile's ranges, changes only the rate and the carrier note, and records which profile version it came from. That keeps one readable policy while allowing an exception that a reviewer can see.

## Packaging is part of the promise

A glazed bowl and an embroidered cover do not survive the same journey. Packaging decides whether the bowl arrives whole, and it also changes the parcel's weight and size, which changes the rate. That is why the profile carries a packaging note rather than treating packing as a private workshop habit.

Write the note for the buyer, in one or two sentences. A double boxed bowl with foam between the walls, the cover wrapped in cloth and posted flat, a wooden board corner protected and marked fragile. Then use the note in two places: on the piece page beside the shipping range, and in the maker's own packing checklist. A note that says premium packaging without saying what it means is marketing text and teaches nobody.

The customs defaults belong beside it. A description and a material for a typical parcel from this workshop save the maker from retyping them for every order, while the declared value comes from the order itself. Never let the browser send a declared value, and never let it be lower than the price the buyer paid.

The last test checks two things at once, which is deliberate. A refused write that still creates a profile has failed even though the status code looks correct. Count documents for the workshop before and after.

## Acceptance criteria

One workshop has exactly one profile, enforced by a unique index and by the route that upserts it. The profile stores the ship from country, a handling range, a set of zones with a flat rate or a quote flag and a transit range each, a packaging note, customs defaults, a pause note and a version. Saving an inverted range, a country in two zones, a rate beside a quote flag, or a pause without a note returns a field error and writes nothing.

The resolver returns exactly one of four answers for any country code, and its pause check runs before the zone lookup. A piece page can render handling and transit as two labelled ranges with no date anywhere. A maker can pause shipping with a note and unpause a week later without losing zones. The next lesson is the gate, and it asks for three buyer countries, three different answers, and one paused destination that shows the maker's note in place of a rate.
