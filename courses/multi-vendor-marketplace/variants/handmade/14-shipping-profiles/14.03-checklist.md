# Shipping profile gate

This gate is passed with one profile, three buyer countries and four answers. A rate for a served destination, a refusal for a destination the workshop does not serve, a quote required answer for a zone the maker will not price, and a paused answer with a note. The evidence is the response body for each country plus the sentence the piece page renders from it.

The point of the gate is not that shipping works. It is that the workshop's decision is stored once, resolved consistently, and shown to a buyer without inventing a delivery date. A maker who cannot say where a parcel goes and how long packing takes cannot sell across a border, and a marketplace that guesses on her behalf will eventually make a promise she has to break.

## Build the profile and the four buyers

Create one profile for Bayt al Zayt with a ship from country, handling of two to three days, and three zones: a neighbouring zone with a flat rate, a wider zone with a flat rate and a longer transit range, and a zone marked quote required. Add a packaging note and a customs description for a glazed bowl. Leave a country outside every zone so the not shipped answer has somewhere to come from.

Then call the piece shipping route four times with four country codes. Write the four response bodies in the learning log. Each one should be short and different, and none of them should contain a rate when the answer is not a rate. A quote required answer that still carries a number is worse than a missing field, because the interface will show it.

Pause the profile with a note that names when the maker is posting again, and call the route once more for a served country. The answer must be paused with the note and no rate, and the piece page must show that note where the shipping range used to be. Unpause and confirm the original zones return unchanged, which proves the pause did not delete the rules.

## Check the numbers and the words

Read the rate answer closely. The amount comes from the zone, the currency comes with the zone, and the handling and transit values are two pairs of integers. Compare them against the profile document in the database, then compare them against the sentence on the page. The page should read like packing takes two to three days and transit has taken seven to fourteen days, with both ends of both ranges.

Now search the rendered page for a date. There should not be one, and the search is not a joke: a template that formats a range into a single date is the most common way this model gets undone. If you find a date, look for the code that computed it from the deposit, because that code is deciding something the maker never said.

Try the profile writes that should fail. Send a zone whose transit minimum is above its maximum, send the same country in two zones, send a rate beside a quote flag, and pause without a note. Each must return a field error naming the field, and the stored profile must be unchanged. Then sign in as the second workshop and try to replace the first workshop's profile. The refusal must leave one profile in the collection, not two.

## Gate checklist

- [ ] One workshop has exactly one shipping profile, and a unique index on the workshop field enforces it.
- [ ] The profile stores the ship from country, handling range, zones, packaging note, customs defaults, pause state and version.
- [ ] Every zone has a country list, a rate in minor units or a quote flag, and a transit range.
- [ ] An inverted handling or transit range is refused with a field error and writes nothing.
- [ ] A country listed in two zones is refused rather than silently resolved by array order.
- [ ] A rate beside a quote flag is refused, and a zone without either is refused.
- [ ] Pausing without a note is refused, and the note is shown to the buyer while paused.
- [ ] The resolver returns exactly one of rate, quote required, paused or not shipped for any country code.
- [ ] The pause check runs before the zone lookup, and the order is visible in the code.
- [ ] A served country returns a rate with handling and transit as two integer pairs taken from the stored profile.
- [ ] A country outside every zone returns not shipped with no rate and no currency.
- [ ] The piece page renders both ranges with both ends, and no date appears anywhere on it.
- [ ] A second workshop cannot read or replace the first workshop's profile, and no second profile is created.
- [ ] The packaging note and customs description appear on the piece page and in the maker's packing steps.
- [ ] The five tests from the lesson run in the suite, and the two resolver cases are named in the log.

## Learning log

1. Paste the four shipping answers for your four country codes, each with its status field. Which one proves the zone lookup and which one proves the pause rule?
2. Which numbers on the rate answer came from the profile, and which came from the request? Say where a client supplied rate would be ignored.
3. Pause the profile with a note and show what the piece page renders. Then unpause and show the zones returned unchanged.
4. Which validation refused the inverted range, and what did the form show beside the field? Include the stored profile version before and after.
5. How many profiles exist for the workshop after the refused cross workshop write, and what proves the number did not change?
6. Where on the page could a date appear, and what did you remove or refuse to stop it?

Write the answers with country codes, integer amounts and status fields. A reviewer should be able to change one zone's rate, reload the piece page, and see the new amount with the same two ranges, without any other country changing.

## What this gate does not prove

The gate does not prove a carrier rate. Every amount comes from a number the maker typed, and the course has no carrier integration, no printed label and no live tracking. It does not prove duty or tax calculations either, because the marketplace states that import charges may apply and does not compute them. Those limits belong in the README and in the shipping and lead-time policy page you will write at the end of the course.

It also does not prove that checkout refuses a paused destination, because checkout is built later. What you have proved is the resolver answer and the note, and the checkout module will call the same function. Say that in the log so the evidence is not read as wider than it is.

It does not prove a production range on a real quote for the same reason. Production ranges arrive with quotes and commissions in week four, and they will use the same integer pair rule this profile uses for handling and transit. The next module leaves the maker's back office behind and turns to the buyer: browsing the collection that these pieces, photographs and shipping answers now describe.
