```quiz
type: mcq
question: Why does Ghurza avoid keeping a long-lived access token in localStorage?
options:
  - localStorage only accepts string values
  - Any XSS bug can read JavaScript-accessible storage
  - localStorage is sent automatically with every request
  - Vite deletes localStorage in production builds
correct: 1
explanations:
  - "localStorage does accept strings only, which is a limitation rather than the security reason."
  - "Any script running on the page can read localStorage, so one XSS bug hands over the token."
  - "The browser sends cookies automatically; localStorage is read only by code you wrote."
  - "A production build does not clear storage, so the value stays until code removes it."
```

```quiz
type: mcq
question: What should the API client do after an expired access token causes a 401?
options:
  - Retry forever with the same expired token
  - Refresh once, then retry the request once
  - Treat it as a 403 ownership failure
  - Redirect to login before trying a refresh
correct: 1
explanations:
  - "Retrying with the same expired token repeats the same 401 and hides the real fix."
  - "One refresh followed by one retry recovers the request without looping on failures."
  - "A 401 is about identity rather than ownership, so it should not be reported as a 403."
  - "Refreshing first is cheaper than a redirect, and it keeps the route when it succeeds."
```
