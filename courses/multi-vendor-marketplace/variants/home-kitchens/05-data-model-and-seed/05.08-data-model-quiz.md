```quiz
type: mcq
id: sufra-model-q1
question: Maqluba needs three load units. A 13:00 kitchen window has only two units left, but the dish still appears on the menu. Which record should make checkout fail?
options:
  - The diner's cart, because it owns all available stock
  - The dish's stockQty, because each dish has its own pool
  - The dated window, because it owns shared kitchen units
  - The weekly rule, because it holds today's remaining count
correct: 2
explanations:
  - A cart requests capacity but does not own it.
  - A dish has load and preparation inputs, not a stock counter.
  - The dated window owns the shared counter for that kitchen and interval.
  - A weekly rule generates occurrences but does not hold today's mutable count.
```

```quiz
type: mcq
id: sufra-model-q2
question: The seven-day generator runs twice for the same kitchen and 13:00 UTC start. What combination protects the existing window and its held units?
options:
  - A unique index plus insert-only initial fields
  - A new random start time on each generator retry
  - A dish-level stock counter reset on every run
  - A cart revision stored beside the kitchen name
correct: 0
explanations:
  - The unique pair prevents duplicate occurrences, while insert-only fields preserve an existing counter.
  - Changing the time would create almost-identical promises, not an idempotent retry.
  - Resetting stock or capacity can make held effort available twice.
  - Cart revision protects a diner's reviewed cart, not window generation.
```

```quiz
type: mcq
id: sufra-model-q3
question: A cook changes a dish name and price after a diner pays. What should the historical kitchen order show?
options:
  - The latest dish name and price from the live menu
  - An empty item because the old dish was edited
  - Only a dish ID, so the page can decide later
  - Its saved purchase name and price snapshots
correct: 3
explanations:
  - A live menu edit cannot rewrite the paid promise.
  - Editing a dish does not erase a historical order item.
  - A bare ID cannot explain what the diner bought at that time.
  - The order keeps immutable purchase fields while future offers use the edited dish.
```
