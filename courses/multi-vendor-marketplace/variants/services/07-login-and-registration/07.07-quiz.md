```quiz
type: mcq
question: Why does SkillSlot avoid keeping a long-lived access token in localStorage?
options:
  - localStorage only accepts string values
  - Any XSS bug can read JavaScript-accessible storage
  - localStorage is sent automatically with every request
  - Vite deletes localStorage in production builds
correct: 1
explanations:
  - Storage accepts strings and JSON serialization covers any token shape, so the storage type is not the problem.
  - A script injected into the page can read any JavaScript-accessible storage, so one XSS bug exposes the token.
  - Nothing is attached to a request automatically, since code reads the value and adds the header by hand.
  - Vite leaves localStorage intact in a production build, which is why the exposure survives deployment.
```

```quiz
type: mcq
question: What should the API client do after an expired access token causes a 401?
options:
  - Retry forever with the same expired token
  - Refresh once, then retry the request once
  - Treat it as a 403 ownership failure
  - Redirect to login before trying a refresh
correct: 1
explanations:
  - Retrying with the same expired token repeats the same 401 and never recovers the request.
  - One refresh and one retry recovers the call, and a second 401 means logout instead of another loop.
  - 403 means the identity is known and the ownership check failed, which is a separate branch of the client.
  - Sending the client to the login page first throws away a session that a silent refresh could have saved.
```

```quiz
type: mcq
question: Why does the refresh request use credentials include?
options:
  - So the browser attaches the HttpOnly cookie
  - To expose the refresh token inside React state
  - To bypass CORS checks on every request sent
  - To attach the MongoDB password to the request
correct: 0
explanations:
  - The cookie is invisible to JavaScript, so only the browser can attach it, and only when the request opts in.
  - The refresh value never reaches React state, which is the whole reason it lives in an HttpOnly cookie.
  - The option adds credentials on an allowed origin, and the CORS check still applies in full.
  - The database credential stays on the server and never travels with a browser request.
```
