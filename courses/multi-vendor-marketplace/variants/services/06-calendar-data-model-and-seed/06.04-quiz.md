```quiz
id: model-q1
question: "Two clients both read no overlapping Booking and then insert for one provider. Which record needs a database uniqueness rule?"
options:
  - "A client browser cache entry, refreshed immediately before the Pay button becomes active"
  - "A SlotClaim keyed by provider and UTC block start, with every occupied block claimed"
  - "A weekly AvailabilityRule whose local Monday opening is copied into each client profile"
  - "A Service title, because two bookings should never mention the same service name"
correct: 1
explanations:
  - "A browser cache cannot serialize concurrent writes at the database boundary."
  - "A unique provider/block key makes overlapping claim sets contend on at least one database key."
  - "A weekly rule describes possible hours; it does not give one client exclusive ownership."
  - "A service may be sold repeatedly at distinct times, so its title is not the lock."
```
