```quiz
type: mcq
id: calendar-q1
question: "A provider opens every Monday at 09:00 in Asia/Gaza. What should the repeating AvailabilityRule store?"
options:
  - "One fixed UTC start copied into every future Monday, even after the provider's zone changes offset"
  - "Local weekday and time together with the provider's IANA zone"
  - "The first Berlin client's displayed local time"
  - "A list of paid Booking IDs instead of a time rule"
correct: 1
explanations:
  - "One UTC instant describes one dated occurrence, not a repeating local rule across possible offset changes."
  - "A weekday, local wall time and IANA zone preserve the provider's recurring intention for later dated expansion."
  - "A viewer's time zone changes presentation, not the provider's published hours."
  - "Bookings are durable appointments; they cannot replace the source rule for future offers."
```

```quiz
question: "A 30-minute lesson starts at 09:00 and another starts at 09:15 for the same provider. Which MongoDB design rejects the overlap at the write boundary?"
options:
  - "Read all existing Booking documents for overlaps, then insert if the response is empty for both concurrent clients"
  - "Put both start times in a Provider document array without an index"
  - "Insert scalar SlotClaim documents for every occupied 15-minute UTC block with a unique provider and block index"
  - "Cache the calendar response for a shorter time"
correct: 2
explanations:
  - "Two requests can both read an empty result before either inserts, so the read alone does not stop a race."
  - "An unindexed array in one mutable profile document does not express the provider and block uniqueness rule."
  - "Both intervals require the 09:15 block; the unique compound key lets only one claim for that provider and block succeed."
  - "A fresher cache improves display but does not become an exclusive database claim."
```
