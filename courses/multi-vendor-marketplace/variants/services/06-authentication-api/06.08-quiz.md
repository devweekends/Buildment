```quiz
type: mcq
question: Why is bcrypt appropriate for storing SkillSlot passwords?
options:
  - Its deliberate slowness and salting make guessing costly
  - It encrypts each password so the client can decrypt it
  - It stores the original plaintext password inside the hash
  - It removes the need for HTTPS on the login routes
correct: 0
explanations:
  - A slow, salted hash makes every guess expensive, so a stolen user collection is not cheap to reverse.
  - bcrypt is a one way hash and not encryption, and no client step ever decrypts a stored password.
  - The stored value holds a salt and a derived hash, so no plaintext password survives inside it.
  - The password still crosses the network on the login request, so transport encryption is still required.
```

```quiz
type: mcq
question: What should the access-token payload contain?
options:
  - The user's password plus the full database connection URL
  - Only the user id and role needed for one short request
  - Every field stored directly on the user document
  - The Stripe secret key and the client API base URL
correct: 1
explanations:
  - A payload is readable by anyone holding the token, so a password or a connection string inside it is a leak.
  - The user id names the caller and the role names the surface, which is all one request needs to authorize.
  - Copying the whole document would put the password hash and the OTP fields into a readable string.
  - A signing secret never belongs inside a signed token, and the API base URL is public anyway.
```

```quiz
type: mcq
question: A request has no valid credentials. Which response best fits that failure?
options:
  - 401 Unauthorized because identity is missing
  - 403 Forbidden because ownership was checked
  - 409 Conflict because the email already exists
  - 201 Created because the token can be added later
correct: 0
explanations:
  - The server could not establish who is calling, so it answers 401 and the client may refresh once and retry.
  - 403 says the identity is known and the ownership check refused the action, which is a different branch.
  - 409 describes a duplicate record on registration, not a caller who arrived without a token.
  - 201 is a success code for a created record, and it must never be sent to a caller with no identity.
```
