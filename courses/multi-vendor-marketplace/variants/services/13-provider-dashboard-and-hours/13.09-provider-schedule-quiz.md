```quiz
type: mcq
id: provider-schedule-q1
question: "A provider in Gaza saves Monday 09:00 to 12:00 weekly hours. What belongs in the AvailabilityRule?"
options:
  - "The provider's browser offset and one UTC timestamp reused for every future Monday appointment"
  - "A UTC start copied from the provider's most recent confirmed Booking"
  - "Local weekday and wall times, effective dates and the provider's IANA zone"
  - "The client's current time zone and a 09:00 UTC start for every Monday"
correct: 2
explanations:
  - "A browser offset and one UTC instant cannot represent future local recurrence."
  - "An existing appointment describes one dated commitment, not recurring intention."
  - "The named provider zone and local fields let Module 15 resolve each dated offer."
  - "A client zone formats offers for display; it does not define provider working hours."
```

```quiz
  - "A pure overlap check followed by independent inserts without versioning"
  - "A stale form warning shown after both inserts have already committed"
  - "A shared Provider revision write plus fresh overlap validation in the transaction"

explanations:
  - "One browser cannot serialize writes from another tab or server instance."
  - "Both requests could read the same old rule set before writing."
  - "A warning after conflicting commits does not restore schedule integrity."
  - "The contended Provider write coordinates editors, and the retry rechecks rules."
```
