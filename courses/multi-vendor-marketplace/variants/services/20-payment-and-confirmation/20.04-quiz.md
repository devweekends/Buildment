```quiz
type: mcq
id: payment-q1
question: "A two-provider held checkout has one client payment. Which amount should create its PaymentIntent?"
options:
  - "The amount most recently typed into the browser's hidden subtotal input"
  - "The sum of immutable charged line allocations in one accepted currency"
  - "The current public Service prices reloaded after the provider changes them"
  - "The first provider Order subtotal, with the second provider charged later"
correct: 1
explanations:
  - "A browser amount can be changed or stale and is not charge authority."
  - "The accepted snapshots sum to the one amount the client agreed to pay."
  - "Later Service edits cannot rewrite an already held purchase."
  - "Separate charges would violate this module's one-payment checkout contract."
```

```quiz
type: mcq
id: payment-q3
question: "A signed success webhook is delivered twice. What should the second delivery do?"
options:
  - "Acknowledge the known event without repeating confirmation or notification"
  - "Create a second PaymentIntent with the same amount to make the duplicated event harmless"
  - "Delete and recreate all SlotClaims so their state is fresh"
  - "Extend the original hold deadline by another ten minutes"
correct: 0
explanations:
  - "Event identity and conditional state transitions make duplicate delivery safe."
  - "A webhook is not a request to create another payment."
  - "Recreating claims risks a collision and changes ownership unnecessarily."
  - "Payment success confirms a Booking; it does not extend a hold."
```
