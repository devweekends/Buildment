# Prerequisites and entry diagnostic

This course assumes JavaScript functions and promises, an HTTP request and response, one small CRUD application, Git commits and basic command-line navigation. You do not need to know Stripe, Cloudinary or licensing terminology in advance. The entry check is a quick way to find a missing foundation before a long build. Do it without looking up a finished solution. Save your answers in `docs/learning-log.md`, then use the repair links or exercises for any missed skill.

## Task 1: Read a route

Consider an Express GET route that takes `productId` from the URL, fetches one Product, and returns JSON. Write two changes you would make before using it for a private ProductFile: one about authentication and one about Studio ownership. An answer such as "add security" is too broad. Name the authenticated ID and the stored relationship the query would compare. You may write pseudocode. The point is to show that a URL ID names a resource but does not grant access to it.

If you cannot identify where `req.params` and the authenticated session value come from, review a basic Express routing exercise and rerun this task. Midad later uses the same route pattern for Products, files and Licenses. The exact syntax is less important today than knowing which value the client controls and which value the server must derive from authentication.

## Task 2: Query a relationship

Write a Mongoose query sketch that finds Products belonging to one Studio ID, sorted by newest first. Then write a second query sketch for Licenses belonging to one Buyer ID. Explain why using Product ID alone cannot list a buyer's purchased rights. This checks basic filtering and the idea that current catalogue ownership and buyer entitlement are separate relationships. It is fine to use method names from memory if the filter and sort are clear.

If this task is difficult, revisit a small MongoDB CRUD example and practice `find({ studioId })` and `sort({ createdAt: -1 })` in a disposable collection. Do not start Module 5 by copying a full schema from the course; first make sure you can read a filtered query. A ten-minute repair here is cheaper than debugging a cross-buyer leak in the library later.

## Task 3: Explain a Git checkpoint

Suppose you have added a ProductFile schema, but the upload route is unfinished when power fails. Describe one small commit you could make before stopping and how you would resume. Include one command to inspect changed files and one command to save a local commit. You do not need network access to commit locally. The answer should show that a half-built feature can be left in a named, recoverable state rather than as unexplained uncommitted edits.

If Git is unfamiliar, create a tiny practice repository, edit one Markdown file, run status, add the file and commit it. Then change the file again and inspect the diff. Keep this exercise outside the course project if you are worried about clutter. The working-rhythm chapter will show how to make this habit useful during a long module sequence.

## Task 4: Calculate a sale in minor units

A personal license costs 1,200 minor units and a template license costs 2,500 minor units in the same currency. State the total as an integer and explain which system should calculate it at checkout. Now imagine the browser submits a total of 1. The server should load current option prices and reject or correct the mismatch before creating payment. This task checks arithmetic and trust boundary, not Stripe API knowledge.

If you added decimal display prices directly with floating point, try the calculation again with integer minor units and format the display amount only at the UI edge. Write down the currency as well as the number. A total without a currency is incomplete. Later Checkout and OrderLine records use this habit to compare what the buyer accepted with the provider event.

## Decide your path

A confident core-path answer names the server-held actor in Task 1, filters by owner or buyer ID in Task 2, uses a recoverable local commit in Task 3, and calculates 3,700 minor units from server prices in Task 4. If two or more answers are missing, complete the relevant repair exercise before Module 2. If one is uncertain, do that repair alongside the next module and ask an instructor to review your explanation. Keep the original attempt and the repaired answer in the learning log so progress is visible.

The diagnostic is not a grade or a barrier to the course. It directs your time. A learner who already knows the basics can move on; a learner who needs one repair can do it now instead of meeting the same gap under payment and private-file complexity. Share your route and query sketches with a peer and ask whether the resource ownership is clear. The next chapter gives a working rhythm for turning these small checks into steady project progress.
