```quiz
type: mcq
question: Why is bcrypt appropriate for storing Hamesh passwords?
options:
  - Its deliberate slowness and salting make guessing costly
  - It encrypts each password so the client can decrypt it
  - It stores the original plaintext password inside the hash
  - It removes the need for HTTPS on the login routes
correct: 0
explanations:
  - Each guess costs real time and a unique salt defeats precomputed tables, so an offline attack on a stolen dump stays slow.
  - A bcrypt hash cannot be decrypted, and the client never needs the original password back.
  - Only the derived digest and its salt are stored, and the plaintext is discarded once hashing finishes.
  - The password still crosses the network on every login, so TLS remains mandatory.
```

```quiz
type: mcq
question: What should the access-token payload contain?
options:
  - The user's password plus the full database connection URL
  - Only the user id and role needed for one short request
  - Every field stored directly on the user document
  - The Stripe secret key and the client API base URL
correct: 1
explanations:
  - The payload is readable by anyone holding the token, so a password or a connection string in it is a leak.
  - A minimal payload carries the identity and role the middleware checks and nothing that ages badly.
  - Copying the whole document exposes fields the API never reads and leaves the token stale as the document changes.
  - Server secrets belong in the process environment, and the client base URL is already public in the build.
```

```quiz
type: mcq
question: A request has no valid credentials. Which response best fits that failure?
options:
  - 401 Unauthorized because identity is missing
  - 403 Forbidden because ownership was checked
  - 409 Conflict because the email already exists
  - 201 Created because the token can be added later
correct: 0
explanations:
  - Nothing established who is calling, so the request is refused as unauthenticated and the client knows to sign in.
  - 403 says the caller is known and the resource is not theirs, which needs a verified identity first.
  - 409 describes a state conflict on a write, not a request that arrived with no credentials at all.
  - 201 reports a successful creation, which cannot be the answer to a request that was refused.
```
