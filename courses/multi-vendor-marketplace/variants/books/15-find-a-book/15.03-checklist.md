# Find-a-book gate

This gate is a student test, not a component checklist. Seed one edition with copies in three grades at three shops, open the storefront at 360 pixels, and ask a partner who has not seen your code to decide which copy they would buy and why. If they cannot name the grade, the shop, the price and the pickup condition from the page, the page is not finished, however clean the JSON looks.

Do the seed work first and write down the expected page before you open the browser. For example: three grade sections, five rows, the cheapest copy at Good rank 2 from Corner Books, one Acceptable copy excluded by the default floor, and one shop with a pickup note about a Friday closing time. Writing the expectation first is what turns a screenshot into evidence, because you can be wrong in a specific way instead of approving whatever renders.

## Read the grade without colour

Turn the screen to greyscale, either through the operating system setting or a browser emulation, and read every grade on the card, the edition page and the copy detail. Each one must still say what it is and where it sits on the scale. Then open the page with a screen reader and listen to one badge: the announcement should contain the label and the rank, not a colour name and not an empty element.

Zoom to 200 percent and repeat the first check. The badge should wrap rather than clip, and the rank must not be the part that disappears. A badge that shows "Good" and hides "rank 2 of 5" in a hidden span for small screens fails this gate, because the visible page has lost the scale.

## Read the page at 360 pixels

Set the viewport to 360 by 640 and load the edition page with the copies seeded above. There must be no horizontal scrolling, no text under 14 pixels, and no control that needs a hover to reveal information. Tap targets for the rows and any filter control should be at least about 44 pixels tall, which usually means padding rather than taller text.

Then check the network panel with throttling on and record the transferred size of the first screen. A page that fetches every full size condition photograph before the student scrolls is the failure this gate is looking for. Note the number in your learning log, along with the device emulation you used, so a mentor can repeat the measurement rather than trust a memory.

Finally, open the page with a long seeded shop name and a long defect note. Both must wrap or clamp without pushing the row wider than the screen. The usual cause is a fixed width price column plus a fixed width image plus padding, and the fix is a layout that lets the text column shrink.

## Compare copies across shops

Ask your partner to answer four questions from the page alone: which edition is this, which shops have a copy, what grade and price is each copy, and can they collect it before a given day. If they have to open a second shop page to compare, the grouping has failed the purpose it exists for.

Then change one shop's price in the database and reload. Only that row should change, and the section order should be unchanged unless a grade section became empty. A grouped list that re-sorts everything when one price changes makes comparison harder, because the row a student was looking at moves while they read.

Test the empty states with a query rather than by deleting seed data. An edition with copies only below the chosen floor should say so and offer to widen the floor. An edition whose copies are all archived should say that no copies are listed right now and not show a broken page. A search with no matches should keep the typed query on screen so the student can correct it.

## Follow one copy to its detail

Open the cheapest Good copy and read it as a buyer. The photographs must be of this copy, with alt text that describes this copy. The defect notes must be the shop's own words and must not be summarised into something friendlier. The pickup note must be present and specific, and the price must match the row you came from.

Then inspect the raw response for that copy. It must not contain the shop's private fields, another student's hold details, or a second shop's notes. Search the JSON for a field name you know is private and confirm it is absent rather than merely unrendered.

Change the copy's status to sold in the database, reload the detail page, and confirm it renders as sold with its facts intact and no path to purchase. A 404 here is a lesser failure than a page that still offers to add a sold book, but it is still a failure, because a student who followed a link should be told what happened.

## Keep the money on the server

Check that the price shown on the card, the row and the detail all come from the API response rather than from a client side calculation. Change a seeded price in the database and reload each screen; all three should move together. Then search the client code for a multiplication or a sum over prices. A storefront that recomputes a total in the browser is already preparing the bug that module 27 will be about.

The same rule applies to the offer summary. The lowest price, the best grade and the shop count must come from module 14's aggregation. If the client re-derives any of them from a copy list it fetched for a different purpose, the card and the edition page will eventually disagree, and there is no way to tell which one is right.

## Gate checklist

- [ ] The seeded edition has copies in at least three grades from at least three shops, and the expected page was written down before the browser was opened.
- [ ] Every grade badge shows the label and the rank as text, and still reads correctly in greyscale.
- [ ] A screen reader announces one badge as a condition and a rank, not as a colour.
- [ ] The edition page has no horizontal scroll at 360 by 640, and no information is reachable only by hover.
- [ ] Tap targets on rows and filters are at least about 44 pixels tall.
- [ ] The first screen stays within the size budget you recorded, with images throttled.
- [ ] Copies are grouped by grade with the highest rank first, and sorted by price then shop inside each group.
- [ ] A long shop name and a long defect note wrap without widening the row.
- [ ] A partner can name the edition, the shops, the grade and price per copy, and the pickup condition, from the page alone.
- [ ] Changing one shop's price moves one row and leaves the section order stable.
- [ ] The three empty states, no copies, none above the floor and no search matches, each show a specific message and a next action.
- [ ] The copy detail shows this copy's photographs with descriptive alt text, the shop's defect words and the pickup note.
- [ ] The copy detail response leaves out private shop fields and other students' hold details, checked in the raw JSON.
- [ ] A sold copy renders as sold with its facts and no purchase path.
- [ ] Card, row and detail prices all come from the API, and no client code recomputes a price or an offer summary.
- [ ] The grouping function has a unit test that covers one grade, several grades and an empty list.

## Learning log

1. Which seeded edition did you use, how many copies did it have, and what did you predict the page would show before you opened it? Note one thing you predicted wrongly.
2. How does your badge announce itself to a screen reader? Quote the exact string, and say what you changed to make the rank part of it.
3. What was the transferred size of the first screen at 360 pixels with throttling on, and which change moved it most?
4. Which four questions did your partner answer from the page, and which one did they need a second tap to answer? What did you change as a result?
5. What does the copy detail response contain for a sold copy, and why is that better than a 404 for a student who followed a stale link?
6. Which fields did you search for and not find in the raw copy response, and which server projection is responsible for leaving them out?

A passing gate leaves five artefacts: the seed description with expected output, the badge test that asserts the accessible name, the 360 pixel layout test, the recorded first screen size, and the notes from your partner's read of one copy. A screenshot at desktop width proves none of them.

Commit the badge, the card, the search box, the edition page, the copy detail and the three tests together, with a short message that names the gate. Do not enable module 16 work on top of an unfinished storefront: the cart rechecks copy state for rows this page renders, and a page that lies about a grade makes the cart's rejection look like a cart bug.
