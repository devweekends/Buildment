```quiz
type: mcq
question: Which file is safe to commit for teammates who need to configure the Hamesh server?
options:
  - server/.env with working credentials for each teammate
  - server/.env.example with variable names and placeholders
  - A full export of the production secret manager values
  - A log line that prints the full MongoDB connection string
correct: 1
explanations:
  - A committed .env hands every teammate a working database password and keeps it in version history for good.
  - Names plus placeholders tell a teammate which variables to supply without shipping a usable credential.
  - An export of production values copies every live secret into git, and rotating them later cannot undo the copy.
  - A printed URI usually embeds the password, so it leaks into terminal scrollback and into whatever stores the logs.
```

```quiz
type: mcq
question: Why should the server connect to MongoDB before it starts listening for HTTP requests?
options:
  - It stops routes accepting work the database cannot serve
  - It makes every MongoDB query run inside the browser tab
  - It removes the need for any error handling after startup
  - It automatically seeds the production data on every boot
correct: 0
explanations:
  - A student request for an Edition should never reach a route whose database connection is still being negotiated.
  - Queries run inside the Node process, so the browser tab never talks to MongoDB at all.
  - Queries still fail after startup, and a connection that drops later still needs handling.
  - Seeding is a script you run deliberately, never a side effect of booting the API.
```

```quiz
type: mcq
question: Which value must stay in server-side configuration rather than a Vite client environment variable?
options:
  - The public app name shown in the browser tab
  - The public API base URL used by the client
  - The MongoDB URI that carries credentials
  - A UI feature label defined in the config
correct: 2
explanations:
  - The app name is public text, so putting it in a client variable reveals nothing.
  - The API base URL has to reach the browser by design, so it is public information.
  - The URI contains the database user and password, which belong to the server process only.
  - A feature label is display text that no deployment secret depends on.
```
