```quiz
type: mcq
question: Why does Hamesh avoid keeping a long-lived access token in localStorage?
options:
  - localStorage only accepts string values
  - Any XSS bug can read JavaScript-accessible storage
  - localStorage is sent automatically with every request
  - Vite deletes localStorage in production builds
correct: 1
explanations:
  - Strings and JSON serialization cover any token shape, so the storage type is not the objection.
  - A script injected into the page reads JavaScript-accessible storage directly, so one XSS bug hands over the token.
  - localStorage is never attached to a request by the browser, and only your own code adds the header.
  - Vite keeps localStorage intact in a production build, which is exactly why the exposure survives deployment.
```

```quiz
type: mcq
question: What should the API client do after an expired access token causes a 401?
options:
  - Retry forever with the same expired token
  - Refresh once, then retry the request once
  - Treat it as a 403 ownership failure
  - Redirect to login before trying a refresh
correct: 1
explanations:
  - Retrying the same expired token reproduces the same 401 and never makes progress.
  - One refresh followed by one retry recovers the call, and a second 401 ends the session instead of looping.
  - 403 means the identity is known and the resource is not theirs, which is a separate branch of the client.
  - Redirecting before the refresh throws away a session the refresh cookie could still restore.
```

```quiz
type: mcq
question: Why does the refresh request use credentials include?
options:
  - So the browser attaches the HttpOnly cookie
  - To expose the refresh token inside React state
  - To bypass CORS checks on every request sent
  - To attach the MongoDB password to the request
correct: 0
explanations:
  - credentials include tells the browser to attach the HttpOnly refresh cookie on the call to the API origin.
  - The cookie stays unreadable to JavaScript, and reading the refresh value in React is what the design prevents.
  - CORS is negotiated by response headers from the server, and this fetch option plays no part in it.
  - The MongoDB password never leaves the API process and never reaches a browser.
```
