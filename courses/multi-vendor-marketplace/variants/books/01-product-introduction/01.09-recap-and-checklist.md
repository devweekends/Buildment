# Recap and checklist

Explain Hamesh in two sentences: a student needs a specific accepted Edition and compares separate physical Listings from local Shops; when no eligible copy exists, a standing want can alert them after a new Listing appears. Do not reduce the promise to title search. A high-grade copy of the wrong Edition can be unusable for a course, and a cheap copy below the student's grade floor may be unacceptable. The final product must show both identity and copy condition.

## Check the actor and record map

Point to Work, Edition, Listing and ReadingListItem on your diagram. Say which record has an ISBN, which Shop owns a physical copy, and which student owns the private requirement. Then point to an OrderLine snapshot and explain why a Shop repricing a current Listing does not change a past receipt. If a peer thinks the first Shop to type an ISBN owns the Edition, redraw the ownership and reference arrows before writing models.

Review scope. A condition grade helps filter, but it does not certify an unseen copy as perfect or prove an edition matches a syllabus. The Shop must disclose material defects with notes and photos. The app will use test-mode payments, fictional Shops and publisher-verified bibliographic identifiers. It will not import real student course lists, copy textbook content or run real Shop payouts. These boundaries make the first demo truthful.

## Check the entry path

Look at the four diagnostic answers: owner-scoped route, exact Edition and grade/price query, local Git checkpoint, and ISBN-13 check calculation. If two or more are missing, complete the named repair before Module 2. If one is weak, write the practice command you will run alongside the skeleton. Keep the original answer and corrected one. The diagnostic is useful only if it changes the next action.

Open `docs/learning-log.md` and show a recovery line: last passing command, current question and next file. A local commit can save this introduction work without network access. Make sure no real buyer details, provider credentials or copied book pages entered the repo. The first seed should remain fictional and small enough to recreate after an interrupted session.

## Learning log

1. A Shop has two copies of one print ISBN. Which records are shared, which are Shop-owned, and which one enters the Cart?
2. A student accepts Good or better for an exact Edition. Why do a cheap Acceptable copy and a Like New copy of an older Edition both fail?
3. Two Shops type the same valid ISBN concurrently. What database rule prevents two Edition rows, and what should the losing request do?
4. Which entry skill needs repair, and what exact exercise or test will show that you repaired it?

The gate passes when your two-sentence product explanation, actor matrix, vocabulary diagram, diagnostic answer and Week 1 plan agree. A mentor should know which relationships you intend to build and which failures later gates must test. This introductory gate does not claim checkout or alerts already work. Module 2 begins with a running client and server, and Module 5 turns the vocabulary into models and a repeatable seed.

## Try a two-minute defense

Ask another learner to be the examiner. Give them one exact ISBN and three Listings under it. They may ask why the Edition is not owned by the first Shop, why a Good copy can cost more than a Very Good one, and why a sold Listing does not remove the Edition. Answer with the ERD and concrete records, not broad marketplace slogans. If you cannot explain the grade and price as separate seller facts, revise the introductory diagram before Module 5 builds it.

Then switch roles. Ask them to show the wrong-Shop edit and wrong-student list read that the API must deny. They do not need working routes yet, but they should name the stored relationship each route will check. This exercise exposes a missing arrow early, when changing the diagram is cheap. It also prepares you for the later capstone viva, where the same questions will be backed by real test output.

## Save a recoverable start

Commit the intro's product statement, diagnostic answers, source-verified ISBN note, actor matrix and Week 1 plan. In the learning log, write one line naming the last passing exercise and the first Module 2 file to open. If power or internet stops now, you can resume without guessing what was decided. Keep the repository free of real student data and textbook scans; the first seed will use fictional accounts and bibliographic identifiers, not copyrighted content.

The checklist is satisfied when a peer can distinguish Work, Edition and Listing, can identify the private owner of a ReadingList, and can say what a condition grade leaves uncertain. Later chapters will test the claims with code. Do not report this introductory evidence as a completed search, payment or alert feature; it is the product contract those features must fulfill.

If the examiner asks for a physical example, point to one fictional Listing and name its condition notes and Shop. If they ask for a catalogue example, point to the Edition ISBN and related Work. If they ask what the student bought, point to the OrderLine snapshot. These answers use different records for different claims and give the next module a clear model to implement.
