```quiz
type: mcq
question: "Zaid's three ovens send a temperature every minute, with the oven letter as the key, into a topic with 3 partitions. Oven A goes to partition 0, B to partition 1 and C to partition 2. They are sent in this order: A 180, B 200, A 190, C 170, B 210. Which statement is guaranteed for a reader?"
options:
  - "Oven A's 180 is read before oven C's 170, because it was sent first"
  - "Oven B's 200 is read before oven B's 210, because they share a partition"
  - "All five readings are read in the order they were sent, from A 180 to B 210"
  - "Oven C's 170 is read before A's 190, because its offset is 0 and A's is 1"
correct: 1
explanations:
  - "A and C are in different partitions. Order holds only inside one partition, so nothing says which of the two a reader sees first."
  - "Right. Both of B's readings have key B, so they go to partition 1 and keep the order in which they were added. A reader sees 200 and then 210. The other pairs sit in different partitions and carry no promise."
  - "A topic does not keep one order across partitions. Only the readings of one oven are certain to stay in order."
  - "Offsets are numbered inside each partition, so offset 0 in partition 2 and offset 1 in partition 0 cannot be compared. They say nothing about which reading comes first."
```

```quiz
type: mcq
question: "Saeed's consumer reads one partition in batches of 5 events and saves its position after each batch. It wrote offsets 0 to 4 and saved position 5. It then wrote offsets 5, 6 and 7 and crashed before the next save. The table has no key. After the restart, the consumer finishes offsets 5 to 9. How many duplicate rows does the table hold?"
options:
  - "None, because the saved position of 5 shows that offsets 0 to 4 are safe"
  - "Five, because the whole second batch of five events is written again"
  - "Eight, because every offset from 0 to 7 is read again after the crash"
  - "Three, because offsets 5, 6 and 7 were written before the crash and again"
correct: 3
explanations:
  - "Offsets 0 to 4 are safe, but offsets 5, 6 and 7 were written before the crash and the position was never saved. They are read and written a second time."
  - "The whole batch is read again, but offsets 8 and 9 had not been written before the crash. Only the three that were written twice are duplicates."
  - "The restart begins at the saved position, 5. Offsets 0 to 4 are not read again, so they are not duplicated."
  - "Right. The restart begins at the saved position, 5, and reads offsets 5 to 9. Offsets 5, 6 and 7 were already written, so they appear twice. Offsets 8 and 9 appear once."
```

```quiz
type: mcq
question: "Ammar asks an AI chat tool how to receive sensor events from a Kafka topic into his database. It answers: 'Use the exactly-once setting. Exactly-once is guaranteed from the producer all the way into your database, so your table does not need a key.' What is wrong with this answer?"
options:
  - "Exactly-once covers work between Kafka topics, so the table still needs a key"
  - "Kafka cannot repeat a message, so a database never sees one event twice"
  - "Exactly-once only works when the table has no primary key, so the key must go"
  - "The answer is right, but it should also add DISTINCT to every report on it"
correct: 0
explanations:
  - "Right. Kafka's exactly-once covers reading from Kafka and writing back to Kafka with transactions. For a database or a file, the result is only as exact as that system's design, so the table needs a key that makes a repeat safe."
  - "At least once is the default, so a message can be delivered again after a crash. A table can see the same event twice."
  - "A key does not stop exactly-once. A key on the table is how a repeat is made safe, and it works whatever the setting is."
  - "The answer is wrong, not right, and DISTINCT only hides doubled rows in one report. The table itself would still hold the repeats."
```

```quiz
type: mcq
question: "Dalia's driver plans the water round once a day at 05:00 from the tank levels. 40 sensors each send a level every 10 minutes, so 5,760 readings a day, and a gateway stores them in files. Dalia's laptop is on only from 04:00 to 06:00 because of power cuts. Which design fits?"
options:
  - "A streaming service that runs all day and shows every tank level live"
  - "A batch every 15 minutes through the day, with a page for each tank"
  - "One batch at 04:30 that reads the overnight files and writes the list"
  - "A cluster of 4 machines, because 40 sensors send a lot of readings"
correct: 2
explanations:
  - "The driver needs the data once a day, and the laptop is on for two hours. A service that must run all day does not fit a computer that is off for 22 hours."
  - "A batch every 15 minutes needs the laptop on all day. It is off outside 04:00 to 06:00, and the driver reads the list only once, at 05:00."
  - "Right. The need is a list at 05:00. The files wait overnight, and one batch at 04:30 reads them while the laptop is on, in well under a second for 5,760 readings."
  - "5,760 readings a day is a very small amount of data. One machine reads it in well under a second, so a cluster adds cost and solves nothing."
```

```quiz
question: "A team's job on a 64-core cluster takes 120 seconds. A colleague runs a simple one-thread script on a laptop, on the same data, and gets the same answer in 90 seconds. What does the COST idea from the paper say?"
options:
  - "The cluster wins, because 64 cores is more than the laptop's one thread"
  - "The cluster has not beaten one thread, so its COST is above 64 cores"
  - "The laptop script is not a fair test, because laptops are not for production"
  - "Any job that takes under 100 seconds on one thread needs no cluster"
correct: 1
explanations:
  - "More cores do not mean a faster result. The cluster took 120 seconds and the single thread took 90, so the single thread is ahead."
  - "Right. COST is the configuration that outperforms a single thread. This cluster takes longer than one thread, so it has not yet justified its cost at 64 cores. It needs more cores, or a different design, to beat the baseline."
  - "The idea of COST is to compare a system with a simple baseline on the same data and the same answer. The baseline is the fair test, wherever it runs."
  - "The paper gives no such threshold, and neither does any source we use. The decision comes from measuring your own job and deadline."
```
