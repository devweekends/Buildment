```quiz
type: mcq
question: "Ibrahim's pharmacy chain sends a stock file every night. It arrives at 03:00 with the same columns as always. The last 7 nights brought 410, 405, 415, 400, 412, 408 and 409 rows (average 408.4). Tonight only 205 rows arrived, because one branch's till was off. His volume check uses a tolerance of 60%, so the alarm line is 163 rows. What do the facts support?"
options:
  - "The check alarms, because 205 is below the average of 408"
  - "The check passes, because 205 is above the line of 163 rows"
  - "The check passes, because the file arrived on time at 03:00"
  - "The check alarms, because a short file means the schema changed"
correct: 1
explanations:
  - "An alarm needs a value below the line, which is 163. Being below the average is not enough, because the tolerance allows for ordinary dips."
  - "Right. 205 is above 163, so the check passes even though half the rows are missing. A tolerance of 60% is too loose for this series: 25% would give a line of about 306 and catch it."
  - "Arrival time belongs to the freshness check. A file can be on time and still half empty, and the volume check does not look at the clock."
  - "The columns are the same as always, so the schema check passes. A short file is a volume problem, not a schema change."
```

```quiz
type: mcq
question: "Hatem asks an AI tool how to share volunteer data safely. It answers: 'Replace each phone number with its SHA-256 hash. A hash cannot be reversed, so the data becomes anonymous and you can share it freely.' Each phone number is a known prefix plus 7 unknown digits. What is the mistake?"
options:
  - "SHA-256 is outdated, so a hash such as MD5 would be safer"
  - "The answer is right, because a one-way hash cannot be run backwards"
  - "A hash is safe only if the key is stored in the same file as the data"
  - "Only 7 digits are unknown, so each hash can be found by trying them all"
correct: 3
explanations:
  - "MD5 is older and weaker than SHA-256, and the UK regulator advises against MD5 and SHA-1. The weakness here is not the algorithm."
  - "The function is one-way, but the attacker never runs it backwards. They hash every possible number and compare. With 7 unknown digits that is 10 million guesses, about 11 seconds at the test rate."
  - "A key stored in the same file protects nothing, because whoever takes the data takes the key. A key helps only when it is kept apart. The answer also did not mention a key."
  - "Right. 10,000,000 hashes take about 11.3 seconds at the test rate, so the hashes can be reversed. The data is pseudonymised at best, which means it is still personal data."
```

```quiz
type: mcq
question: "Hala's retention job deletes restricted partitions after 30 days. A colleague says quarantine can stay for a year, because it holds only bad rows. The quarantine files are full raw rows: they include volunteer_name and volunteer_phone, kept so that the rows can be fixed. What do the facts support?"
options:
  - "Quarantine keeps the same period as restricted: it holds names and phones"
  - "Quarantine can stay a year, because bad rows are of no use to anyone"
  - "Quarantine can stay once the price is fixed, because fixed rows are clean"
  - "Quarantine should go at once, because bad rows can never be corrected"
correct: 0
explanations:
  - "Right. Quarantine rows are full raw rows, so they hold the same names and phones as the restricted zone and need the same retention period."
  - "The stated facts say the rows include names and phones, so someone who reads them can use them, and they are a risk. A year is much longer than the 30 days for restricted data."
  - "Fixing the price does not remove the name and phone from the row. The personal columns stay until the file is deleted."
  - "Rows wait in quarantine so that they can be fixed and loaded again, so deleting at once would lose that. The rule is a period, the same as for restricted data."
```

```quiz
type: mcq
question: "Mais compares two plans for the average price on a lake partitioned by upload_date, with 28 daily folders. Plan 1 shows: Projections: price; File Filters: upload_date = '2026-03-05'; Scanning Files: 1/28. Plan 2 shows: Projections: price; Filters: market_code = 'M05'; and no Scanning Files line. What do the facts support?"
options:
  - "Plan 2 opens fewer files, because it filters on market_code"
  - "Plan 1 reads only the price column, but plan 2 reads every column"
  - "Plan 1 opens 1 of 28 files, as it filters on the partition column"
  - "Both plans open only one file, since both show a filter line"
correct: 2
explanations:
  - "market_code is not the partition column, and plan 2 has no Scanning Files line, so the files are not reduced by name."
  - "Both plans show Projections: price, so both read only the price column."
  - "Right. The file filter on upload_date and Scanning Files: 1/28 show that the engine opens one folder's file out of 28. That is partition pruning."
  - "Only a filter on the partition column shows Scanning Files: 1/28. A plain Filters line works on rows, not on which files are opened."
```

```quiz
type: mcq
question: "A pull request in Ibrahim's team changes the default keep_days of the retention job from 30 to 90. CI is green. The test of the default lands 16 days of data and expects that nothing is deleted. What do the facts support?"
options:
  - "Nothing is wrong, because every test in CI passed"
  - "The test cannot tell 30 from 90: 16 days delete nothing either way"
  - "CI is broken, because a green run should fail on a changed default"
  - "The sample is too small, so CI needs all of the production data"
correct: 1
explanations:
  - "Green means the written tests pass. No test pins the default, so a changed policy slips through."
  - "Right. With 16 days of data, both 30 and 90 delete nothing, so the test passes either way. A test with more than 30 days of data, which expects the oldest day to go, would pin the default."
  - "CI ran what it was told to run, and nothing failed. The gap is a missing test, not a broken run."
  - "The size of the sample is not the problem. Production data would also hold personal data, which should not go into CI. The missing piece is a test."
```
