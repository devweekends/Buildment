```quiz
type: mcq
question: "In a SQL round, Yahya is given three doctors (Amal, Basil, Chadi) and three appointments: Amal done, Amal cancelled, Basil done. Chadi has none. Her query left joins appointments to doctors on doctor_id, keeps only the rows where the appointment status is done, and counts rows per doctor name with count(*). What does it return?"
options:
  - "Amal 1, Basil 1, Chadi 0, because a left join keeps every doctor"
  - "Amal 1 and Basil 1 only, because the filter removes Chadi's empty row"
  - "Amal 2, Basil 1, Chadi 1, because count(*) counts every row of the join"
  - "Amal 1, Basil 1, Chadi 1, because count(*) counts his empty row"
correct: 1
explanations:
  - "A left join does keep Chadi, but the filter on status runs after the join. Chadi's status is NULL, so his row fails the filter and is removed. To keep him, the condition must sit in the join and the query must count a column of appointments."
  - "Right. After the join, Chadi has one row with a NULL status. The filter keeps only rows where the status is done, so that row goes, and the left join behaves like an inner join. Amal and Basil have one done appointment each."
  - "The filter removes Amal's cancelled appointment and Chadi's empty row, so Amal counts 1 and Chadi does not appear."
  - "The filter removes Chadi's row, so there is no empty row left to count."
```

```quiz
type: mcq
question: "Hatem's practice query lists doctors who have no appointments. It selects the doctors whose doctor_id is NOT IN the doctor_id column of appointments. The doctors are Amal (D1), Basil (D2) and Chadi (D3). The appointments table has three rows, with doctor_id D1, D2 and NULL, because one booking was saved without a doctor. What does it return?"
options:
  - "Chadi, who is the only doctor with no appointments at all"
  - "Amal and Basil, who are the doctors with appointments"
  - "All three doctors, because a NULL in the list matches none of the doctors"
  - "No rows, because the NULL makes the test unknown for every doctor"
correct: 3
explanations:
  - "This is what the query is meant to return. But with a NULL in the list, NOT IN cannot say that D3 is absent, so it is not what the database returns."
  - "NOT IN would never return doctors who are in the list, so Amal and Basil cannot appear."
  - "NULL does not match a doctor, but it does not make every doctor qualify either. A comparison with NULL is unknown, not true."
  - "Right. The list holds D1, D2 and NULL. For D3, the test D3 is not equal to D1, D2 or NULL is unknown at the NULL, so the row is not kept. A left join with a test for NULL, or NOT EXISTS, returns Chadi."
```

```quiz
type: mcq
question: "Rasha models a pharmacy. The product dimension has one row per product, with a supplier name. In June, product P12 changes supplier from Supplier A to Supplier B. Reports for May must still show Supplier A, and reports for June must show Supplier B. The fact table has one row per sale. Which change to the dimension fits?"
options:
  - "Overwrite the supplier name, so May sales then show Supplier B"
  - "Add a second row for P12 with valid dates, and join sales by date"
  - "Add a column for the previous supplier, which keeps only one past value"
  - "Delete the old row for P12, so no sale points at the old supplier"
correct: 1
explanations:
  - "An overwrite makes every May sale of P12 show Supplier B, which breaks the rule that May must show Supplier A."
  - "Right. A second row with valid dates keeps both versions. Each sale joins to the version valid on its date, so May shows Supplier A and June shows Supplier B, and a later change adds a third row."
  - "A column for the previous supplier keeps only one past value, so a second change would lose Supplier A. It also needs date logic in every report."
  - "Deleting the old row removes Supplier A, so May sales would point at a missing row or at the wrong supplier."
```

```quiz
type: mcq
question: "Khalil owns a bakery and wants sales by branch on a screen in the kitchen, updated within a minute. Each till sends a sale as it happens. There are 3 branches with about 400 sales a day each, and the team is one person. Which design does the stated need support?"
options:
  - "A small job that runs every minute and reads the new sales"
  - "A nightly batch that rebuilds the whole screen after closing"
  - "A hosted streaming platform with a cluster to process every sale"
  - "An hourly micro-batch that refreshes the screen at the top of the hour"
correct: 0
explanations:
  - "Right. A job every minute meets the need of a minute, and about 1,200 sales a day is small enough for one person to run. A streaming platform would add cost and skills that these facts do not ask for."
  - "A nightly batch cannot update the screen within a minute, which is the stated need."
  - "A streaming platform could meet the need, but the facts are 1,200 sales a day and one person. The cost and the skills do not match, and a small job meets the need."
  - "An hourly refresh can be up to an hour old, so it fails the need for updates within a minute."
```

```quiz
type: mcq
question: "Mais's clinic pipeline gets bookings that arrive up to 2 days late, about 6 percent of them. She re-reads the last 3 days on every run, instead of only today. Which sentence best states the trade-off in her project story?"
options:
  - "I chose a three-day lookback because it is simply the best way to handle late data"
  - "Late data is a hard problem, and every pipeline has to handle it somehow"
  - "A three-day lookback reads 3 days, not 1, to catch the 6 percent that arrive late"
  - "I used a lookback because it was taught in the course I followed"
correct: 2
explanations:
  - "It claims a lookback is the best way, with no cost and no alternative. A trade-off names what you pay and what you rejected."
  - "This is true of every pipeline, so it says nothing about Mais's choice. A trade-off is specific to the decision."
  - "Right. It states the choice, the cost (3 days read instead of 1) and the reason (6 percent arrive late, up to 2 days), so an interviewer can ask about each part."
  - "Where an idea came from is not a reason. An interviewer wants the cost and the benefit for this pipeline."
```
