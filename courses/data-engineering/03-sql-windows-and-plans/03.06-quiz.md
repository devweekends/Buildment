```quiz
type: mcq
question: "Anas runs the stock sheet of a pharmacy with 6 shelves. It has 4 lines (item, counted at, boxes): paracetamol 08:00 40; paracetamol 16:00 32; ibuprofen 08:00 25; ibuprofen 08:00 25, the same count typed twice. He keeps the rows where RANK() OVER (PARTITION BY item ORDER BY counted_at DESC) = 1. Which result do the facts support?"
options:
  - "2 rows, one for each item, because RANK works like ROW_NUMBER"
  - "4 rows, because RANK removes nothing from the sheet"
  - "3 rows, because the two ibuprofen lines tie at rank 1"
  - "1 row, because only the latest line of all gets rank 1"
correct: 2
explanations:
  - "RANK gives tied rows the same number. The two ibuprofen lines have the same counted_at, so both get rank 1. ROW_NUMBER would keep only one of them."
  - "RANK does remove lines here: the paracetamol count at 08:00 gets rank 2 and is filtered out. Only lines with rank 1 stay."
  - "Right. Paracetamol at 16:00 gets rank 1 and the 08:00 line gets rank 2. The two ibuprofen lines tie, both get rank 1, and both stay. That makes 3 rows."
  - "The window has PARTITION BY item, so each item has its own rank 1. Without the partition, one line would win, but the partition is in the query."
```

```quiz
type: mcq
question: "Lama's table has 50,000 order edit lines. Every order was edited 2 to 4 times, and each edit has its own status and edited_at. She asks an AI tool how to keep only the latest edit of each order. It answers: 'Run SELECT DISTINCT order_id, status, edited_at FROM edits. DISTINCT removes the old edits, so the latest line stays for each order.' What will the query return?"
options:
  - "All 50,000 lines, because every edit differs in status or edited_at"
  - "One line per order, chosen by DISTINCT as the latest edit"
  - "One line per order, but only if the table is sorted by edited_at first"
  - "An error, because DISTINCT cannot compare three columns at once"
correct: 0
explanations:
  - "Right. DISTINCT removes only lines that are identical in every selected column. Each edit has its own status or edited_at, so no line is removed. The latest edit needs a window function."
  - "DISTINCT does not choose a line from each order. It has no idea which edit is the latest, because it only compares values for equality."
  - "Sorting does not change what DISTINCT compares. Lines that differ still differ after a sort, so all 50,000 lines remain."
  - "DISTINCT accepts any number of columns and runs without an error. The mistake is in what it does, not in whether it runs."
```

```quiz
type: mcq
question: "Hiba's school keeps attendance in SQLite: 80,000 rows and one index on (class_id, student_id). The screen for one student runs WHERE student_id = 4412, and the plan says SCAN attendance. The screen does not know the student's class. What do the facts support?"
options:
  - "SCAN is fine: reading all 80,000 rows is the fastest way to find one student"
  - "Drop the index on (class_id, student_id), because it slows this query"
  - "Run EXPLAIN ANALYZE, which builds the missing index while it runs"
  - "Create an index that starts with student_id, then read the plan again"
correct: 3
explanations:
  - "One student owns very few of the 80,000 rows. For a query that picks few rows, an index reads far fewer pages than a scan, as the toy rule of chapter 3.4 showed."
  - "The plan says SCAN, so this query does not use that index at all. An unused index cannot make the query slower, and it may still serve queries that filter by class."
  - "EXPLAIN ANALYZE runs the query and reports on it. It never creates an index. You create the index yourself with CREATE INDEX."
  - "Right. The index starts with class_id, and the filter has no class, so SQLite cannot start in the sorted list. An index that starts with student_id can. Read the plan again to see SEARCH, then time the query."
```

```quiz
type: mcq
question: "Tamer's solar shop has daily output readings (kWh): Mon 12, Tue 18, Thu 15, Fri 13. There is no reading on Wednesday. He changes his frame from ROWS BETWEEN 2 PRECEDING AND CURRENT ROW to RANGE BETWEEN INTERVAL 2 DAYS PRECEDING AND CURRENT ROW, ordered by day. What is the average on Friday with the RANGE frame?"
options:
  - "15.33, because RANGE still takes the last three rows"
  - "14.0, because the frame reaches Wednesday, which has no row"
  - "9.33, because the missing Wednesday counts as a reading of 0"
  - "13.0, because the frame holds only the Friday row and nothing else"
correct: 1
explanations:
  - "That is the ROWS result: Tuesday, Thursday and Friday give 46 / 3 = 15.33. RANGE counts days, not rows, so Tuesday is more than 2 days before Friday."
  - "Right. Two days before Friday reaches Wednesday. Wednesday has no row, so the frame holds Thursday and Friday: (15 + 13) / 2 = 14.0."
  - "A missing day is a missing row, not a row with the value 0. Nothing is added for Wednesday, so the sum is divided by 2 and not by 3."
  - "The frame also reaches back to Thursday, which is only 1 day before Friday. Thursday's 15 is inside the frame."
```

```quiz
type: mcq
question: "A table has 500,000 rows. The toy rule of chapter 3.4 says a full scan reads rows / 100 pages, and an index reads log2(rows), about 19 pages, plus 3 pages for each matching row. For exactly one of these four queries, the full scan reads fewer pages than the index. Which one?"
options:
  - "A query that matches 100 rows"
  - "A query that matches 1,000 rows"
  - "A query that matches 1,700 rows"
  - "A query that matches 1,600 rows"
correct: 2
explanations:
  - "The index reads about 19 + 300 = 319 pages, and the scan reads 5,000. The index is far cheaper here."
  - "The index reads about 19 + 3,000 = 3,019 pages against 5,000 for the scan. The index is still cheaper."
  - "Right. The scan reads 500,000 / 100 = 5,000 pages. The index reads about 19 + 5,100 = 5,119 pages, which is more. This is the only query past the break-even point."
  - "The index reads about 19 + 4,800 = 4,819 pages, which is just under the 5,000 of the scan. The index is still slightly cheaper at 1,600 rows."
```
