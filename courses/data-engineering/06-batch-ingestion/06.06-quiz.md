```quiz
type: mcq
question: "Jamal's youth centre keeps its attendance files in a restricted folder. While debugging, his job prints each failed row in full to a log file. Those rows hold a child's name and a parent's phone number. The log folder can be read by every staff member. What do the facts support?"
options:
  - "The log is safe, because it is a log and not a data file"
  - "The log holds personal data, so it needs the restricted rule"
  - "The log is safe, because only the failed rows are ever printed"
  - "The log is safe once the file is renamed to something plain"
correct: 1
explanations:
  - "A log can hold the same personal data as any file. What matters is what is in it, not what it is called."
  - "Right. The rows contain names and phone numbers, so the log is a copy of restricted data. It needs the same rule as the restricted zone, or the job should stop printing whole rows."
  - "A failed row still holds the name and the phone number. Printing fewer rows leaves the same personal data in a place that every staff member can read."
  - "A new file name changes nothing about who can open the file or what it holds. The rows are still in it."
```

```quiz
type: mcq
question: "Manar's job loads the day's pharmacy orders and replaces the partition for the date it is given. Run for 3 May, it left 500 rows. Later that day the source file was corrected and now has 520 rows. She runs the job for 3 May again. What does the table hold?"
options:
  - "500 rows, because a rerun must never change the result"
  - "1,020 rows, because the rerun adds to the 500 already there"
  - "520 rows, because the output follows the corrected input"
  - "An error, because the folder for 3 May already exists"
correct: 2
explanations:
  - "Idempotent means the same input gives the same result. Here the input changed, so a different result is correct. A job that ignored the correction would be wrong."
  - "That is what an append would do. This job replaces the partition, so the old 500 rows are thrown away before the 520 are written."
  - "Right. The job replaces the day, so the table follows the source: 520 rows. Run again with the same corrected file, it would give 520 rows again, which is what idempotent means."
  - "A replacing job expects the folder to exist and swaps its content. An existing folder is the normal case for a rerun, not an error."
```

```quiz
type: mcq
question: "Sana's extract uses a watermark and asks for updated_at strictly later than the saved value, 2026-05-10 09:00. The source holds: R1 updated at 09:00, R2 updated at 09:05, R3 deleted at 09:10, and R4 edited by a script that leaves updated_at at 1 May. Which rows does the next run read?"
options:
  - "R2 only, the one existing row with a later updated_at"
  - "R1 and R2, because the run also reads rows equal to the watermark"
  - "R2 and R3, because the run also reads rows that were deleted"
  - "R2 and R4, because the run reads every row that was edited"
correct: 0
explanations:
  - "Right. R1 is equal to the watermark, not later. R3 no longer exists. R4's updated_at is old. Only R2 exists and has a later updated_at."
  - "The query asks for rows strictly later than the watermark, so R1, which is equal to it, is not read."
  - "A deleted row has no updated_at and does not exist for the query, so R3 cannot be read. That is the gap in the watermark method."
  - "The run looks at updated_at, not at whether a row was edited. A script that leaves updated_at at 1 May hides R4's edit from the watermark."
```

```quiz
type: mcq
question: "Rana keeps a table of 40 product prices for her bakery. She edits some rows by hand a few times a week and sometimes deletes a product. A job copies the table to the lake each night. Which design do the facts favour?"
options:
  - "A watermark on updated_at, because only changed rows should move"
  - "Log-based capture, because every table needs a change log"
  - "A merge on the product id, because a merge never misses a change"
  - "A full copy each night: 40 rows are cheap, and deletes show"
correct: 3
explanations:
  - "A watermark cannot see deleted rows, and she sometimes deletes a product. For 40 rows it also saves nothing worth the gap."
  - "A change log catches deletes, but it is a lot to set up for 40 rows. Nothing in the facts says every table needs one."
  - "A merge on the key updates and inserts rows, but it does not remove a row that is gone from the source. A deleted product would stay in the lake."
  - "Right. Copying 40 rows is cheap, and a full copy replaces the lake table with what the source holds now, so a deleted product disappears too."
```

```quiz
type: mcq
question: "Duaa builds a statistics site and asks for the shared-zone files to publish on it. Those files hold volunteer_key, a code made from the phone number and a secret that the project keeps. Names and phones are dropped, and there are 12 volunteers. Can she publish them?"
options:
  - "Yes, because the names are gone, so the data is anonymous"
  - "Yes, because the key is a hash, and hashes cannot be reversed"
  - "No: it is still data about people, and the key links reports"
  - "Yes, if she deletes only the volunteer_id column before publishing"
correct: 2
explanations:
  - "Dropping names makes the data pseudonymised, not anonymous. The key still links all of one volunteer's reports, and anyone with the secret and a phone number can recompute it."
  - "A hash of a phone number can be found by trying every possible number, and the key links reports even without that. It does not make the data safe to publish."
  - "Right. The shared zone is for people bound by the project's rules. The key still ties a volunteer's reports together, so the data is about people and is not for a public site."
  - "The key is the link, so deleting volunteer_id leaves the reports of one volunteer tied together by the key."
```
