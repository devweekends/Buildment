```quiz
type: mcq
question: "Sara designs a fact table with the grain sentence 'one row is one appointment' for a clinic. The table has 12,400 rows, but only 12,100 distinct appointment_id values. What do the facts show?"
options:
  - "The grain is fine, because 12,400 is simply the true number of appointments"
  - "The sentence is false: 300 appointments appear twice and are counted twice"
  - "A date dimension is missing, and it would hold the extra 300 rows"
  - "The table has a coarser grain than the sentence, so some detail was lost"
correct: 1
explanations:
  - "If one row were one appointment, the number of rows would equal the number of distinct appointment ids. They differ by 300, so some appointments have more than one row."
  - "Right. A true grain sentence matches a count: rows equal distinct ids. Here 300 extra rows mean 300 repeated appointments, and a sum or a count over the table counts them twice."
  - "A date dimension holds one row for each day. It cannot hold extra appointment rows, and adding it would not change the count of rows in the fact table."
  - "Extra rows mean the table is finer than the sentence in some places, not coarser. A coarser grain would give fewer rows than ids, and detail would be missing."
```

```quiz
type: mcq
question: "Mazen's fact table has 1,000 sales rows for shop S4, adding up to 50,000 shekels. The shop dimension has 3 rows for S4, one for each version of the shop. He joins the sales to the dimension on shop_code only and sums the amount for S4. What does the sum return?"
options:
  - "50,000, because each sale still has one amount"
  - "16,667, because the total is shared between the 3 versions"
  - "100,000, because each sale matches two of the older versions"
  - "150,000, because each sale matches all 3 versions"
correct: 3
explanations:
  - "Each sale keeps its amount, but the join returns it once for every matching version. A join on the code alone makes 3 rows from each sale, so the sum is not 50,000."
  - "A join does not divide the amount among the matches. It repeats the whole row for each match, so the sum goes up, not down."
  - "All 3 versions share the code S4, so every sale matches all 3, not only the older two. That gives 3 rows for each sale."
  - "Right. Every sale matches all 3 rows that share the code S4, so 1,000 rows become 3,000 and the sum becomes 3 x 50,000 = 150,000. The join needs the date range, or the surrogate key."
```

```quiz
type: mcq
question: "Tamer's pharmacy app records about 1,200 stock changes a day, typed one at a time by cashiers. Once a month the owner runs a report that adds up a year of stock lines. It runs on the live tables, takes minutes, and the cashiers' screens freeze while it runs. What fits these facts?"
options:
  - "Copy the data into report tables on a schedule, and run the report there"
  - "Add the report's columns to the app tables, so that the report needs no joins"
  - "Run the monthly report every hour, so that each run adds up a smaller part"
  - "Ask the cashiers to stop typing for the minutes while the report runs"
correct: 0
explanations:
  - "Right. Recording is many small writes and the report is one big read. A copy shaped for reports lets the report run without touching the app, and the cashiers keep working."
  - "More columns in the app tables would repeat values on the live lines and make every change slower. The report would still read the live tables and still freeze the screens."
  - "Running the report more often puts the heavy read on the live tables more often. A smaller part each time still competes with the cashiers, and the numbers are harder to add up."
  - "This hides the problem and does not solve it. Cashiers must be able to record changes at any time, and the report still reads the wrong tables."
```

```quiz
type: mcq
question: "Iyad keeps a customer dimension for an online shop. (a) The delivery district changes when a customer moves, and the owner wants sales by the district where each order was shipped. (b) One customer's name had a typing mistake. (c) The preferred language changes, and the owner only ever mails customers in their current language. Which mapping fits?"
options:
  - "(a) type 1, (b) type 2, (c) type 1"
  - "(a) type 2, (b) type 2, (c) type 2"
  - "(a) type 2, (b) type 1, (c) type 1"
  - "(a) type 1, (b) type 1, (c) type 1"
correct: 2
explanations:
  - "This is backwards for (a) and (b). Overwriting the district moves every old order to the new district, and a new row for a typing mistake keeps a wrong name as a version."
  - "Type 2 for all three works for (a), but (b) keeps a mistake as a version and (c) adds rows for a past that nobody will ask about. It is wasteful and gives one customer two names."
  - "Right. The district is a real change and the owner needs the past, so it gets type 2. The typing mistake was never true, so it is overwritten. Only the current language is used, so overwriting loses nothing anyone needs."
  - "Overwriting everything puts old orders in the customer's new district. The owner asked for the district where each order was shipped, and type 1 cannot answer that."
```

```quiz
type: mcq
question: "Mazen's water round has a route dimension for household H9. Key 1: route R1, valid_from 2026-01-01, valid_to 2026-02-09. Key 2: route R2, valid_from 2026-02-09, valid_to empty. The valid_to date is not part of the range. H9 had deliveries on 3 February, 9 February and 10 February, and each is joined to the version valid on its date. How many deliveries does each route get?"
options:
  - "R1 gets 2 and R2 gets 1, because the end date counts for R1"
  - "R1 gets 0 and R2 gets 3, because only the household's current route is used"
  - "R1 gets 3 and R2 gets 3, because each delivery matches both rows"
  - "R1 gets 1 and R2 gets 2, because the end date is not part of R1's range"
correct: 3
explanations:
  - "The stem says the end date is not part of the range. 9 February is the first day of R2, so only the delivery on 3 February belongs to R1."
  - "That is what type 1 would do: only the current route is kept. Here both versions exist, and the dates decide which delivery belongs to which route."
  - "Each delivery matches only one version, since the ranges do not overlap. Six rows would come from a join that ignores the dates."
  - "Right. 3 February falls in R1's range. 9 February is not in R1's range, because the end is excluded, and it starts R2. So R1 gets 1 delivery and R2 gets 2."
```
