```quiz
type: mcq
question: "A design has two gateways that can pass on 2,400 requests a second each, and 4,000 requests a second arrive at the busiest moment. One gateway dies. What does the board show?"
options:
  - "Everyone is served, because the other gateway takes over"
  - "About 60%, because one gateway cannot carry 4,000"
  - "Nothing is served, because the phones lose their lines"
  - "About 83% are served, because the cache absorbs the rest"
correct: 1
explanations:
  - "The other gateway takes over only if it has room. It can pass on 2,400 a second, which is less than the 4,000 that now arrive."
  - "Right. One gateway passes on 2,400 of 4,000, which is 60%. Three gateways would leave two at 83% busy and serve everyone."
  - "The gateway left is still alive, so some requests are served. The board measures how many, and it is the capacity left over the load."
  - "The cache sits behind the app servers and cannot take load off the gateways, which every request passes first."
```

```quiz
type: mcq
question: "A design has a cache at a 90% hit rate and a message store of one small node. At 4,000 requests a second the board shows it passing every check in the peak scene and failing the p99 check in the cache scene. What explains the difference?"
options:
  - "The cache is too small and drops data when it gets busy"
  - "The gateways are the busiest part in the cache scene"
  - "Without a cache, the store gets all 4,000"
  - "The cache scene removes the app servers as well"
correct: 2
explanations:
  - "The cache's size is not the problem here. In the peak scene it works and the store is nearly idle. The failure appears only when the cache is gone."
  - "The gateways are not behind the cache. Their load is 4,000 requests a second in both scenes, so they cannot be what changed."
  - "Right. At a 90% hit rate the store sees about 400 requests a second. When the cache dies it sees all 4,000, which fills a single small node."
  - "The scene only takes the cache down. The app servers carry the same load as before, so they are not what fails."
```

```quiz
type: mcq
question: "About 1 request in 10 needs an alert, so 400 alerts arrive each second. The alert workers stop for 15 minutes, then return. Each worker sends 2,400 alerts a second. How many workers clear the waiting alerts (the backlog) within 120 seconds?"
options:
  - "One, because 2,400 a second is far above the 400 arriving"
  - "Two, with 4,400 a second to spare"
  - "Three, to be safe against any outage"
  - "None, because a queue clears itself on restart"
correct: 1
explanations:
  - "One worker has 2,000 a second to spare after the new alerts. 360,000 waiting alerts divided by 2,000 is 180 seconds, over the limit."
  - "Right. Two workers send 4,800 a second. After 400 for new alerts, 4,400 are spare, and 360,000 divided by 4,400 is 82 seconds."
  - "Three workers also pass, in 53 seconds, but the third costs $0.12 an hour more and the design then goes over its budget."
  - "A queue only holds alerts. Something must take them out, and it must do so faster than they arrive, or the waiting alerts stay."
```

```quiz
type: mcq
question: "A gateway holding 50,000 phones crashes. The board shows every request still served. A real design must also cope with what happens next. What does the board not show?"
options:
  - "That the cache lost its entries when the gateway stopped"
  - "That the queue can no longer hold alert jobs"
  - "That 50,000 phones reconnect at the same moment"
  - "That the message store forgot the messages of those phones"
correct: 2
explanations:
  - "The cache did not stop in this scene. The board takes the cache down in a different scene, and it is not tied to one gateway."
  - "The queue is not behind the gateway and keeps every job it has. A dead gateway does not touch it."
  - "Right. The board counts requests a second, and a reconnect storm is a burst of connections. Phones should wait a random time that grows after each failure (chapter 22.3)."
  - "The store keeps messages whether or not a gateway is alive. Losing a gateway loses its open lines, not any saved message."
```
