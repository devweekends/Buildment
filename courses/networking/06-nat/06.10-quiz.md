```quiz
type: mcq
question: "A router masquerades two phones. Both send from source port 52000 to the same web server, and the first phone's packet crosses first. The router's outside address is 203.0.113.1. What does the server see for the second phone?"
options:
  - "203.0.113.1 with source port 52000"
  - "The phone's private address, with a new port"
  - "203.0.113.1 with a new source port"
correct: 2
explanations:
  - "The first phone already owns 203.0.113.1:52000 for this server. If the second phone also used it, the router could not tell their replies apart, so it changes the port."
  - "The router rewrites the source address every time. A private address never reaches the server."
  - "Right. The address is always rewritten. The port is changed only because the two conversations would otherwise look the same."
```

```quiz
type: mcq
question: "A laptop at 192.168.0.40 sits behind a home router with the outside address 100.66.7.2. That router sits behind a provider NAT with the public address 198.51.100.9. What source address does a packet carry between the two routers, and what does the server see?"
options:
  - "100.66.7.2 between them; 198.51.100.9 at the server"
  - "198.51.100.9 between them; 100.66.7.2 at the server"
  - "192.168.0.40 between them; 198.51.100.9 at the server"
correct: 0
explanations:
  - "Right. The home router rewrites the source first, to its outside address 100.66.7.2. The provider NAT rewrites it again, to 198.51.100.9, and the server sees only that one."
  - "The order is reversed. The public address can only be put on the packet by the router that owns it, which is the last one, the provider's."
  - "The home router also does NAT. The private address 192.168.0.40 is already gone by the time the packet leaves it."
```

```quiz
type: mcq
question: "A friend sends a packet to your router's outside address, port 9000. Nothing at home ever used that port, and you wrote no forwarding rule. Why does it not reach your laptop?"
options:
  - "The packet is for a private address, so it is lost on the way"
  - "No row or rule tells the router which device it is for"
  - "NAT blocks everything from outside, as a firewall would"
correct: 1
explanations:
  - "The packet is addressed to the router's outside address, which is not private. The private address of the laptop is never in it."
  - "Right. A row exists only if a device sent a packet first, and a rule exists only if someone wrote one. With neither, the router has nobody to give the packet to."
  - "NAT is not a firewall. It blocks nothing by itself: with a route to the home range, the lab router forwarded a packet straight to the laptop."
```

```quiz
type: mcq
question: "A laptop at 192.168.1.23 uses source port 48172 for a connection to a server at 192.168.1.80, port 8080. The laptop's ss line shows 192.168.1.23:48172 and 192.168.1.80:8080. How does the server's ss line show the same connection?"
options:
  - "Local 192.168.1.80:48172, peer 192.168.1.23:8080"
  - "Local 192.168.1.80:8080, peer 192.168.1.23:8080"
  - "Local 192.168.1.80:8080, peer 192.168.1.23:48172"
correct: 2
explanations:
  - "The ports are swapped to the wrong sides. Each end keeps its own port: the server's port is 8080, and the laptop's is 48172."
  - "The laptop's port is 48172, not 8080. The server's peer is the laptop and the port it used."
  - "Right. The server sees the same numbers the other way round: its own address and port 8080 as local, and the laptop with port 48172 as the peer."
```

```quiz
type: mcq
question: "One computer runs a server on 127.0.0.1:8000 and another on 0.0.0.0:8001. A client on a different computer tries both. What happens?"
options:
  - "Port 8001 works; port 8000 is refused"
  - "Both work, because the client knows the port"
  - "Both are refused, because the client is remote"
correct: 0
explanations:
  - "Right. A server on 127.0.0.1 listens only for connections from its own computer, so a remote client is refused. A server on 0.0.0.0 listens on every address."
  - "Knowing the port is not enough. A server on 127.0.0.1 answers only the computer it runs on."
  - "A remote client can reach a server that listens on 0.0.0.0. Only the one on 127.0.0.1 refuses it."
```
