```quiz
type: mcq
question: "You run a game server on your own computer at home. The game listens, you are sure, but players get no answer on its port. Which tool shows whether that port answers, refuses or stays silent?"
options:
  - "iperf3, which measures the path"
  - "dig, which asks a resolver"
  - "nmap, which knocks on the port"
correct: 2
explanations:
  - "iperf3 measures how much data a path carries each second between two computers you control. It does not test whether one port of the server answers."
  - "dig tells you which address a name gives. If the name is right and the port is silent, dig cannot see the port at all."
  - "Right. nmap sends the first packet of a handshake to the port and reports what came back: open for an answer, closed for a reset, filtered for nothing."
```

```quiz
type: mcq
question: "An mtr report from your laptop to a website: hop 1 0.0%, hop 2 45.0%, hop 3 0.0%, hop 4 (the website) 0.0%. What does the 45.0% at hop 2 mean?"
options:
  - "Hop 2 limits replies about itself"
  - "Packets are lost on the cable to hop 2"
  - "The website loses 45% of your packets"
correct: 0
explanations:
  - "Right. Every probe for hops 3 and 4 passed through hop 2, and none was lost. So hop 2 forwards well and only answers few probes about itself."
  - "Loss on that cable would also hit every probe for hops 3 and 4, because they cross it too. Those rows would show loss as well."
  - "The website is hop 4, and its row shows 0.0%. The last hop is the loss your traffic really feels."
```

```quiz
type: mcq
question: "In the lab, you want tcpdump to save only the packets to or from the campus resolver, 192.0.2.1, so the file stays small. What goes at the end of the tcpdump command?"
options:
  - "ip.addr == 192.0.2.1"
  - "ip.src == 192.0.2.1"
  - "host 192.0.2.1"
correct: 2
explanations:
  - "That is a Wireshark display filter. It only hides packets in a file you already have. tcpdump takes the libpcap language when it captures."
  - "That is a display filter too, and it would keep only one direction. tcpdump needs a capture filter, which decides what is saved."
  - "Right. host 192.0.2.1 is a capture filter. It keeps packets to or from that address, and the rest are never saved."
```

```quiz
type: mcq
question: "You scan your own lab server with nmap -n -p 8443. It shows 8443/tcp filtered. On the server, ss -ltn shows a program listening on 8443. What is the most likely cause?"
options:
  - "A rule on the way drops the packets"
  - "Nothing listens, so the server resets"
  - "The program refused nmap with a reset"
correct: 0
explanations:
  - "Right. The program listens, but no answer reached nmap, not even a reset. Something between the two, such as a drop rule in a router, throws the packets away."
  - "A reset would make nmap say closed, not filtered. And ss shows that a program does listen."
  - "A listening program answers the first packet with a SYN-ACK, and nmap would say open. A reset would make it closed. Filtered means nothing came back."
```

```quiz
type: mcq
question: "A resolver copies the answer for www.example.org at 11:58. The answer has a TTL of 600 seconds. The owner changes the address at 12:00. Until when may this resolver still give the old address?"
options:
  - "12:10, ten minutes after the change"
  - "12:00, when the change was made"
  - "12:08, ten minutes after the copy"
correct: 2
explanations:
  - "The TTL counts from the moment the resolver made its copy, not from the change. The copy was made at 11:58."
  - "The resolver does not know the record changed. It keeps its copy until the TTL runs out."
  - "Right. 600 seconds is ten minutes. The copy was made at 11:58, so it may be used until 12:08. After that the resolver asks again and gets the new address."
```
