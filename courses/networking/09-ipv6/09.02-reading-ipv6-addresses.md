Your phone shows `fe80::1c2b:3aff:fe4d:5e6f`. How many bits is that, and where did the missing zeros go? This chapter answers both, and then shows you how to shorten any address the standard way.

## Eight groups of sixteen bits

<MermaidDiagram title="One address, cut into eight groups" chart={`flowchart LR
  subgraph N["First 64 bits: the network"]
    A["2001"] --- B["0db8"] --- C["04a1"] --- D["0020"]
  end
  subgraph I["Last 64 bits: the interface"]
    E["0000 (::)"] --- F["0000 (::)"] --- G["0000 (::)"] --- H["005c"]
  end
  D --- E
`} legend="The address 2001:db8:4a1:20::5c written out in full. The cut after the fourth group splits network from interface. The three groups of zeros are what :: stands for." />

An IPv6 address has 128 bits [S2]. It is written as eight groups, and each group is four hex digits, which is 16 bits. The picture cuts the address after four groups: the first 64 bits name the network, and the last 64 name the interface [S3]. The `::` stands for a run of zero groups.

<GoDeeper title="Go deeper: count the bits of your phone's address">

A hex digit is one of 0 to 9 and a to f, and it holds 4 bits. Four hex digits make one group of 16 bits. Eight groups make 8 x 16 = 128 bits [S2]. An IPv4 address has only 32 bits [S1]. So IPv6 has 2^96 times as many addresses as IPv4. That is arithmetic, not a measurement.

Now the opening question. The address `fe80::1c2b:3aff:fe4d:5e6f` writes five groups: `fe80`, `1c2b`, `3aff`, `fe4d` and `5e6f`. Five groups are 5 x 16 = 80 bits. The `::` hides the rest: 128 - 80 = 48 bits, which is three groups of zeros. So the address is 128 bits, and the missing zeros are inside the `::`.

The first group, `fe80`, tells you what kind of address it is. The block `fe80::/10` is for <GlossaryTerm term="link-local address" definition="An address that works only on your own link and is never forwarded off it." />, and routers never forward it off the link [S3]. Two more special addresses are worth knowing. `::1` is the loopback address, the way a computer talks to itself. A lone `::` means "unspecified", an address that is not set yet [S3].

The last 64 bits are the <GlossaryTerm term="interface ID" definition="The last 64 bits of an IPv6 address. They name one network connection on the network." />. Chapter 9.3 shows how a device chooses its own.

</GoDeeper>

## Expand an address, group by group

<InteractiveCanvas slug="net-m9-v6-expand" />

Press Expand on `2001:db8:4a1:20::5c`. Five groups are written and an address has eight, so `::` becomes three groups of `0000`. Each written group also gets its leading zeros back: `db8` becomes `0db8`, and `5c` becomes `005c`. Then type an address of your own.

<GoDeeper title="Go deeper: one short form, one expansion">

To expand, count the written groups and take them from eight. The answer is how many zero groups `::` stands for. Then fill each group up to four digits with zeros on the left. For `2001:db8:4a1:20::5c` the full form is `2001:0db8:04a1:0020:0000:0000:0000:005c`.

This only works because `::` is used at most once. With one `::`, the count has one answer, so every short form has exactly one full form. Your phone's address does the same: `fe80::1c2b:3aff:fe4d:5e6f` becomes `fe80:0000:0000:0000:1c2b:3aff:fe4d:5e6f`.

The special addresses show the extremes. `::1` is seven groups of zeros and then `1`, so its full form is `0000:0000:0000:0000:0000:0000:0000:0001`. A lone `::` is all eight groups of zeros [S3].

</GoDeeper>

## Shorten it to the standard form

<InteractiveCanvas slug="net-m9-v6-shorten" />

Now go the other way. Drop the leading zeros of every group. Then find the longest run of zero groups and replace it with `::` [S4]. The address `2001:0db8:0000:0000:0001:0000:0000:0001` has two runs of two zero groups. They are equally long, so the first one is compressed: `2001:db8::1:0:0:1`.

<GoDeeper title="Go deeper: the rules of RFC 5952">

One address can be written in many ways, so RFC 5952 picks one standard text form [S4]. It has four main rules. First, drop the leading zeros in every group. Second, write the letters a to f in lower case. Third, replace the longest run of zero groups with `::`. Fourth, when two runs are equally long, replace the first one (section 4.2.3 of the RFC).

A run must be two groups or more. A single zero group stays `0` and is never replaced by `::`. For example, `2001:db8:0:1:1:1:1:1` is already in standard form.

Two worked cases. `2001:db8:0:0:1:0:0:0` has a run of two groups and then a run of three. The longer run wins, so the standard form is `2001:db8:0:0:1::`. And `fe80:0000:0000:0000:0000:0000:0000:0001` has one run of six groups, so it becomes `fe80::1`.

<MustRead title="A Recommendation for IPv6 Address Text Representation, section 4" url="https://www.rfc-editor.org/rfc/rfc5952.txt" source="RFC 5952" description="The rules for the standard short form. Read section 4 and answer: which run does :: replace when two runs are equally long?" readMinutes={5} />

</GoDeeper>

## Invalid is not the same as non-standard

<InteractiveCanvas slug="net-m9-v6-invalid" />

Type a form and read the verdict. `2001:db8::1::5c` is invalid: it has two `::`, and nobody can tell how many zero groups each one hides [S3]. `2001:0DB8:0:0:0:0:0:5C` is valid, because everybody can read it. It is only not standard, because it has capital letters and an uncompressed run.

<GoDeeper title="Go deeper: why two :: are refused">

Count the groups of `2001:db8::1::5c`. Four are written: `2001`, `db8`, `1` and `5c`. So four zero groups are left, and two `::` must share them. They could split them 1 and 3, 2 and 2, or 3 and 1. Each split gives a different address from the same text. A text with three possible meanings is not an address, so the rule is that `::` appears once [S3].

Other invalid forms break a different rule. A group with more than four digits, such as `12345`, is invalid. So is a character that is not hex, and so is an address with too many or too few groups.

Valid but not standard forms are different. Every reader gets the right address from them. They only break a rule of the standard text. The common ones are capital letters, kept leading zeros, a run left uncompressed, a `::` used for only one zero group, and a tie broken the wrong way. For example, `2001:db8:0:0:0::5c` is valid. The standard form is `2001:db8::5c`.

The standard exists so that one address has one text. Then two people, or two programs, who write the same address write the same characters [S4].

</GoDeeper>

## Why a normal subnet is a /64

<MermaidDiagram title="Under a documentation block" chart={`flowchart TD
  P["Block 2001:db8::/32 (documentation)"] --> S["32 bits left for subnets: 2^32 subnets"]
  S --> N["Each subnet is a /64: 64 bits name the network"]
  N --> H["64 bits name the interface: 2^64 addresses per subnet"]
`} legend="The prefix 2001:db8::/32 is kept for examples. The split at 64 bits is the same in every normal subnet." />

A normal subnet is a `/64`. The standard asks for a 64-bit interface ID [S3], and a `/64` is the practical reading of that. Under the documentation block `2001:db8::/32` [S69], 32 bits are left for subnets. That makes 2^32 subnets, and each has 2^64 addresses.

<GoDeeper title="Go deeper: how big one subnet is">

The numbers come from simple arithmetic. A `/32` leaves 128 - 32 = 96 bits. A `/64` subnet uses 32 of them to number the subnets, so there are 2^32 = 4,294,967,296 subnets. The remaining 64 bits number the interfaces, so one subnet has 2^64 = 18,446,744,073,709,551,616 addresses.

Compare this with IPv4. The whole IPv4 space is 2^32 addresses [S1]. One single IPv6 subnet holds 2^64 / 2^32 = 2^32 times that, which is about 4.3 billion times the whole IPv4 internet. A home needs only a few subnets, so nobody has to count addresses.

<Callout type="info" title="Two phrases, one idea">
The standard says "64-bit interface ID" [S3]. "A subnet is a /64" is the practical reading of it. When you see a `/64` on a router, think: 64 bits network, 64 bits interface.
</Callout>

Take a <GlossaryTerm term="global address" definition="An address that can be reached from the internet." /> such as `2001:db8:4a1:20::5c`. Its first four groups are the `/64` prefix, and its last four groups are the interface ID.

Chapter 9.3 shows how a device fills in the last 64 bits for itself. Until then, only the idea matters: the cut is at 64 bits, and the network part is on the left.

</GoDeeper>

## Shorten five addresses by hand

<InteractiveCanvas slug="net-m9-v6-drill" />

Practise without help. Each set has five questions: the short form of a full address, the full form of a short one, and whether a written form is standard, valid but not standard, or invalid. After a wrong answer, find the rule you broke. Nothing here is saved or graded.

<GoDeeper title="Go deeper: the usual slips, and a four-step method">

The wrong answers in the drill are realistic slips. They keep leading zeros. They compress the wrong run. They compress nothing. They write capital letters. And they use two `::`.

A four-step method catches all of them. Step one: drop the leading zeros in every group. Step two: mark every run of two or more zero groups. Step three: pick the longest run, or the first one if two are equally long, and write `::` there. Step four: check that all letters are lower case and that `::` appears at most once.

Try it on `2001:0db8:0000:0001:0000:0000:0000:0001`. After step one it is `2001:db8:0:1:0:0:0:1`. The runs are one single zero group and then a run of three. The run of three is longer, so the answer is `2001:db8:0:1::1`. The single zero group after `db8` is not touched.

</GoDeeper>

<GoDeeper title="Sources">

[S3] RFC 4291: 64-bit interface IDs, the special addresses `::1`, `::` and `fe80::/10`, and one `::` at most; the RFC says "64-bit interface ID", and "a subnet is a /64" is the practical reading. [S4] RFC 5952: the standard text form, with section 4.2.3 for equally long runs. [S69] RFC 3849: `2001:db8::/32` is reserved for documentation. ## Quick check

```quiz
type: mcq
question: "A log prints the address 2001:0db8:0000:0000:0000:0a00:0000:0001. Which one is the standard short form?"
options:
  - "2001:db8::a00::1"
  - "2001:db8::a:0:1"
  - "2001:db8::a00:0:1"
  - "2001:db8:0:0:0:a00:0:1"
correct: 2
explanations:
  - "This replaced both runs with ::. Two :: are invalid, because nobody can tell how many zero groups each one hides."
  - "This cut the zeros at the end of a00 and left a. Only leading zeros go, never the ones at the end of a group, so a00 stays a00."
  - "Right. Drop the leading zeros, replace the longest run (three groups) with ::, and keep the single zero group before 1 as 0."
  - "This is valid, and every reader gets the right address. But the run of three zero groups should be replaced with ::, so it is not the standard form."
```
