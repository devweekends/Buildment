With IPv6, your phone and your laptop each get their own global address. So what stops anyone on the internet from reaching them?

## Every device has its own global address

<InteractiveCanvas slug="net-m9-ipv6-addresses" />

Press **Next** to fill the table. The router announces one prefix, `2001:db8:4a1:20::/64`. The phone adds `::5c` and the laptop adds `::23`, so each holds its own <GlossaryTerm term="global address" definition="An address that can be reached from the internet. It is the one other networks see." />. The server lives on another network, at `2001:db8:ffff::80`.

<GoDeeper title="Go deeper: what a global address changes">

In module 2 you saw that a home network uses private addresses such as `192.168.1.24`. They work only inside the home, so many homes can use the same numbers. A global address is different. It is the one other networks see, so every device can keep its own.

The numbers explain why this is possible. Chapter 9.2 showed that one `/64` subnet holds 2^64 addresses. A home with ten devices uses a tiny part of one subnet, and nobody has to share an address.

All the addresses here are in the documentation prefix `2001:db8::/32`, which is reserved for examples [S69]. The public IPv4 addresses in these pictures come from the IPv4 documentation ranges [S10]. In the picture, the phone and the laptop share only the prefix, which is the first 64 bits. Only the interface part differs.

The picture is a model. The router announces a prefix and each device checks its address before it uses it, as the fourth beat shows [S72]. These steps are not drawn here. The course lab tested one IPv6 link between two namespaces, and it worked [D5.5]. Router announcements and IPv6 forwarding through a router were not tested [D5.6].

</GoDeeper>

## The server sees each device itself

<InteractiveCanvas slug="net-m9-ipv6-vs-nat" />

Press **Next** through the IPv4 home first. Both devices reach the server as `198.51.100.2`, so the server cannot tell them apart by address. Then the IPv6 home: the phone arrives as `2001:db8:4a1:20::5c` and the laptop as `2001:db8:4a1:20::23`, and nothing is rewritten. Compare the two tables.

<GoDeeper title="Go deeper: why NAT shows one address">

NAT with ports, called NAPT, translates many inside addresses into one outside address [S17]. The router keeps a table that ties an inside address and port to an outside address and port [S18]. A reply comes back to the outside address, and the table tells the router which inside device it is for. Module 6 builds this with your own hands.

In the course lab, the server saw the router's outside address, `198.51.100.2`, for a device behind the router [D5.7]. In the same lab, the router rewrote the address and kept the port. It rewrote the port only when two devices would have clashed [D5.6].

Without NAT, none of this is needed. The request keeps its source address all the way. The server sees the phone's own address, and it sees the laptop's own address, so it can tell the two devices apart by address.

The picture does not say that NAT is bad. It only shows what the server sees. The next beat looks at the other job people expect from NAT, which is keeping strangers out.

</GoDeeper>

## A filter, not NAT, keeps strangers out

<InteractiveCanvas slug="net-m9-ipv6-filter" />

Press **Next**. The phone's own request makes the filter write a note, so the reply is let in. Before the last packet moves, pick what the filter does with a packet that nobody asked for. Then read why: the address says where a packet goes, and the filter, not NAT, says whether it may come in.

<GoDeeper title="Go deeper: NAT was never the lock">

Module 6 showed that NAT was never what kept the internet out. An unsolicited packet to a device behind NAT has no mapping, and the internet has no route to private ranges [S17, S18]. In the course lab, a server that added a route to the private network could reach the laptop at once. A router that only does masquerade is not a firewall [D5.6]. AWS documents the same for its NAT gateway: it only passes traffic from private instances out [S51].

So a global address does not mean "open to everyone". Reachability is decided by a filter. A <GlossaryTerm term="stateful filter" definition="A filter that remembers the connections that devices inside started. It lets their replies in and drops packets that nobody asked for." /> remembers the connections that a device inside started. It lets their replies in and drops packets that nobody asked for. The picture shows exactly this.

<Callout type="warning" title="The filter here is a model">
This is the lab's model of a simple filter, not a test of a real router. Real home routers differ in what they filter by default. Do not read the picture as a promise about your own router.
</Callout>

Two wrong ideas are common. One says that no NAT means anyone can reach your laptop. The other says that IPv6 is unsafe. Both mix up the address and the filter. The address says where a packet goes. The filter says whether it may come in.

</GoDeeper>

## A device forms its own address

<MermaidDiagram title="How a device gets a global address" chart={`flowchart TD
  R["Router announces the prefix 2001:db8:4a1:20::/64"] --> D["Device adds its own interface identifier"]
  D --> C["Device checks that nobody else uses the address"]
  C --> G["Global address, for example 2001:db8:4a1:20::5c"]
  G --> T["Temporary address: random identifier, replaced over time"]
`} legend="The first three steps are called SLAAC. The last box is the privacy feature: a temporary address." />

A device builds its own global address. This is called <GlossaryTerm term="SLAAC" definition="Stateless address autoconfiguration: a device forms its own address from the router's prefix." />. The router announces a prefix, the device adds its own interface identifier, and it checks that nobody else uses the result [S72]. A temporary address is random and is replaced over time, for privacy [S73].

<GoDeeper title="Go deeper: SLAAC, temporary addresses and your own phone">

SLAAC is the way a host forms a global address from a router-advertised prefix plus its interface identifier, after duplicate address detection [S72]. Duplicate address detection means the device first checks that no other device already uses the address. The prefix is 64 bits and the interface identifier is the other 64, as chapter 9.2 showed [S3].

A <GlossaryTerm term="temporary address" definition="A random address that is replaced over time." /> answers a privacy problem. A fixed number is easy to recognise. A temporary address uses a random identifier, and the device replaces it over time, so the same number does not stay for long [S73].

For you, this means one thing. If the global address you read in 9.1 is a temporary one, it changes after a while, which is normal.

The pictures of the first three beats do not draw router announcements or the check for duplicates, and each picture says so in its limits. The optional stretch S5, about 60 minutes, builds IPv6 in the lab network with addresses and routes and `ping -6`. It comes later, it is not graded, and it needs the settings from the lab test: `disable_ipv6=0` in each namespace, and `nodad` when you add addresses [D5.5].

</GoDeeper>

## Dual stack is two networks side by side

<MermaidDiagram title="One phone, two paths" chart={`flowchart LR
  P["Phone: 192.168.1.24 and 2001:db8:4a1:20::5c"] -->|"IPv4 path"| N["Router with NAT: 198.51.100.2"]
  N --> S4["Server over IPv4: 203.0.113.80"]
  P -->|"IPv6 path, no NAT"| S6["Server over IPv6: 2001:db8:ffff::80"]
`} legend="The same phone has an IPv4 address and an IPv6 address. NAT sits only on the IPv4 path." />

Your phone in chapter 9.1 had an IPv4 address next to IPv6 addresses. That is <GlossaryTerm term="dual stack" definition="Complete support for both IPv4 and IPv6 in hosts and routers." />: complete support for both IPv4 and IPv6 [S74]. The phone has two addresses and two paths: on the IPv4 path NAT is still in the middle, and on the IPv6 path the packet goes direct.

<GoDeeper title="Go deeper: why both are still running">

Dual stack means hosts and routers support both protocols at once [S74]. The two protocols run side by side, and each has its own addresses and its own paths. So a network can use IPv6 without switching IPv4 off.

The reason it is still needed is in the numbers. Google counted just over half of its users on IPv6 on 28 March 2026, so about half still reached it over IPv4 [S33]. Chapter 9.5 asks you to use that number.

In the picture, NAT is a part of the IPv4 path only. The IPv6 path has no NAT, and its protection comes from a filter, as the third beat showed. The phone uses its own address on the IPv6 path, with the same prefix and ending you saw in the first beat.

</GoDeeper>
