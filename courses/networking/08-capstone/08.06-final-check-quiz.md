```quiz
type: mcq
question: "An office VPN gives your laptop addresses from 192.168.1.128/25. Your home subnet is 192.168.1.0/24. Do the two ranges overlap?"
options:
  - "No: different masks mean different networks"
  - "Only the DHCP pool overlaps, not the subnets"
  - "Yes: 192.168.1.128/25 sits inside the /24"
correct: 2
explanations:
  - "The length of a mask does not keep two ranges apart. What counts is whether they share addresses. A /25 from .128 to .255 uses numbers that the home /24 already owns."
  - "The pool is only a part of the home range. The whole VPN block, .128 to .255, lies inside 192.168.1.0/24, so the subnets overlap, and the laptop cannot tell which network a packet belongs to."
  - "Right. The /24 covers .0 to .255. The /25 covers .128 to .255, which is the upper half. It is nested inside the home subnet, so the two overlap."
```

```quiz
type: mcq
question: "A packet from 192.168.1.30 to 203.0.113.80 crosses one plain router that does no NAT. You capture it on the link before the router and on the link after it. Which fields differ?"
options:
  - "Both MACs and the TTL; the IPs are the same"
  - "The source IP and the TTL; the MACs are the same"
  - "Nothing: a plain router copies the packet as it is"
correct: 0
explanations:
  - "Right. A MAC covers one link, so each link has its own pair. The router also lowers the TTL by one. Without NAT, both IP addresses stay as they were."
  - "A router without NAT does not touch the source IP. The MACs do change, because the packet now crosses a new link. This mixes up a plain router with a NAT router."
  - "The router must lower the TTL by at least one, and it builds a new frame for the next link. Only the two IP addresses are copied unchanged."
```

```quiz
type: mcq
question: "home1 and home2 both open a connection to the public server from source port 41000 at the same moment. Both pass through masquerade. What does the server see?"
options:
  - "Two addresses, 192.168.1.30 and 192.168.1.31"
  - "One address; the second flow gets a new port"
  - "One address and port 41000 for both flows"
correct: 1
explanations:
  - "The server never sees a private address. Masquerade rewrites the source of every flow to the router's outside address."
  - "Right. The address is rewritten for both. The port is kept for the first flow, and the router gives the second flow a new port, because two flows with the same pair would clash."
  - "Two flows to the same server with the same address and port would be one connection. The router must change one port, so the server could not see 41000 twice."
```

```quiz
type: mcq
question: "On the capstone network, dig @192.168.1.1 web.test times out. A ping to 203.0.113.80 works, and a new device still gets a lease. Which layer is at fault?"
options:
  - "The route out of the home router is missing"
  - "The lease: the DHCP server has stopped"
  - "The name step: DNS is not answering"
correct: 2
explanations:
  - "A ping to 203.0.113.80 works, so the home router has its route out. A missing route would break that ping first."
  - "A new device still gets a lease, so DHCP is working. DHCP uses its own ports, 67 and 68, so it can work while DNS fails."
  - "Right. Everything below the name works: the route, forwarding and the lease. Only the question to the DNS server gets no answer. That is the name layer."
```

```quiz
type: mcq
question: "A new device has a lease and a default gateway, but curl http://203.0.113.80:8080/ hangs. Which command do you run first?"
options:
  - "ping the gateway: the next layer up"
  - "dig web.test: the name may be wrong"
  - "conntrack -L in hrouter: NAT may be at fault"
correct: 0
explanations:
  - "Right. The address layer is done, since the device has a lease. The next layer is the gateway: does a packet reach the router? One ping splits the problem in two."
  - "curl used an address, not a name, so no name lookup is involved. Checking DNS here tests a layer that this command never uses."
  - "NAT is far up the order. The device may not even reach its router, and then the NAT table has nothing to show. Check the lower layers first."
```
