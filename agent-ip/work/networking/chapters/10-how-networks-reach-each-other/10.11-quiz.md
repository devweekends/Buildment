question: "Router X is AS64502. It is offered three routes to 203.0.113.0/24, with the AS paths 64501 64503, 64504 64502 64503 and 64505 64506 64507 64503. Which routes may X use at all?"
options:
  - "Only 64501 64503"
  - "64501 64503 and 64505 64506 64507 64503"
  - "All three routes"
correct: 1
explanations:
  - "The loop rule removes only paths that hold X's own number, 64502. The long path does not hold it, so it stays. It is longer, but it is still allowed."
  - "Right. The path 64504 64502 64503 already holds 64502, so X leaves it out. The other two do not hold 64502, so X may use either one."
  - "The middle path holds 64502, X's own number. Using it would send traffic back through X, so X leaves it out."

```quiz
type: mcq
question: "bestRoute gets myAsn 64496, destination 198.51.100.200 and a policy that gives 64497 local preference 150. The routes are: A, 198.51.100.0/24 from 64497, path 64497 64498; B, 198.51.100.128/25 from 64499, path 64499 64500 64498; C, 198.51.100.0/24 from 64499, path 64499 64498. Which one does it return?"
options:
  - "A, preference 150"
  - "B, the longer block"
  - "C, the shortest path"
correct: 1
explanations:
  - "Local preference only compares routes to the same block. The /25 also holds 198.51.100.200, and the longest block is kept first."
  - "Right. 198.51.100.200 is in the /25 (.128 to .255). The longest block wins first, before preference and path length are looked at."
  - "C ties with A on the /24 and loses to A on preference. And both /24 routes lose to the /25, which is longer."
```

```quiz
type: mcq
question: "The holder of 198.51.100.0/24 has a ROA: origin AS64496, maximum length 24. A customer of AS64496 passes that /24 from one of its providers to its other provider, so the route spreads far too wide. The AS path still ends in 64496. What does RPKI origin validation do with it?"
options:
  - "Marks it Invalid and drops it"
  - "Marks it NotFound and keeps it"
  - "Marks it Valid and lets it pass"
correct: 2
explanations:
  - "Invalid needs a wrong origin or a block longer than the maximum. Here the block is the /24 and the origin is 64496, both as signed."
  - "NotFound means no ROA covers the block. This block has a ROA, so it is checked, and it matches."
  - "Right. The block and the origin match the ROA, so the route is Valid. Origin validation does not check the rest of the path, so a leak with the right origin passes."
```
