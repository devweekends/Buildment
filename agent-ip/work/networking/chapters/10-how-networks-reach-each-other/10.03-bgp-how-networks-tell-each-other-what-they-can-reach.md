A network gets a new address block today. By tomorrow, routers on the other side of the world send traffic for it to the right place. Nobody typed a row into those routers. In 4.5 you saw the idea: networks announce what they can reach. This chapter shows the protocol that carries the announcements, BGP, one message at a time.

## Two neighbours talk over TCP port 179

<MermaidDiagram title="One BGP session between two networks" chart={`flowchart LR
  A["Router of AS64498<br>owns 203.0.113.0/24"] <-->|"BGP session<br>TCP port 179"| B["Router of AS64497"]
  A -->|"UPDATE: announce 203.0.113.0/24"| B
`} legend="Two routers of two made-up networks keep one TCP connection open on port 179. Over it they send UPDATE messages that announce blocks or take them back." />

The protocol is <GlossaryTerm term="BGP" definition="Border Gateway Protocol: the protocol networks use to tell their neighbours which address blocks they can reach." />, and it runs between two routers of neighbour networks. They open a TCP connection, as in module 5, to port 179, and keep it open. Over it they send UPDATE messages. One UPDATE can announce blocks, or withdraw blocks that are no longer reachable [S83].

<GoDeeper title="Go deeper: the four messages, and why a dead link takes time to notice">

RFC 4271, the BGP standard from January 2006, says that "BGP listens on TCP port 179" [S83]. TCP is the reliable conversation from 5.4: every message arrives, in order, or the connection breaks.

BGP has four kinds of message [S83]:

| Type | Name | What it does |
|---|---|---|
| 1 | OPEN | Starts the session. Each side says its own AS number |
| 2 | UPDATE | Announces blocks, or withdraws them |
| 3 | NOTIFICATION | Reports an error, and the session closes |
| 4 | KEEPALIVE | "I am still here", sent when there is nothing else to say |

One UPDATE can announce several blocks that share the same details, and in the same message withdraw blocks that are no longer reachable [S83]. A route also goes away when it is replaced by a newer one, or when the session closes [S83].

How does a router notice that its neighbour died? It waits. The standard suggests a hold time of 90 seconds: if nothing arrives for that long, the session is declared dead [S83]. So a broken cable can take a while to notice, unless the router sees the cable go down itself.

Two networks that talk BGP are external neighbours. Routers inside one network can also talk BGP to each other, and that is called internal BGP [S83]. It is still BGP between routers of one AS, not something for a home network. This module uses only the external kind. In 10.7 you will see a real session come up in the lab, with the state `Established`.

</GoDeeper>

## Each network adds its number at the front

<MermaidDiagram title="The AS path grows by one at each network" chart={`flowchart LR
  O["AS64498 announces<br>AS path: 64498"] --> M["AS64497 passes it on<br>AS path: 64497 64498"]
  M --> F["AS64496 passes it on<br>AS path: 64496 64497 64498"]
`} legend="Left to right, the same announcement three times. Each network puts its own number at the front before it passes the route to the next one. The origin, 64498, stays at the end." />

An announcement carries an <GlossaryTerm term="AS path" definition="The list of networks an announcement has crossed, newest first, with the origin network last." />. Before a network passes a route to a neighbour network, it puts its own number at the front [S83]. So you read a path from the right. The last number is the origin, the network that owns the block. Each number before it passed the route on.

<GoDeeper title="Go deeper: a real AS path from the lab">

In challenge 7 you will build three networks in a line: r1 is AS64496, r2 is AS64497, and r3 is AS64498, which owns `203.0.113.0/24`. This is what r1's BIRD program printed for that block in a recorded run:

```
203.0.113.0/24       unicast [to_r2 16:39:51.919] * (100) [AS64498i]
	via 10.0.12.2 on veth-to-r2
	Type: BGP univ
	BGP.origin: IGP
	BGP.as_path: 64497 64498
	BGP.next_hop: 10.0.12.2
	BGP.local_pref: 100
```

Read `BGP.as_path: 64497 64498` from the right. AS64498 announced it, then AS64497 passed it on. The short form `[AS64498i]` names the origin too. The line `via 10.0.12.2` says where to send the traffic: to r2, the neighbour that passed the route on.

Why does r1's own number, 64496, not appear? A network adds its number only when it sends a route out to another network [S83]. r1 will add 64496 when it passes this route on. Its own copy does not need it.

The path is also a rough measure of distance. A path of two numbers crossed two networks before it reached you. Chapter 10.4 shows that a network does not always pick the shortest one.

</GoDeeper>

## Step through four networks and a loop

<InteractiveCanvas slug="net-m10-bgp-announce" />

Press Next and watch the path grow by one number at each network. AS64499 hears the route twice, then loses its link to AS64497 and passes on the only way it has left. At the last step, AS64496 finds its own number in the path and leaves the route out [S83].

<GoDeeper title="Go deeper: the loop rule, and why the lab cannot show it">

RFC 4271 says that a route whose AS path contains the local AS number is left out of the decision [S83]. The router does not use it, and it does not pass it on. This one check is why an announcement cannot go round the internet forever. Every network on a circle would find its own number in the path.

The picture sends a copy back to AS64496 on purpose, so that the check can be seen. The order in which copies arrive is a model: on the real internet, announcements reach different networks at different moments, and a network passes on the way it knows at that moment.

Step 5 shows a second rule from the first beat. When a BGP session closes, the routes it brought are withdrawn [S83]. AS64499 does not wait for a message about each block. It forgets every route from AS64497 at once.

You will not see a loop in the lab in 10.7. BIRD, the BGP program in the lab, drops such a route without printing a message. So the loop rule lives in this chapter only. You will see its effect in another way: no path in the lab ever shows the same number twice.

</GoDeeper>

## A path with your own number goes nowhere

<MermaidDiagram title="What the loop rule prevents" chart={`flowchart LR
  A["AS64496"] -->|"64496 64497 64498"| B["AS64499"]
  B -->|"64499 64496 64497 64498"| A
  A -.->|"without the check: back to AS64499 again"| B
`} legend="Two made-up networks pass the same route back and forth. The dotted arrow is what would happen with no loop check: the route, and any traffic that follows it, goes round and round." />

Without the check, AS64496 would send traffic for the block to AS64499, and AS64499 would send it back. The packet would circle until its TTL ran out, as in 4.4. The path makes the circle visible: a network that finds its own number in a path knows the route has already passed through it [S83].

<GoDeeper title="Go deeper: a path is a record, not a promise">

The AS path tells a network which networks a route has crossed, as each one wrote it down. It does not prove that traffic will follow the same road, and it does not prove that the origin really owns the block. The networks write the path themselves, so a wrong network can claim to be the origin of a block it does not own. Chapter 10.9 shows what happens then, and 10.10 lets you do it in your own lab.

The loop check needs nothing but the path itself. That is its strength: a router does not need to trust anybody to know that its own number should not be in a route it is offered.

</GoDeeper>

## A withdrawal travels the same road

<MermaidDiagram title="AS64498 withdraws its block" chart={`flowchart LR
  O["AS64498<br>UPDATE: withdraw 203.0.113.0/24"] --> M["AS64497 forgets the route<br>and withdraws it too"]
  M --> F["AS64496 forgets the route"]
  F --> X["Traffic for 203.0.113.0/24<br>has no row and fails"]
`} legend="Left to right, the same road as the announcement. Each network forgets the route and tells its own neighbours, until nobody has a way to the block." />

This is the withdrawal from 4.5, now with a name. AS64498 sends an UPDATE that withdraws its block. Each network forgets the route and passes the withdrawal on [S83]. The addresses still exist, but nobody knows the way. In 10.7 you will withdraw a block and watch a ping fail at once.

<GoDeeper title="Go deeper: what a withdrawal looks like in the lab">

In part 2 of challenge 7, r3 stops announcing `203.0.113.0/24`. In a recorded run, r1's BIRD then answered `Network not found` for the block, and its counters showed one withdrawal received:

```
      Import withdraws:            1          0        ---          0          1
```

Linux in r1 lost the row too. Asked where it would send a packet for `203.0.113.1`, it answered:

```
RTNETLINK answers: Network is unreachable
```

Nothing was broken on r3. Its address was still there and its computer still ran. Only the announcement was gone, and with it every network's way to the block. In 7.4 you met a real outage of this kind. Chapter 10.9 comes back to it.

</GoDeeper>
