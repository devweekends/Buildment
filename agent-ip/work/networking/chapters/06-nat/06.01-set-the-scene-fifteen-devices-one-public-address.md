All your devices are connected to your router, and none of them has a public IPv4 address. So how do they talk to the internet? This module answers that question, and this chapter shows the first surprise. A server cannot tell fifteen devices apart by their source address. To the server, they are one.

## Fifteen devices, one address in the log

<InteractiveCanvas slug="net-m6-home-router-first-look" />

Fifteen devices at home, from `192.168.1.20` to `192.168.1.34`, each open a connection to the server at `203.0.113.80`. Press Next, and tap your pick when the picture asks. Every packet leaves the router with the router's outside address as its source. The server logs `203.0.113.45` fifteen times. Only the router knows which device is which.

<GoDeeper title="Go deeper: what the server can and cannot know">

A server learns about a visitor from the packets it receives. Each packet carries a source address, and the server writes that address in its log and sends the reply to it. At home, the source address of a packet starts as the device's private address, for example `192.168.1.20`. Private addresses are for use inside a network, and they are not globally reachable [S8, S9].

So the router changes the source address on the way out. It writes its own outside address in its place. This is network address translation, and the standard calls the many-devices version NAPT [S17]. The need is stated plainly in the same standard: internal addresses cannot be used outside the network [S17]. The server never sees the private address, so it cannot count the devices.

In the lab you will build later in this module, the server runs a one-line page that tells a visitor the address and port it sees. It prints the router's outside address, whichever device asks [D5.6].

<Callout type="info" title="Two stand-in addresses">
The picture uses `203.0.113.45` for the router's outside address, the same stand-in as in 1.1. The lab you build in 6.7 uses `203.0.113.1` for the same job. Both stand in for a public address and come from a range kept for examples [S10]. Your real public address is personal, so the course never prints it.
</Callout>

</GoDeeper>

## The two numbers from 1.1, again

In 1.1 your computer said `192.168.1.23`, and a website said `203.0.113.45`. Now the router between them is in the picture. Your computer used the first number. The website saw the second. The router is the only place that knows both. If your own 1.1 result was a long number with colons, or began with `100.`, 6.11 tells you what to do.

<GoDeeper title="Go deeper: see it with two of your own devices">

You can repeat the picture with two real devices. On your laptop, run this on your own computer, not in the lab:

```
curl -4 ifconfig.me
```

Then, on your phone, connected to the same home Wi-Fi, open `ifconfig.me` in the browser. Compare the two numbers. If both are IPv4 addresses, they should be the same, because both devices leave through the same router. The site is run by someone else, it is optional, and it is never graded [S52]. If one of the numbers is long and has colons, it is an IPv6 address. Module 9 explains those. Write down both numbers in your 1.1 log if you like, but do not post them. A public address is personal.

If the two numbers differ, do not worry yet. A VPN, a phone on mobile data or a second router can each change the answer. Chapter 6.4 shows how to tell which one you have.

</GoDeeper>
