In 2.1 you saw that IPv4 addresses ran out, and your laptop's address from 1.3 is something like `192.168.1.23`. No phone, laptop or router will accept `192.168.1.256`: why does each part stop at 255? The answer takes eight small switches and four short steps of arithmetic.

## One part is one byte

<InteractiveCanvas slug="net-m2-byte-bits" />

Each card is a <GlossaryTerm term="bit" definition="One place that holds 0 or 1." />. Eight bits make a <GlossaryTerm term="byte" definition="Eight bits, holding 0 to 255." />, and each bit is worth twice the one on its right. All eight on is 255. Adding one needs a ninth bit, and a byte has only eight. So 256 cannot be one part.

<GoDeeper title="Go deeper: place values and the limit of a byte">

A bit is worth its place, not its own digit. In `00010111` the bits that are on sit in the places worth 16, 4, 2 and 1, so the byte is 16 + 4 + 2 + 1 = 23. That is the last part of `192.168.1.23`.

Eight bits give 2 x 2 x 2 x 2 x 2 x 2 x 2 x 2 = 256 different patterns. Counting starts at 0, so the patterns cover 0 to 255, and the biggest is all eight on. There is no pattern left for 256.

The **Add 1** button in the picture counts up to the limit so that you can see it. At 255 the carry has nowhere to go inside one byte, so every bit falls back to 0. In a whole address the carry does have somewhere to go: the next part. `192.168.1.255` plus one is `192.168.2.0`, because the four bytes are really one 32-bit number, as the next beat shows. A byte here is unsigned, which means it has no minus sign, so its smallest value is 0.

</GoDeeper>

## Four bytes make one address

<InteractiveCanvas slug="net-m2-address-bits" />

The four parts are four bytes, so an <GlossaryTerm term="IPv4 address" definition="A 32-bit number that names one network connection, written as four numbers from 0 to 255 with dots between them." /> is 32 bits in all. Flip the last bit, which is worth 1, and `192.168.1.23` becomes `192.168.1.22`. Each row is one byte, with its value beside it. Type your own address from 1.3 and watch its bits appear.

<GoDeeper title="Go deeper: why 32 bits, and what the field accepts">

RFC 791, written in 1981, fixed an address at "four octets (32 bits)" [S1]. An octet is a group of eight bits, the same size as the byte you just played with. So there are 2^32 = 4,294,967,296 possible addresses. That is the 4.3 billion from 2.1, and the reason the supply ran out.

The picture uses the same rules as the code in 2.5. An address has exactly four parts. Each part is digits only and from 0 to 255. A part has no leading zero unless it is `0`, so this course writes `1`, not `001`. Other tools may treat leading zeros in their own way. This course does not rely on that.

The extreme addresses are worth typing in. `0.0.0.0` is the number 0. `255.255.255.255` is 4,294,967,295, the biggest 32-bit number. `128.0.0.0` has only the top bit on, which makes it 2,147,483,648.

The picture shows how an address is stored. A pasted address that breaks a rule shows a short error, and the picture does not change. It does not say whether the address is private or public. That is 2.4.

</GoDeeper>

## Three ways to write one address

<MermaidDiagram title="One address, three ways to write it" chart={`flowchart LR
  D["Dotted: 192.168.1.23"] --> S["The same 32 bits"]
  B["Bits: 11000000.10101000.<br/>00000001.00010111"] --> S
  N["One number: 3,232,235,799"] --> S
`} legend="The dotted form, the four bytes in binary and the single number are three ways to write the same 32 bits." />

Dots are for people, because four short numbers are easier to read than 32 bits. Computers store the bits, and the network only ever sees bits. Code and databases often keep an address as the one number, here 3,232,235,799, because one number is easy to sort and compare. Change one form and the other two change with it, because they are the same 32 bits.

<GoDeeper title="Go deeper: the worked example, both directions">

Take `192.168.1.23` one part at a time. Each part uses the place values 128, 64, 32, 16, 8, 4, 2 and 1.

- 192 = 128 + 64, so the bits are `11000000`.
- 168 = 128 + 32 + 8, so the bits are `10101000`.
- 1 = 1, so the bits are `00000001`.
- 23 = 16 + 4 + 2 + 1, so the bits are `00010111`.

To get the one number, the first part counts 16,777,216 times, the second 65,536 times, the third 256 times and the last once: 192 x 16,777,216 + 168 x 65,536 + 1 x 256 + 23 = 3,232,235,799. Each weight is 256 times the next one, because each part is one byte, which has 256 patterns. A smaller address works the same way: `10.0.0.1` is 10 x 16,777,216 + 1 = 167,772,161.

To go back, divide by 16,777,216 and keep the whole number: 3,232,235,799 gives 192, with 11,010,327 left. Divide that by 65,536: 168, with 279 left. Divide 279 by 256: 1, with 23 left. The four answers are 192, 168, 1 and 23.

Code often keeps the number form. Exercise 2.5 asks you to write `ipToNumber` and `numberToIp`, and it warns about a JavaScript trap with the top bit. The details are there, not here.

</GoDeeper>

## Now do it by hand

<InteractiveCanvas slug="net-m2-address-drill" />

Write 128, 64, 32, 16, 8, 4, 2, 1. Take the biggest value that fits, subtract it, and repeat with what is left. Do the five questions with no calculator, and tap or choose each answer yourself. After each answer, the picture shows the sum.

<GoDeeper title="Go deeper: the hand method twice, and three near misses">

Convert 172 to bits. 128 fits, and 44 is left. 64 does not fit. 32 fits, and 12 is left. 16 does not fit. 8 fits, and 4 is left. 4 fits, and nothing is left. 2 and 1 are not needed. Writing a 1 where a value was used and a 0 where it was not gives `10101100`.

Go back to check it: 128 + 32 + 8 + 4 = 172. Checking in the other direction takes ten seconds and catches most slips. A second check is the count of bits: every byte has exactly eight, so write the leading zeros. The number 10 is `00001010`, not `1010`.

Three near misses are common.

- **The dots are not digits.** `192.168.1.23` is not the decimal number 192168123. Each part is a separate byte, and the weights are 16,777,216, 65,536, 256 and 1.
- **A part above 255.** `192.168.1.256` cannot exist, because 256 needs a ninth bit. `172.16.300.4` cannot exist for the same reason.
- **Leading zeros.** This course writes `1`, never `001`, and its tools reject the second form. What other tools do with a leading zero is their own rule.

</GoDeeper>

In 2.3 you will use these bits to see how the internet decided which addresses go to whom, and why its first plan failed.

<GoDeeper title="Sources">

[S1] RFC 791, Internet Protocol (September 1981): "Addresses are fixed length of four octets (32 bits)." The totals 2^32 = 4,294,967,296 and the examples above are arithmetic, checked by script. The bit patterns and place values are the standard way to write a number in binary.
