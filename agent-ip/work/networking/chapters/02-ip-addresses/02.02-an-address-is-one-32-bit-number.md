## One part is one byte

<InteractiveCanvas slug="net-m2-byte-bits" />

Each card is a <GlossaryTerm term="bit" definition="One place that holds 0 or 1." />, and eight bits make a <GlossaryTerm term="byte" definition="Eight bits, holding 0 to 255." />. Each bit is worth twice the one on its right, so all eight on is 255. Press **Add 1** at 255: the carry needs a ninth bit, and there is none. So no part of an address goes above 255.

<GoDeeper title="Go deeper: place values and the limit of a byte">

A bit is worth its place, not its own digit. In `00010111` the bits that are on sit in the places worth 16, 4, 2 and 1, so the byte is 16 + 4 + 2 + 1 = 23. That is the last part of `192.168.1.23`.

Eight bits give 2 x 2 x 2 x 2 x 2 x 2 x 2 x 2 = 256 different patterns. Counting starts at 0, so the patterns cover 0 to 255, and the biggest is all eight on. There is no pattern left for 256.

The **Add 1** button counts up to the limit so that you can see it. At 255 the carry has nowhere to go inside one byte, so every bit falls back to 0. In a whole address the carry does have somewhere to go: the next part. `192.168.1.255` plus one is `192.168.2.0`, because the four bytes are really one 32-bit number, as the next beat shows. A byte here is unsigned, which means it has no minus sign, so its smallest value is 0.

</GoDeeper>

## Four bytes make one address

<InteractiveCanvas slug="net-m2-address-bits" />

The four parts are four bytes, so an <GlossaryTerm term="IPv4 address" definition="A 32-bit number that names one network connection, written as four numbers from 0 to 255 with dots between them." /> is 32 bits in all. The big number under the rows reads all 32 bits as one number. So one more than `.255` rolls into the next part. Type your own address from 1.3.

<GoDeeper title="Go deeper: why 32 bits, and one address as one number">

RFC 791, written in 1981, fixed an address at "four octets (32 bits)" [S1]. An octet is a group of eight bits, the same size as the byte you just played with. So there are 2^32 = 4,294,967,296 possible addresses. That is the 4.3 billion from 2.1, and the reason the supply ran out.

The dots are for people: four short numbers are easier to read than 32 bits. Computers store the bits, and code and databases often keep an address as one number, because one number is easy to sort and compare. The four parts have weights. The first part counts 16,777,216 times, the second 65,536 times, the third 256 times and the last once. Each weight is 256 times the next one, because each part is one byte. So `192.168.1.23` is 192 x 16,777,216 + 168 x 65,536 + 1 x 256 + 23 = 3,232,235,799, and `10.0.0.1` is 10 x 16,777,216 + 1 = 167,772,161. Nobody does the big multiplications by hand; code exercise 2.5 asks you to write `ipToNumber` and `numberToIp`, and warns about a JavaScript trap with the top bit.

The picture uses the same rules as the code in 2.5. An address has exactly four parts. Each part is digits only and from 0 to 255. A part has no leading zero unless it is `0`, so this course writes `1`, not `001`. Other tools may treat leading zeros in their own way. This course does not rely on that.

The extreme addresses are worth typing in. `0.0.0.0` is the number 0. `255.255.255.255` is 4,294,967,295, the biggest 32-bit number. `128.0.0.0` has only the top bit on, which makes it 2,147,483,648. The picture shows how an address is stored. It does not say whether the address is private or public: that is 2.4.

</GoDeeper>

## Walk the places, subtract what fits

<MermaidDiagram title="Reading 172 as bits by subtracting" chart={`flowchart TD
  S["172"] --> A["128 fits: write 1, 44 left"]
  A --> B["64 is too big: write 0"]
  B --> C["32 fits: write 1, 12 left"]
  C --> D["16 is too big: write 0"]
  D --> E["8 fits: write 1, 4 left"]
  E --> F["4 fits: write 1, 0 left"]
  F --> G["2 and 1: write 0, 0"]
  G --> R["172 = 10101100"]
`} legend="Walk the place values from 128 down to 1. Each value that fits becomes a 1 and is subtracted; each value that does not fit becomes a 0." />

Start at 128 and walk right. If the place value fits in what is left, write 1 and subtract it; if not, write 0. So 172 becomes `10101100`. The same walk works for every number from 0 to 255. Check by adding the 1s back: 128 + 32 + 8 + 4 = 172. The questions below use exactly this walk.

<GoDeeper title="Go deeper: the walk again, and both directions">

Convert 23. 128, 64 and 32 are too big, so the first three bits are 0. 16 fits, and 7 is left. 8 is too big. 4 fits, and 3 is left. 2 fits, and 1 is left. 1 fits, and nothing is left. So 23 is `00010111`, the last byte of `192.168.1.23`.

Going from bits to a number is the walk backwards: add the place values of the bits that are on. `11000000` is 128 + 64 = 192. `10101000` is 128 + 32 + 8 = 168.

Always write all eight bits, leading zeros included. The number 10 is `00001010`, not `1010`, because every part of an address is exactly one byte. Checking in the other direction takes ten seconds and catches most slips.

</GoDeeper>

## Five conversions, no calculator

<InteractiveCanvas slug="net-m2-address-drill" />

Use the same walk for each question: tap the bits for a number, read a byte from its bits, or spot an address that cannot exist. After each answer, the picture adds the place values up so you can see where a slip happened.

<GoDeeper title="Go deeper: three near misses">

- **The dots are not digits.** `192.168.1.23` is not the decimal number 192168123. Each part is a separate byte with its own weight.
- **A part above 255.** `192.168.1.256` cannot exist, because 256 needs a ninth bit. Any part from 256 up fails the same way.
- **Leading zeros.** This course writes `1`, never `001`, and its tools reject the second form. What other tools do with a leading zero is their own rule.

</GoDeeper>

In 2.3 you will use these bits to see how the internet decided which addresses go to whom, and why its first plan failed.

<GoDeeper title="Sources">

[S1] RFC 791, Internet Protocol (September 1981): "Addresses are fixed length of four octets (32 bits)." The totals 2^32 = 4,294,967,296 and the examples above are arithmetic, checked by script. The bit patterns and place values are the standard way to write a number in binary.

</GoDeeper>

  - "Right. The last byte cannot hold 256, so it rolls over to 0 and the carry moves into the next part, the same way the byte picture rolled over at 255."
