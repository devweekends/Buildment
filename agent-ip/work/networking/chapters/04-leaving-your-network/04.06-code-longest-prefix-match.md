In 4.3 you chose routes by eye. A router makes the same choice for every packet, so the choice has to be a rule that a program can follow. In this chapter you turn the table rule into a function. The rule is only three comparisons in a fixed order, and once you can see them, the code is short.

By the end you will have one tested function, `lookup`. It takes a table and a destination and returns the row that a router would use. The pictures in 4.3 follow the same rules as your tests, so what you saw there is what your code must do.

## What the function gets and what it returns

The table is an array of rows. Each row is an object with four fields. The field `prefix` is a dotted string, such as `"10.1.0.0"`. The field `length` is a number from 0 to 32, which is the `/n` of the row. The field `nextHop` is a dotted string, or `null` for a connected row, which has no next hop. The field `metric` is a number. The destination is a dotted string too.

The function returns the row object itself, the same object that is in the array, so a test can check which row you chose. If no row holds the destination, it returns `null`. A row with the prefix `"0.0.0.0"` and the length 0 is the default route, and it holds every address.

Bad input throws an `Error` whose message starts with `invalid address`. You do not have to write the checks. The starter code gives you `ipToNumber`, the function from 2.5, with all its checks. If you prefer your own version from 2.5, paste it in its place. Chapter 2.5 explains why the result must stay unsigned, and the same care matters here.

## Three comparisons, in a fixed order

Start with the whole plan, because the code follows it step by step. For every row, the first question is whether the row holds the destination at all. If it does not, the row is out. Among the rows that hold it, the longest prefix wins. If two rows have the same length, the lower metric wins. If the metrics are equal too, the row that comes first in the list wins. That last step is not a fact about routers. It is a rule of this exercise, so that your function gives exactly one answer.

The takeaway: you never sort the table. You walk it once, and you keep the best row so far. Each new row that holds the destination is compared with the best row by length first, then by metric. A row that ties on both leaves the earlier row in place, and that is exactly the "first listed" rule.

## How to test whether a row holds the destination

You did this test by hand in 3.2, with the address and the mask. A row holds the destination when the destination, after the row's mask, equals the row's network. For the row `10.1.0.0/16` the mask is `255.255.0.0`. The destination `10.1.2.3` becomes `10.1.0.0`, which is the row's network, so the row holds it.

In code, the mask for a length `n` is a number whose top `n` bits are on and whose other bits are off. You make it by shifting 32 bits that are all on to the left. Here is a worked example for a block that is not in the tests: the private block `172.16.0.0/12`. The shift is `32 - 12 = 20` places. The bits `0xffffffff` shifted left by 20 give `255.240.0.0`. The destination `172.20.5.5` becomes `172.16.0.0` after this mask, which is the network of the row. So the row holds it. An address whose second number is 32 or more becomes a different network, so the row does not hold it. This is the edge you saw in 2.4, where `172.16.0.0/12` ends at `172.31.255.255`.

```js
(0xffffffff << 20) >>> 0   // 4293918720, which is 255.240.0.0, the /12 mask
```

You apply the same mask to the row's prefix as well. That matters, and the next section shows why.

<Callout type="warning" title="In JavaScript, a shift by 32 does nothing">
A shift count is taken modulo 32. So `x << 32` gives the same result as `x << 0`. For the row with length 0, the shift would be `32 - 0 = 32`, and a mask built this way turns out to be all ones, not all zeros.
</Callout>

## The /0 trap and the host-bits trap

The default route has length 0, and its mask must be zero: no bits are compared, so every address matches. If you build the mask as `(0xffffffff << (32 - n)) >>> 0` and give it `n = 0`, the shift is 32, the count wraps to 0, and the mask is all ones. The default route then holds only the single address `0.0.0.0`. The tests include a destination of `255.255.255.255` against a default row, and the buggy mask fails it. The fix is one line: treat length 0 as its own case and use the mask 0.

The second trap is a prefix with host bits set. A person may write the row as `10.1.9.9/16`, which is not the network address of the block. The row means the whole `/16`, so the part after the first 16 bits must be ignored. If you compare the destination after the mask with the raw prefix, the two never match, because the raw prefix still has its host bits. So mask the prefix with the same mask first, and compare the two masked numbers. One of the tests uses exactly this row.

## Four ways this goes wrong

**The default route matches nothing.** This is the `/0` trap above. If your function returns `null` for `203.0.113.80` when a default row exists, check how you build the mask for length 0.

**The first match wins.** If you return the first row that holds the destination, you get the `/8` for `10.1.2.3`, which is the mistake that 4.3 warned about. Keep the best row and compare the length. The tests list the `/8` before the `/16` on purpose.

**The metric beats the length.** A row with a very low metric and a short prefix must still lose to a row with a longer prefix. Compare the length first, and use the metric only when the lengths are equal. One test gives the longer prefix a high metric, to catch this.

**A negative number.** The shift gives a negative result when the top bit is on. A negative number is never equal to the unsigned number you get from `ipToNumber`, so the comparison fails for many addresses. End the mask with `>>> 0`, and end the masked addresses with `>>> 0` as well.

  function ipToNumber(ip) {
    if (typeof ip !== "string") throw new Error("invalid address: not text");
    const parts = ip.split(".");
    if (parts.length !== 4) throw new Error("invalid address: need four parts, got " + parts.length);
    let total = 0;
    for (const part of parts) {
      if (!/^(0|[1-9][0-9]{0,2})$/.test(part)) throw new Error("invalid address: bad part '" + part + "'");
      const value = Number(part);
      if (value > 255) throw new Error("invalid address: " + value + " is more than 255");
      total = (total << 8) | value;
    }
    return total >>> 0;
  }

  function lookup(routes, destination) {
    const dest = ipToNumber(destination);
    let best = null;
    for (const route of routes) {
      const mask = route.length === 0 ? 0 : (0xffffffff << (32 - route.length)) >>> 0;
      const network = (ipToNumber(route.prefix) & mask) >>> 0;
      if (((dest & mask) >>> 0) !== network) continue;
      if (best === null || route.length > best.length || (route.length === best.length && route.metric < best.metric)) best = route;
    }
    return best;
  }
