Your trace crossed networks that different organisations run. Who tells your router where `203.0.113.0/24` is? An autonomous system is a connected group of address blocks with one routing policy [S68]. Networks announce which blocks they can reach. If an announcement disappears, the row disappears with it, and traffic to those addresses fails.

## Networks announce what they can reach

<MermaidDiagram title="An announcement travels from C to A" chart={`flowchart LR

  B -->|"passes the announcement on"| A["Network A"]
  A --> T["A's new row: 203.0.113.0/24 via B"]
`} legend="Networks A, B and C are made up. C announces the block it owns to B, B passes it to A, and A adds a row that points at B." />

Networks A, B and C are made up. C owns `203.0.113.0/24` and announces it to B. B passes the announcement to A. Now A has a row: `203.0.113.0/24` via B. Each network is an <GlossaryTerm term="autonomous system" definition="A connected group of address blocks, run by one or more operators, with one clear routing policy." />.

<GoDeeper title="Go deeper: what an announcement is, and what this picture is not">

RFC 1930 defines an autonomous system as a connected group of IP prefixes, run by one or more operators, with a single clearly defined routing policy [S68]. In plain words, it is a part of the internet that one organisation, or a few working together, decides how to route.

An announcement tells a neighbour: you can send traffic for this block to me. The neighbour can pass it on, so the row travels outward from the network that owns the block. At each step the receiving network adds a row whose next hop is the network it heard from. This is how A ends up with `203.0.113.0/24` via B, as in 4.3.

The networks in the picture have letters, not numbers, because they are made up. The protocol that carries these announcements has a name, BGP. Module 10, in Part 2 of the course, gives real networks their numbers and lets you run three networks that talk BGP.

<Callout type="info" title="This is not your router">
The picture shows how large networks learn rows. Your own router in 4.7 does not do this: you will write its rows by hand.
</Callout>

</GoDeeper>

## When an announcement disappears

<MermaidDiagram title="C withdraws the block" chart={`flowchart LR
  C["Network C: withdraws 203.0.113.0/24"] -->|"no announcement"| B["Network B: drops its row"]
  B -->|"no announcement"| A["Network A: drops its row"]
  A --> F["Traffic for 203.0.113.0/24 has no row, and fails"]
`} legend="When C stops announcing the block, B and A lose their rows one after the other. Traffic for those addresses then has nowhere to go." />

Now C withdraws its announcement, for example after a mistake. B drops the row, then A drops it. A has no row for `203.0.113.0/24` any more, so traffic for those addresses fails. The addresses still exist. Nobody knows the way to them.

<GoDeeper title="Go deeper: a real case">

This happens in real life. On 14 July 2025 an internal configuration error at Cloudflare withdrew the address blocks of its 1.1.1.1 resolver from the internet, for about an hour [S50]. Other networks lost their rows for those addresses, so queries that went to 1.1.1.1 failed. Traffic that used different addresses, such as DNS over HTTPS with its own host names, was mostly unaffected [S50].

<RealWorldEvent title="Cloudflare's 1.1.1.1 blocks are withdrawn" when="14 July 2025" summary="An internal configuration error withdrew the 1.1.1.1 address blocks from the internet for about an hour." lesson="With no announcement, other networks had no row for those addresses, so traffic to them failed. The addresses did not disappear. The way to them did." />

Names and routes depend on each other. A name needs an address, and an address needs a route. If the route is withdrawn, a working name server can still be unreachable. Later in the course you will meet a second incident that makes the same point.

</GoDeeper>
