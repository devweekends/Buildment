Two browser tabs talk to the same website, on port 443. Both replies come back to your one address. How does your laptop tell them apart?

## Two tabs, one address

<InteractiveCanvas slug="net-m5-scene-two-tabs" />

Two tabs ask the same website for a page. Both replies come back to the same laptop address, 192.168.1.23. Yet each page reaches the right tab, never the other one. Something in each reply says which tab it is for. Watch the numbers on the arrows. They are the clue.

<GoDeeper title="Go deeper: two connections, one address">

The picture shows two connections from one laptop. A real browser may let two tabs share one connection, so this course says two connections here and does not claim that every tab opens its own. What matters is the idea: when several conversations share one address, something else must tell them apart.

The numbers 51234 and 51236 are chosen for the drawing. A real computer picks its own. The website's port, 443, is the number the website listens on. Every tab that wants this website sends to it, so the website's port is the same for both tabs. The laptop's number is the one that differs.

The website and its address, 203.0.113.80, are made up. The address comes from a block set aside for examples, so it should not appear on the public internet [S10].

</GoDeeper>

## A port names an app on your computer

<InteractiveCanvas slug="net-m5-sockets-ports" />

An address finds a computer. A <GlossaryTerm term="port" definition="A number from 0 to 65535 that names one app on a computer." /> finds one app on it. Tab 1 gets port 51234, tab 2 gets port 51236, and the chat app gets port 40000. Press Next and watch the laptop fill its table. At the end, a chat message comes back, and the port in it picks the chat app.

<GoDeeper title="Go deeper: server ports and client ports">

A port is a 16-bit number [S25, S26], so it runs from 0 to 65535. Two kinds of ports appear in every conversation.

A server listens on a port that clients know in advance. In our pictures the website uses 443 and the chat server uses 5222. A client app does not need a fixed port. Its computer gives it a free one for the length of the conversation. That is why the three apps on the laptop have the ports 51234, 51236 and 40000. A port that the system hands out for a short time is called an ephemeral port.

The table in the picture is the idea. On a real computer, `ss -tn` and `netstat -an` list it, as you saw in chapter 5.1. The system ports are the numbers 0 to 1023 [S27]. The lab README notes that ports below 1024 need extra rights on many systems, which is one reason the lab in chapter 5.6 uses port 8080.

</GoDeeper>

## Five numbers name one conversation

<InteractiveCanvas slug="net-m5-five-numbers" />

A conversation is named by five numbers: the protocol, two addresses and two ports. Tab 1 and tab 2 match in four of them, so one number does all the work. A <GlossaryTerm term="socket" definition="One end of a conversation: an address and a port." /> is one end, so a connection is a pair of sockets [S25]. Pick the number that differs.

<GoDeeper title="Go deeper: a connection is a pair of sockets">

The standard for TCP says that a connection is defined by a pair of sockets [S25]. A socket is an address and a port. So the laptop's end is 192.168.1.23 with port 51234, and the website's end is 203.0.113.80 with port 443. Add the protocol, TCP here, and you have the five numbers. UDP ports have the same size [S26], so the same five numbers name a UDP conversation too.

Look at the two rows in the picture. The protocol, the laptop's address, the website's address and the website's port are the same in both. Only the laptop's port differs. This is why two conversations from one laptop to the same website and port need different laptop ports. If two conversations to the same website used the same laptop port, all five numbers would match, and the laptop could not tell them apart.

</GoDeeper>

## Replies find their socket by number

<InteractiveCanvas slug="net-m5-match-replies" />

Six replies arrive at the laptop, and each one carries a port. The laptop reads that port and hands the reply to the socket that owns it. Now do the laptop's job: drop each reply on its socket. A wrong try tells you which number to read again. Both tabs talk to the same website, so look at the port the reply is addressed to, not at the sender.

<GoDeeper title="Go deeper: what a real system compares">

The exercise uses the port alone, because every reply belongs to a conversation the laptop has already opened. A real system looks at more. When a packet arrives, it reads the protocol, the two addresses and the two ports from the packet's header, as you saw in chapter 1.5. Then, for a TCP connection that is already open, it looks for the socket with the same five numbers [S25]. If there is none, and no app listens on that port, no app gets the packet.

So a right port is not always enough. A reply that comes from the wrong address does not match the socket, even if its port is right.

</GoDeeper>

## Port ranges: IANA and Linux differ

<MermaidDiagram title="Two sets of port ranges" chart={`flowchart LR
  subgraph I["IANA ranges"]
    I1["System: 0 to 1023"] --> I2["User: 1024 to 49151"] --> I3["Dynamic: 49152 to 65535"]
  end
  subgraph L["Linux default for client ports"]
    L1["32768 to 60999"]
  end
  P["Port 40000"] -.->|"inside"| L1
  P -.->|"outside"| I3
`} legend="Top: the three IANA ranges, from 0 to 65535. Bottom: the range Linux uses by default for the ports it hands to client apps. Port 40000 is inside Linux's range and outside IANA's dynamic range." />

The IANA rules set system ports 0 to 1023, user ports 1024 to 49151, and dynamic ports 49152 to 65535 [S27]. Linux hands out its own <GlossaryTerm term="ephemeral port" definition="A port the system picks for a client for a short time." /> from 32768 to 60999 by default [S28]. Port 40000 is inside Linux's range but outside IANA's dynamic range. The two ranges differ.

<GoDeeper title="Go deeper: a rule and a setting">

Read the standard once, in the original. It is short, and it is the source for the three ranges.

<MustRead title="RFC 6335, the port number ranges" url="https://www.rfc-editor.org/rfc/rfc6335.txt" source="IETF RFC 6335" description="Find the section that sets the system, user and dynamic port ranges. Afterwards you can say where the dynamic range starts and where it ends." readMinutes={5} />

The two ranges do two different jobs. The IANA ranges are a rule for how port numbers are handed out: system ports 0 to 1023, user ports 1024 to 49151, and dynamic or ephemeral ports 49152 to 65535 [S27]. The Linux range is a setting. The kernel documents it as `ip_local_port_range`, and its default is 32768 to 60999 [S28]. So a Linux client can use a port that IANA does not call dynamic.

The recorded capture in chapter 5.6 shows two real laptop ports, 48158 and 48172. Both sit inside Linux's range, and both are below 49152, so both are outside IANA's dynamic range. Windows and macOS use ranges of their own. This course gives no numbers for them, because it has no source for them. Look up your own system if you want to know.

</GoDeeper>

<GoDeeper title="Sources">

[S25] RFC 9293, Transmission Control Protocol: 16-bit ports, and a connection is defined by a pair of sockets. [S26] RFC 768, User Datagram Protocol: 16-bit ports, protocol number 17.
