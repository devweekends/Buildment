Your laptop has one address. Forty browser tabs, a music app and a chat app are all talking at once. When a reply arrives, how does it find the right app? Every conversation already has a name you can see, and your computer keeps a table of them.

## One line is one conversation

<MermaidDiagram title="One line of your list, read left to right" chart={`flowchart LR
  A["Me<br>192.168.1.23 : 51234"] --> B["Them<br>203.0.113.80 : 443"]
  B --> C["State<br>ESTABLISHED"]
`} legend="Left: my address and port. Middle: their address and port. Right: the state of the conversation. The numbers are an example from a made-up laptop. Your list will show other numbers." />

Each line of the list is one conversation. Read it from left to right: my address and port, their address and port, then the state. An <GlossaryTerm term="established connection" definition="An open conversation: both sides have finished starting it." /> is one that is open. Run the command for your computer, then read one line aloud.

```
# Windows and macOS
netstat -an
# Linux
ss -tn
```

<GoDeeper title="Go deeper: the same line on Linux">

Run these on your own computer, not in the lab. The lab is a small made-up network with almost no conversations, so your own list is the better place to look.

<Callout type="info" title="Your list will look different">
Column names and state words differ between operating systems, and this course has not recorded a macOS list. Match the pattern, not the names: an address and a port, another address and a port, and a state. Lines with long addresses full of colons are IPv6 [S4] and are normal.
</Callout>

Here is a real list from a Linux computer in the course lab, so you can see the shape. It has only one open conversation. Yours will have more lines.

```
State Recv-Q Send-Q Local Address:Port  Peer Address:PortProcess
ESTAB 0      0       192.168.1.23:48172 192.168.1.80:8080
```

`ESTAB` is the state, short for established. `Local Address:Port` is the first end, and `Peer Address:Port` is the other end. The two numbers after the state are not needed here.

</GoDeeper>

## Your computer keeps a table of them

<MermaidDiagram title="A table of conversations, one row each" chart={`flowchart LR
  subgraph T["The table on the laptop 192.168.1.23"]
    R1["Tab 1: port 51234 to 203.0.113.80 port 443"]
    R2["Tab 2: port 51236 to 203.0.113.80 port 443"]
    R3["Music app: port 51240 to 198.51.100.7 port 443"]
    R4["Chat app: port 40000 to 192.0.2.44 port 5222"]
    R5["... and more rows"]
  end
`} legend="Four rows of a table that may hold forty. Each row has an address and a port on each end. The numbers are an example." />

Every tab, music app and chat app is a row in this table. A busy computer can have many rows. Each row has an address and a <GlossaryTerm term="socket" definition="One end of a conversation: an address and a port." /> on each end. When a reply arrives, the computer finds its row. Chapter 5.2 shows how.

<GoDeeper title="Go deeper: why the number of rows is not fixed">

The number forty is a figure of speech. Your own list may have more lines or fewer. This course gives no average, because the right number to look at is the one on your screen.

The address on the left is the same in every row. That is the point of this chapter: one computer, one address, many conversations. What differs between rows is the port. A port is a number from 0 to 65535 that names one app on a computer, because the standards give it 16 bits [S25, S26]. The next chapter uses it to tell the rows apart.

</GoDeeper>
