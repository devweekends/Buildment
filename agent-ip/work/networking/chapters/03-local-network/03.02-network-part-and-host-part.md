Your laptop sends directly to `192.168.1.40`, but sends toward a router for `192.168.2.40`. Its own mask makes that decision. [S7]

## Send direct, or through the router?

<MermaidDiagram title="Compare two network results" chart={`flowchart TD
 A["My address AND my mask"] --> C{"Same network result?"}
 B["Destination AND my mask"] --> C
 C -->|Yes| L["Send directly to neighbour"]
 C -->|No| G["Need a route through a gateway"]`} legend="The host applies its own mask to both addresses before comparing." />

The laptop compares two results: its own address with its mask, and the destination with that same mask. Matching results mean the destination is local. Different results mean it needs a route beyond the local network, usually through a gateway. This comparison uses the sender's settings; it does not ask the destination for its mask. [S7]

<GoDeeper title="Go deeper: send direct, or through the router?">

AND is a bit operation. At each position its result is 1 only when both input bits are 1. A mask therefore preserves some address bits and clears the others. The next pictures show this operation one position at a time.

The diagram's gateway branch describes the next need, not a promise of delivery. If no route exists, the host cannot send to that remote address. You will see that failure in 3.9. For now, separate the boundary decision from the later job of getting a packet to another network. [S7]

</GoDeeper>

## The mask marks the network part

<InteractiveCanvas slug="net-m3-mask-bits" />

Drag the prefix length and watch the mask change beside the address. The 1 bits mark the network part; the remaining positions hold the host part. A /24 fixes 24 bits and leaves eight host bits, while /20 fixes 20 and leaves twelve. The boundary can fall inside a byte, so the dots do not decide where it belongs.

<GoDeeper title="Go deeper: the mask marks the network part">

This course uses contiguous masks: all the 1 bits come first, followed by all the 0 bits. RFC 950 recommends that arrangement. We do not practise masks with gaps. [S7]

For /24 the mask is 255.255.255.0. For /20 it is 255.255.240.0. The third byte of the second mask is 11110000. Only its first four positions belong to the network; its last four belong to hosts. That is why a rule based on matching the first three dotted numbers fails.

There are two choices for each host bit, so eight free bits give 256 addresses. Twelve give 4,096. These are total addresses, before deciding which can be assigned to ordinary hosts.

</GoDeeper>

## AND with the mask gives the network

<InteractiveCanvas slug="net-m3-mask-and" />

Flip address bits and watch the row below the AND operation. A bit under a mask 1 survives, while a bit under a mask 0 becomes zero. The resulting network address is the first address of the block. Changing only host bits leaves that result unchanged, which is why many different device addresses can belong to the same network. [S7]

<GoDeeper title="Go deeper: and with the mask gives the network">

For 192.168.1.23/24, the last byte is cleared and the network address is 192.168.1.0. A destination such as 192.168.1.40 gives the same result. Applying the same /24 to 192.168.2.40 gives 192.168.2.0, a different network.

Now use the campus example. In 10.20.143.7/20, 143 is 10001111. AND it with 11110000, the third mask byte. The result is 10000000, which is 128. The fourth byte becomes zero. The network address is therefore 10.20.128.0. The address and the network are different values because the original host bits were not all zero.

</GoDeeper>

## Host bits all 1 give the broadcast

<InteractiveCanvas slug="net-m3-broadcast" />

Turn all the host bits on and read the other end of the block. For an ordinary subnet, that end is its broadcast address; the network address is the first end. The assignable host range lies between those two ends. Read both limits before counting hosts, because a block's total size includes addresses that are not ordinary host addresses.

<GoDeeper title="Go deeper: host bits all 1 give the broadcast">

For 192.168.1.23/24, the broadcast address is 192.168.1.255. The ordinary host range is 192.168.1.1 through 192.168.1.254. That is 254 hosts inside 256 total addresses.

For the campus /20, set the four host bits in the third byte to 1. The byte becomes 10001111, or 143. Set the fourth byte to all 1s as well. The last address is 10.20.143.255; the ordinary hosts run from 10.20.128.1 to 10.20.143.254. There are 4,096 total addresses and 4,094 ordinary host addresses.

These endpoints follow directly from bit arithmetic. Do not subtract two blindly for every prefix. The edge cases below need their own meanings.

</GoDeeper>

## A /23 spans two third bytes

<InteractiveCanvas slug="net-m3-wide-mask" />

Type a destination into the /23 picture and watch the local result. The block for `192.168.1.23/23` starts at `192.168.0.0` and ends at `192.168.1.255`. Therefore `192.168.0.40` is local even though its third number differs from the laptop's. The mask keeps seven bits of that third byte, allowing the remaining bit to change inside one network.

<GoDeeper title="Go deeper: a /23 spans two third bytes">

A /23 leaves nine host bits: one in the third byte and all eight in the fourth. Its size is 512. The third mask byte is 254, or 11111110. Both 0 AND 254 and 1 AND 254 are 0, so third bytes 0 and 1 share this network.

Try a destination whose third byte is 2. Its network starts at 192.168.2.0, outside the displayed block. This gives you a counterexample to the first-three-numbers shortcut without changing the address format. You still compare two complete network results.

</GoDeeper>

## The edges: /31, /32 and /0

<MermaidDiagram title="Three edge prefixes" chart={`flowchart TD
 P["Prefix length"] --> A["/32: one address; both numeric ends equal"]
 P --> B["/31: two endpoints on a point-to-point link"]
 B --> C["No directed broadcast on that link"]
 P --> D["/0: all 4,294,967,296 IPv4 addresses"]`} legend="Total size comes from free bits; ordinary host reservations do not apply uniformly." />

A /32 leaves no host bits, so its range contains exactly one address. A /31 leaves one bit and can number two ends of a point-to-point link, without a directed broadcast. [S70] A /0 fixes no bits and spans the whole IPv4 number space. Keep numeric range endpoints separate from what a network uses an endpoint for.

<GoDeeper title="Go deeper: the edges: /31, /32 and /0">

The /31 rule is specifically for point-to-point links, with just two ends. It does not turn an ordinary shared network into a two-host subnet by applying the usual broadcast convention. For 192.168.1.4/31 the two endpoints are .4 and .5. Both can be used on that link. [S70]

In the calculator exercise, broadcast() returns the high numeric endpoint even for /31 and /32. That is a stated programming convention, not a claim that those prefixes have an ordinary directed broadcast. For /0 the numeric endpoints are 0.0.0.0 and 255.255.255.255. The total size needs a number large enough to hold 2 to the power 32.

</GoDeeper>

## Network and broadcast by hand

<InteractiveCanvas slug="net-m3-mask-drill" />

Answer each drill before opening its feedback, using the bit rows to explain your result. Find the network first, set the host bits for the high endpoint, then compare a destination using the same mask. If a result is wrong, identify the first bit where your calculation differs. This gives you a correction you can reuse on the next address.

<GoDeeper title="Go deeper: network and broadcast by hand">

Write the prefix and the number of free bits before doing any arithmetic. That small note separates /20 from a block with twenty host bits. Then find both endpoints, including the final byte, even if the changing boundary is in the third byte.

Check your answer by counting: last minus first plus one must equal the total size. For a local decision, repeat the AND for the destination. Do not compare a destination with an arbitrary host address. Compare network results.

Sources: [S1] RFC 791, 32-bit addresses; [S7] RFC 950, the mask and local decision. [S70] The /31 point-to-point rule cited in the supplied brief. All worked ranges are derived arithmetic.

</GoDeeper>
