You can already read your own numbers, from chapter 1.1. Now you will write them into a file and let a script read them back. A script that reads your numbers and checks them is the first real tool you use in this course. On the way you learn seven commands. They are enough for every challenge that follows.

By the end you will have a file called `my-numbers.txt` with five lines and a checker that prints `PASS`. One line of the output shows your mask written the short way. That short form is called a prefix, and you will use it in every module from now on.

## Why a command line at all

A command line is a way to ask a computer a question in exact words and get an exact answer. You type a command, the computer runs it, and the text it prints is the whole answer. There is no menu to find and no screen that changes between versions. The same words give the same result for you, for a mentor and for a fellow on the other side of the world. That is why a checker can be a short script, and why you can paste its output into a message when you are stuck.

Seven commands are enough. You will not need to memorise a manual. You will type each one a few times in this chapter, and by the end of the module you will type them from memory.

## The seven commands

The lab is a Linux computer, so these commands are Linux commands. Windows has similar ones, but you do not need them, because you type them at the `(lab)` prompt. The table lists them. The paragraphs after it explain why each one is worth knowing.

| Command | What it does |
|---|---|
| `cd folder` | Go into a folder |
| `ls` | List what is in the folder |
| `cat file` | Show what is in a file |
| `nano file` | Edit a file. Save with Ctrl+O then Enter. Leave with Ctrl+X |
| `Ctrl+C` | Stop a command that is still running |
| `exit` | Leave the lab |
| `sudo` | Run a command as root. Not needed in the lab |

The first three are about looking around. `cd` moves you into a folder, so that the commands that follow work on the files there. `ls` lists what is in the folder, so you know what you can work with. `cat` prints a file on the screen. When something goes wrong, `cat` is how you check what a file really contains, and not what you think it contains. This habit will save you many times in the course.

`nano` is a small editor that runs inside the terminal. You open a file with `nano my-numbers.txt`, type, press Ctrl+O and then Enter to save, and press Ctrl+X to leave. It is not the best editor in the world, but it is always in the lab, and it never needs a mouse.

`Ctrl+C` stops a command that is still running. Some commands, such as `ping`, run until you stop them. If the lab seems stuck, press Ctrl+C first. `exit` leaves the lab and returns you to your own computer. Because the lab is deleted when you leave, you can always start again from a clean place.

The last one, `sudo`, needs more care. On Linux, a few commands are only allowed for a user called root, who is allowed to do everything, including changing the network. A normal Linux user types `sudo` before such a command to borrow root's power for one command. In the lab you are already root. Look at the end of your prompt: the `#` means root. So in the lab you never need `sudo`, and the lab image does not even contain it, so typing it prints an error. You need it only if you run the course scripts on your own Linux laptop or on WSL 2, the Linux inside Windows. There the scripts run with `sudo`.

Notice where the numbers start and where the checking happens. The numbers live on your computer. The lab has numbers of its own, such as the `192.168.1.10` you will meet in chapter 1.4, and they are not yours. The lab cannot read your computer's settings. It only reads what you paste into the file. So you copy your numbers from your own terminal, never from the lab. If you copy from the lab by mistake, the checker will say it looks wrong, and in a moment you will see how.

## Where each number comes from

You found these in chapter 1.1. The table shows the exact line to copy on each system. For the mask on macOS, the number looks strange: it is written in hex, like `0xffffff00`. That is fine, because the checker understands it.

| Line | What to copy | Windows | macOS | Linux |
|---|---|---|---|---|
| `address` | Your IPv4 address | `ipconfig`, line `IPv4 Address` | `ifconfig`, line `inet` | `ip addr`, line `inet` |
| `mask` | Your mask | `ipconfig`, `Subnet Mask` | `ifconfig`, `netmask` | `ip addr` shows `/24`; write `255.255.255.0` |
| `gateway` | Your router | `ipconfig`, `Default Gateway` | `netstat -rn`, line `default` | `ip route`, `default via` |
| `dns` | The IPv4 DNS server | `ipconfig /all`, `DNS Servers` | `scutil --dns` | `resolvectl status` |
| `public` | What a website sees | `curl.exe -4 ifconfig.me` | `curl -4 ifconfig.me` | `curl -4 ifconfig.me` |

On Windows PowerShell, type `curl.exe`, not `curl`. Plain `curl` in PowerShell is a different command. If your repository is public, do not publish your real public address. Write `203.0.113.45` on the `public` line. The checker accepts it, because that is the stand-in address from chapter 1.1. The macOS commands have not yet been checked on a Mac for this course.

## What the checker does with your mask

The checker does one thing for you that you might not expect. It turns your mask into a prefix. A mask such as `255.255.255.0` says which part of an address names the network. The prefix is the same fact in a shorter form: the number of ones at the start of the mask. Each `255` is eight ones, so `255.255.255.0` has 8 + 8 + 8 = 24 ones, and its prefix is `/24`. You will learn why in chapter 2.2, when you meet bits. For now, trust the count and let the checker do it.

macOS writes the mask in hex. `0xffffff00` is `255.255.255.0`, because each `ff` is 255, so it is also `/24`. A wider example is `0xfffff000`, which is `255.255.240.0` and prints `/20`. A phone or a campus network can have a prefix like that. This is a recording of the checker on two files. One has a dotted mask and one has a hex mask. Both use the stand-in numbers from chapter 1.1. Your own output will show your own numbers.

```
address   192.168.1.23
mask      255.255.255.0 = /24
prefix    192.168.1.23/24
gateway   192.168.1.1
dns       192.168.1.1
public    203.0.113.45
PASS my-numbers.txt looks right

address   192.168.1.23
mask      0xffffff00 = 255.255.255.0 = /24
prefix    192.168.1.23/24
gateway   192.168.1.1
dns       192.168.1.1
public    203.0.113.45
PASS my-numbers.txt looks right
```

## The test that must pass and the test that must fail

The test is `bash test.sh`, run in the lab. It does two jobs. First it proves that the checker itself works, by feeding it made-up numbers, including wrong ones that must be refused. Then it checks your file. Some of its checks must fail. A mask with three numbers must be refused, with a message that starts `FAIL mask: mask needs four numbers`. A mask such as `255.0.255.0` must be refused too, because a mask is ones and then zeros.

The most useful failure needs no extra work. Run `bash test.sh` before you fill in the file. Your own file is empty, so the last check must fail. This is the recorded end of that run.

```
FAIL your my-numbers.txt has a problem. Checker said: FAIL address: address is empty. Paste the number from your computer, for example 192.168.1.23
FAIL gateway: gateway is empty. Paste the number from your computer, for example 192.168.1.1
FAIL dns: dns is empty. Paste the number from your computer, for example 192.168.1.1
FAIL public: public is empty. Paste the number from your computer, for example 203.0.113.45
FAIL mask: mask is empty. Paste the number from your computer, for example 255.255.255.0
RESULT: 5 problem(s). Run cat my-numbers.txt to see what the checker read.
RESULT: 1 check(s) failed
```

Read the failure carefully. Every line names the label that is wrong and says what to do. After you fill in the file, run the test again. The last check then prints `PASS your my-numbers.txt is correct`, and `RESULT: all checks passed`. Your proof is the checker output in `results.md`, with your own numbers and the commands you used to find them.

## Hints, and what to do if you are stuck

If a line fails, try these in order. First, run `cat my-numbers.txt`. It shows what the checker read, which is not always what you meant to write. Second, look at the label in the failure: it names the line that is wrong. Third, copy the number from your computer's terminal, not from the lab. The lab's addresses start with `192.168.1.10` and `192.168.1.20`, and they are not yours.

Two near misses are common. The first is typing `ipconfig` or `ifconfig` in the lab. Those are programs for your own computer, and the lab does not contain them. Open a new terminal on your computer for them. The second is a Windows editor that saves the file with Windows line endings, as chapter 1.2 described. For this file that is fine, because the checker ignores them.

The checker may also print a `NOTE` line, which does not fail the check. If the gateway is not on your network, it says so, which usually means you copied the wrong line. If your public address is private or starts with `100.`, it says a website normally sees a different one. Write it anyway, and say so in `results.md`. It is a clue about your provider, and a later module explains it.
